Machine-Level Representation of Programs

Your C program becomes a list of tiny chores the chip already knows how to do. Each chore is just a few bytes — and those bytes are the only thing the machine ever sees.

“The program executed by the machine is simply a sequence of bytes encoding a series of instructions.”

3.1–3.2 · history and encodings

English recipe, kitchen tickets, then dots on a card

Amara writes a C function. The compiler turns it into assembly — one line per tiny job, with names like %rbx. The assembler then turns those lines into bytes. That pile of bytes is machine code. The chip never sees her variable names.

Intel’s line started as the 16-bit 8086 in 1978 and grew, always able to run yesterday’s programs. That is why the names look like a family attic: %ax inside %eax inside %rax. We will stay with the subset gcc and Linux actually use on x86-64.

Step the translation of the book’s multstore. Watch the same six instructions become a 14-byte object file, then a linked program whose call finally knows where mult2 lives.

What the book says

Compile with gcc -Og so the machine code still follows the C. “Invoking higher levels of optimization can generate code that is so heavily transformed that the relationship between the generated machine code and the original source code is difficult to understand.”

Figure for multstore: object bytes 53 48 89 d3 e8 00 00 00 00 48 89 03 5b c3 — 14 bytes inside a 1,368-byte mstore.o. “x86-64 instructions can range in length from 1 to 15 bytes.” After linking, the call target is filled in and two nops pad the function to 16 bytes.

The book uses ATT format (source then destination, % on registers). Intel format reverses the operands. The ISA says each instruction finishes before the next begins, even though the hardware overlaps them. Memory uses virtual addresses; current x86-64 implementations keep the upper 16 bits zero, so an address can name a byte in a range of 248, or 64 terabytes.

Aside: transistors have doubled about every 26 months on the Intel line; Moore’s original 1965 guess was every year, and the industry average over 50 years is about every 18 months.

        3.3–3.4.1 · formats, registers, operands
        
Sixteen cubbies, and three ways to name a value

        
Intel still calls 2 bytes a word, 4 bytes a double word, 8 bytes a quad word. That is why movq moves 8 bytes and movl moves 4 — the ‘l’ is “long word,” a leftover 32-bit name. A long and a pointer are both 8 bytes here.

        
The CPU has 16 integer registers. An instruction can take a constant (immediate, written $0x1F), a register, or a memory address. The most general address is Imm(%rb,%ri,s) — offset + base + index × scale, and scale is only 1, 2, 4, or 8.

        
Pick an operand from the book’s Practice 3.1. The machine computes the address, then reads the byte. Same memory, different glasses.

        

          What the book says
          

            
Figure 3.1: char 1 / b, short 2 / w, int 4 / l, long 8 / q, char * 8 / q, float 4 / s, double 8 / l. Avoid long double (the old 80-bit x87 format): “It is not portable to other classes of machines.”

            
Figure 3.2: 16 registers, each readable as 1, 2, 4, or 8 bytes in the low end. A 4-byte write zeros the high 4 bytes; a 1- or 2-byte write leaves the rest alone. %rsp is the stack pointer. Roles: %rax return; %rdi %rsi %rdx %rcx %r8 %r9 arguments 1–6; %rbx %rbp %r12–%r15 callee-saved.

            
Figure 3.3: the general form is Imm(rb, ri, s) with effective address Imm + R[rb] + R[ri] · s. Practice 3.1 stores 0xFF, 0xAB, 0x13, 0x11 at 0x100–0x10C, with %rax = 0x100, %rcx = 0x1, %rdx = 0x3.

        3.4.2–3.4.4 · mov, exchange, push and pop
        
Copy a note, or stack the plates

        
movq copies 8 bytes. Source can be a constant, a register, or memory. Destination can be a register or memory — not both memory. To move house to house you go via a register. movl to a register also zeros the top half. There is no movzlq; movl already does that job.

        
The book’s exchange is three instructions: read *xp into %rax (that is the return value), write y to *xp, ret. A C pointer is just an address.

        
The stack grows toward lower addresses. pushq subtracts 8 from %rsp then writes. popq reads then adds 8. We draw it upside down, so the “top” sits at the bottom of the picture.

        
Run exchange, then push and pop the book’s Figure 3.9: %rsp = 0x108, %rax = 0x123.

        

          What the book says
          

            
“x86-64 imposes the restriction that a move instruction cannot have both operands refer to memory locations.” movq immediates are 32-bit sign-extended; movabsq is the 64-bit immediate into a register. Aside: movb leaves the other bytes; movsbq sign-extends; movzbq zero-extends.

            
Figure 3.7: exchange(long *xp, long y) — xp in %rdi, y in %rsi. The example a = 4; b = exchange(&a, 3) prints a = 3, b = 4.

            
Figure 3.8–3.9: pushq is %rsp ← %rsp − 8; M[%rsp] ← S. After pushq %rax then popq %rdx, 0x123 sits in %rdx and %rsp is back at 0x108, but 0x123 still lingers in memory until something overwrites it.

        3.5 · arithmetic and leaq
        
Add without touching the house

        
leaq looks like a memory read, but it never knocks. It just writes the effective address into a register. Compilers love it as a free 5x + 7: if %rdx holds x, then leaq 7(%rdx,%rdx,4), %rax stores 5x + 7.

        
Most other ops use ATT’s “backwards” order: subq %rax, %rdx means “subtract %rax from %rdx.” Shifts take the count in an immediate or in %cl. xorq %rcx, %rcx is a compact way to write zero.

        
Slide x and watch leaq compute 5x + 7. Then step the book’s scale: x + 4y + 12z in three leaqs.

        

          What the book says
          

            
Figure 3.10: leaq, unary inc/dec/neg/not, binary add/sub/imul/xor/or/and, shifts sal/shl/sar/shr. “If register %rdx contains value x, then the instruction leaq 7(%rdx,%rdx,4), %rax will set register %rax to 5x + 7.”

            
scale: three leaqs compute x + 4y + 12z. Figure 3.11 arith turns z*48 into leaq plus salq $4, and uses andl $252645135 for the mask 0x0F0F0F0F.

            
Figure 3.12: one-operand mulq/imulq put a 128-bit product in %rdx:%rax. idivq takes that oct word as the dividend; cqto sign-extends %rax into %rdx first. Two-operand imulq keeps only 64 bits and matches unsigned and two’s-complement bits.

        3.6.1–3.6.6 · condition codes, jumps, cmov
        
Four lamps, then a fork or a quiet swap

        
After most arithmetic, four 1-bit lamps update: CF (unsigned carry), ZF (zero), SF (negative), OF (signed overflow). cmp subtracts without storing; test ANDs without storing. Then you either set* a byte, j* to a label, or cmov* a value.

        
A jump can be a guess. Modern chips keep a pipeline full by predicting the fork. A wrong guess throws away 15–30 cycles of work. So for a simple absdiff, gcc computes both y−x and x−y, then cmovge picks one. No fork, no guess.

        
Add two 4-bit numbers and watch the lamps. Then run the book’s absdiff both ways: a jump, and a conditional move.

        

          What the book says
          

            
Figure 3.13–3.15: cmp is subtract; test is AND. Jump and set suffixes: e/ne, signed g/ge/l/le, unsigned a/ae/b/be (“above/below”). Jumps are often PC-relative: the offset is from the next instruction. Conditional jumps are direct only.

            
Figure 3.16 absdiff_se uses jge because the branches have side effects (lt_cnt / ge_cnt). Figure 3.17 absdiff uses cmovge. On Haswell the jump version was about 8 cycles when predictable and 17.50 when random — a misprediction penalty near 19 cycles. The cmov version stayed near 8.

            
cread cannot use cmov: evaluating *xp when xp is NULL would fault. gcc only emits cmov when both sides are cheap.

        3.6.7–3.6.8 · loops and switch
        
A doorbell at the end, or a hotel directory

        
There is no while instruction. A do-while is “do the body, then jump back if the test holds.” A while is the same loop plus either a jump to the test first (-Og, “jump to middle”) or a skip-over if the first test fails (-O1, “guarded do”). A for is a while with init and update filled in.

        
A switch with several nearby cases becomes a jump table: an array of code addresses. Subtract the lowest case, reject anything outside 0…6 as unsigned (so negatives become huge), then jmp *table(,%index,8). Missing cases point at default. Fall-through is just “no jump at the end of that block.” Time does not grow with the number of cases.

        
Step factorial as a do-while. Then pick a switch index and watch the table pick a door.

        

          What the book says
          

            
Figure 3.19 fact_do: imulq, subq $1, cmpq $1, jg .L2. Figure 3.20 jump-to-middle inserts jmp to the test. Figure 3.21 guarded-do uses jle to skip; gcc even rewrote the back-edge as n != 1.

            
Figure 3.22–3.23 switch_eg: cases 100, 102–104, 106. Index = n − 100; ja .L8 if index > 6; table .L4 holds seven quad words. Case 102 falls through into 103. “Even if we had a switch statement with hundreds of cases, they could be handled by a single jump table access.” gcc uses a table when there are about four or more cases in a small range.

        3.7 · procedures
        
Leave a bookmark, pass the first six in cubbies

        
call Q pushes the address of the next instruction — the return address — then jumps to Q. ret pops that address into the program counter. That is why a stack (last in, first out) matches nested calls, including recursion.

        
The first six integer or pointer arguments travel in %rdi %rsi %rdx %rcx %r8 %r9. The return value comes back in %rax. Argument 7 and up sit on the stack. If Q will smash a register that P still needs, the rule is: %rbx %rbp %r12–%r15 are callee-saved (Q must restore them). The others are caller-saved.

        
Step Figure 3.27: main calls top(100), which calls leaf(95). Watch %rsp drop 8 bytes per call and climb back.

        

          What the book says
          

            
Figure 3.25: a stack frame can hold the return address, saved registers, locals, and an “argument build area.” Many functions need none of it — a leaf that fits in registers allocates nothing.

            
Figure 3.27: top(100) does x-5, calls leaf, doubles the 97 it gets back, returns 194. call at 0x40055b pushes 0x400560. Figure 3.28 lists the six argument registers by size. Figure 3.29 proc has eight arguments: a4 and a4p arrive at 8(%rsp) and 16(%rsp).

            
Figure 3.31: taking &arg1 forces a stack slot. Figure 3.34: P saves %rbp and %rbx around two calls to Q. Figure 3.35: recursive rfact keeps n in %rbx across the recursive call — the same conventions work for recursion.

        3.8 · arrays
        
A row of lockers, then a block of rows

        
T A[N] is N lockers of L bytes each, starting at address xA. Locker i lives at xA + L·i. In assembly that is often (%rdx,%rcx,4) for an int array — scale 4 is the locker width. Pointer math scales too: p+i means “i lockers further,” not “i bytes.” And A[i] is exactly *(A+i).

        
A nested int A[5][3] is five rows of three ints, stored row-major: all of row 0, then row 1. Element [i][j] sits at xA + 4(3i + j). A variable-size A[n][n] needs a real multiply for n·i; a fixed 16×16 can become pointer walking with +4 and +64.

        
Tap a cell in the book’s 5×3 picture. The address formula updates. Then step along a row.

        

          What the book says
          

            
Array element i is stored at address xA + L · i. Examples: char A[12] total 12; int C[6] total 24; pointer arrays use 8-byte elements. “The array reference A[i] is identical to the expression *(A+i).”

            
Equation 3.1: &D[i][j] = xD + L(C · i + j). Figure 3.36 is the 5×3 row-major layout, 60 bytes. Figure 3.37: gcc -O1 turns a fixed 16×16 inner product into pointers Aptr++ and Bptr += N with Bend = &B[N][k]. Figure 3.38 keeps an index j for the variable-n case and increments Bptr by n.

        3.9 · structs, unions, alignment
        
A labelled suitcase, or one pocket with many names

        
A struct lays different fields end to end. The compiler remembers each field’s byte offset and writes 4(%rdi) instead of the name j. The machine code has no field names left. A union gives several names to the same bytes — handy, and a way to leak past the type system.

        
Hardware likes addresses that are multiples of the object’s size: a 4-byte int at a multiple of 4. The compiler inserts padding so that happens, and more padding at the end so an array of structs stays aligned. x86-64 still works if you ignore this; Intel just asks you not to, for speed. Some SSE 16-byte moves are the exception: they fault if unaligned.

        
Tap fields of the book’s struct rec. Then compare struct S3 with union U3, and watch the 3-byte gap appear in struct S1.

        

          What the book says
          

            
struct rec { int i; int j; int a[2]; int *p; } is 24 bytes: offsets 0, 4, 8, 16. r->p = &r->a[r->i + r->j] becomes add, cltq, leaq 8(%rdi,%rax,4), movq to offset 16. “The machine code contains no information about the field declarations or the names of the fields.”

            
struct S3 vs union U3: S3 offsets c=0, i=4, v=16, size 24; U3 all at 0, size 8. “The overall size of a union equals the maximum size of any of its fields.”

            
“The x86-64 hardware will work correctly regardless of the alignment of data.” The rule: “any primitive object of K bytes must have an address that is a multiple of K.” struct S1 { int i; char c; int j; } gets a 3-byte gap so j sits at 8, size 12. struct S2 pads to 12 so an array steps by 12. malloc returns 16-byte-aligned blocks; most stack frames are 16-byte aligned because of SSE.

        3.10 · combining control and data
        
Write past the pad and you move the bookmark

        
C does not check array bounds. Locals live on the same stack as the return address. So a tiny char buf[8] plus the old gets is enough: type 24 characters and you overwrite the return address. ret then jumps into the fog. That is a buffer overflow. The 1988 Internet worm used one against fingerd.

        
Defences the book walks through: move the stack each run (ASLR), plant a random canary between the buffer and the saved state, and mark the stack NX (readable, writable, not executable). A long “nop sled” still helps a determined attacker. Prefer fgets.

        
Type into echo’s 8-byte pad. At 24 characters the return address dies. Turn the canary on and the same write is caught.

        

          What the book says
          

            
“C does not perform any bounds checking for array references, and that local variables are stored on the stack along with state information such as saved register values and return addresses.” Figure 3.40: echo does subq $24, %rsp; buf is at %rsp. Typed characters: 0–7 safe; 9–23 unused; 24–31 the return address; 32+ the caller’s frame.

            
Also dangerous: strcpy, strcat, sprintf. Attack string = exploit bytes + a forged return address. The November 1988 Internet worm overflowed fingerd.

            
Stack randomization / ASLR: 64-bit Linux samples of a local in main spanned nearly 232. A 256-byte nop sled vs 223 of randomization is about 215 guesses. Figure 3.42: canary between buf and the return address, loaded from %fs:40. gcc skipped it for the demo only with -fno-stack-protector. AMD’s NX bit lets the stack be writable but not executable.

Words to know
The chapter’s grown-up words, in plain language.

      

        
ISA
The contract: what the registers are, what each instruction does, as if they ran one after another.

        
assembly
A readable spelling of machine code. One line, one instruction.

        
PC / %rip
The address of the next instruction. Jumps and calls write a new one.

        
word / dword / qword
Intel: 2, 4, and 8 bytes. That is why the suffixes are w, l, and q.

        
immediate
A constant baked into the instruction, written with a $ in ATT syntax.

        
effective address
Imm + base + index × scale. leaq computes it without reading memory.

        
condition codes
CF, ZF, SF, OF — four bits updated by arithmetic, read by set / j / cmov.

        
PC-relative
A jump stores “how far from the next instruction,” so the bytes still work after linking.

        
cmov
Copy a register only if a flag test holds. No pipeline guess.

        
stack frame
The slice of stack one call owns: return address, saved regs, locals, extra args.

        
callee-saved
%rbx, %rbp, %r12–%r15. The called function must give them back as it found them.

        
jump table
An array of code addresses. A switch indexes it in constant time.

        
row-major
A[i][j] stores a whole row before the next row. Address x + L(C·i + j).

        
alignment
Put a K-byte object at a multiple of K. Padding makes that true inside structs.

        
canary
A random guard word between a buffer and the return address. Changed? Abort.

        
ASLR / NX
Randomize where the stack lives; refuse to execute bytes that are only data.
