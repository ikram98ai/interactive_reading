3.1 · a historical perspective

One family of chips, many years long

The processor in a new laptop still understands programs written for a chip from 1978. Each new model added instructions, but it kept the old ones. That promise is called backward compatibility.

The book measures the growth by transistor count: a few tens of thousands, then millions, then more than a billion. The instructions a C compiler emits got wider too, from 16-bit moves to 64-bit moves to packed floating-point adds.

Try it: Tap a chip, or press Next chip. Then jump to 8086 and Haswell and read the one instruction each era added to the story. The code panel shows that instruction.

What the book says

The book lists Intel processors by the transistors it took to build them. The 8086 (1978, 29 K transistors) is a 16-bit microprocessor. Its 8088 variant, with an 8-bit external bus, was the heart of the original IBM personal computers. Those machines came with 32,768 bytes of memory. Addresses were 20 bits long (1,048,576 bytes addressable), and the operating system reserved 393,216 bytes, leaving a 655,360-byte space.

The i386 (1985, 275 K transistors) expanded the architecture to 32 bits and the flat addressing model used by Linux. It was the first machine in the series that could fully support a Unix operating system. The PentiumPro (1995, 5.5 M transistors) introduced the P6 microarchitecture and a class of conditional move instructions.

The Pentium 4E (2004, 125 M transistors) added EM64T, Intel’s implementation of a 64-bit extension to IA32 developed by Advanced Micro Devices (AMD), which the book calls x86-64. The Core i7 Haswell (2013, 1.4 G transistors) extended AVX to AVX2. A program compiled for an earlier chip in this line still runs.

3.2 · compiling into machine code

One command, four workers

You type one line. Four programs run in a row, and only the last one writes the file the processor can run.

This chapter asks gcc for -Og. That setting keeps the assembly close to the C, so you can still see the program you wrote. Stronger settings, -O1 and -O2, may reshuffle the instructions until the shape is hard to recognize.

Try it: Press Step and watch the file name travel from one worker to the next. Reset puts the line back at the start. The code panel highlights the worker that just ran.

What the book says

gcc is a compiler driver. For a command such as gcc -Og -o p p1.c p2.c it runs the preprocessor (cpp), the compiler (cc1), the assembler (as), and the linker (ld). The preprocessor handles directives that begin with #. The compiler writes assembly. The assembler writes relocatable object code. The linker merges the object files and library code and fills in addresses.

The book generates code with gcc -Og. At this level the generated code follows the structure of the original C. Optimization levels -O1 and -O2 can transform the code so thoroughly that the mapping back to the source is hard to follow.

The finished file is what the processor runs. Everything before it is a tool for people, or a file the next tool still has to finish.

3.2.1 · machine-level code

A contract the hardware must keep

The chip may overlap work inside, but the program is allowed to pretend that one instruction finishes before the next one starts. That pretend-machine is the instruction set architecture.

The state a C programmer does not usually see is small: a program counter, sixteen registers, a few condition codes, and a giant array of bytes called memory.

Try it: Press Step to fetch, read memory, read the registers, and write the sum. Reset returns to the idle machine. The highlighted line is the instruction being carried out.

What the book says

The instruction set architecture defines the processor state, the format of the instructions, and the effect of each instruction. The hardware may execute parts of several instructions at once, but it must produce the same results as a processor that completes one instruction before starting the next.

The visible state is the program counter (called %rip on x86-64), a register file of 16 named locations, condition codes that record recent arithmetic, and memory. Memory is a large byte-addressable array. Virtual addresses give each program its own view of that array.

Current 64-bit machines can use up to 256 terabytes (2^48 bytes) of memory, and could be extended toward 16 exabytes (2^64 bytes). A 32-bit machine can only make use of around 4 gigabytes (2^32 bytes).

3.2.2 · code examples

The chip only sees the bytes

The assembly listing is for people. The file the assembler writes is a string of bytes. Fourteen of them are the whole function.

A tool called a disassembler reads those bytes backward and prints something that looks like assembly again. After the linker runs, one of the bytes changes: the call finally learns where to go.

Try it: Press Step to move from the assembly listing, to the 14 object bytes, to the linked call. Reset starts over. The code panel switches to the form you are looking at.

What the book says

3.2.3 · notes on formatting

Two spellings of the same instruction

gcc and the book’s listings use ATT format: the source is written first, registers wear a %, and a letter at the end of the instruction says how many bytes move.

Intel’s manuals write the destination first, and they do not put a % on the register. It is the same instruction. Only the spelling changed.

Try it: Use the switch for Annotated, Raw .s, and Intel. Press Show the call while you are on the annotated listing. The code panel is the file that switch selected.

What the book says

The book shows assembly in ATT format, the form produced by gcc. A register name is prefixed by %, and an immediate is prefixed by $. The last letter of many instruction names is a size: b, w, l, or q. The source operand is written before the destination.

The raw output of gcc -Og -S also contains assembler directives, lines that begin with a period. The book’s annotated listings omit those and add a comment on each instruction.

gcc -Og -S -masm=intel asks for Intel format. The operands are reversed, the % signs disappear, and the size is written differently. The book uses ATT unless it says otherwise.

3.3 · data formats

How many bytes, and which letter

Every C type the compiler moves has a size in bytes, and the instruction name grows a letter to match: b, w, l, or q.

One letter is a trick. On integer instructions, l means 4 bytes. On floating-point instructions, l means an 8-byte double. The rest of the instruction tells you which meaning you are looking at.

Try it: Press Next type, or tap a row, or press double. The bar is the width. The code panel highlights the move that carries that type.

What the book says

Figure 3.1 gives the sizes used by gcc on x86-64. char is 1 byte (suffix b). short is 2 bytes, which Intel calls a word (suffix w). int is 4 bytes, a double word (suffix l). long and any pointer are 8 bytes, a quad word (suffix q).

float is 4 bytes, moved by instructions with suffix s. double is 8 bytes, moved by instructions with suffix l. The suffix l also means a 4-byte integer on instructions such as movl, but the floating-point forms are separate instructions, so the two meanings do not collide.

Most instructions that move or compute on these sizes encode the size in the name. A pointer is an address, 8 bytes on this machine, moved with movq.

3.4 · the register file

Sixteen slots, each with more than one name

The processor keeps sixteen 64-bit slots close at hand. %rax is the same slot as %eax, %ax, and %al. The short names mean “only the low part.”

A 4-byte write is special: it stores the new bytes and clears the top half. A 1-byte or 2-byte write leaves the other bytes alone. That is why there is no instruction that zero-extends a 4-byte move. movl already did it.

Try it: Tap a register name. Then press Write 4 bytes, Write 2 bytes, and Write 8 bytes. The eight boxes are the bytes of the slot you picked, high byte on the left.

What the book says

x86-64 has 16 general-purpose registers holding 64 bits each. The names %rax through %rsp are the historic ones, and %r8 through %r15 were added with the 64-bit extension. Each register also has names for its low 32, 16, and 8 bits.

Writing the 32-bit form, such as movl, sets the low 4 bytes and forces the high 4 bytes to 0. Writing the 8-bit or 16-bit form leaves the remaining bytes unchanged. There is no movzlq, because movl already zero-extends into the 64-bit register.

Some names have fixed jobs in the calling convention: %rsp is the stack pointer, %rax carries a return value, and the argument registers are assigned in a set order. The picture’s role labels follow that convention.

3.4.1 · operand specifiers

Where an instruction is allowed to look

An instruction can take a value from a register, from a constant written in the instruction itself, or from memory. Memory is named with a little formula: a number, plus a register, plus another register times 1, 2, 4, or 8.

Practice Problem 3.1 is that formula on a tiny memory. %rax holds 0x100, so (%rax) means “the byte at 0x100,” not the number 0x100.

Try it: Press the operand buttons. The lit box is the place that was read, and the code panel highlights the matching movq. Start from (%rax), then try $0x108 and 0xFC(,%rcx,4).

What the book says

The three kinds of operands are immediate (a constant, written with $), register, and memory. A memory operand has the general form Imm(rb, ri, s): the effective address is Imm + R[rb] + R[ri] × s, where the scale s is 1, 2, 4, or 8. Any of those pieces except the scale may be omitted.

Practice Problem 3.1 stores 0xFF, 0xAB, 0x13, and 0x11 at addresses 0x100, 0x104, 0x108, and 0x10C. %rax holds 0x100, %rcx holds 1, and %rdx holds 3. Absolute address 0x104 reads 0xAB. The immediate $0x108 is the number itself, not a load.

9(%rax,%rdx) is 9 + 0x100 + 3 = 0x10C. 260(%rcx,%rdx) is 264, which is 0x108. 0xFC(,%rcx,4) is 0xFC + 4 = 0x100. (%rax,%rdx,4) is 0x100 + 12 = 0x10C.

3.4.2 · data movement

A move may touch memory once

movq can copy a constant into a register, a register into a register, a register into memory, or memory into a register. It cannot copy memory straight into memory.

The width letters matter. movl writes four bytes and clears the top of the register. movb writes one byte and leaves the other seven exactly as they were.

Try it: On legal moves, set the source and the destination to memory. Then switch to width and press movl $0xaabbccdd and movb $0x7f. The code panel marks the line that matches.

What the book says

The data-movement instruction movq allows an immediate, a register, or one memory operand. Both operands cannot be memory. A copy from memory to memory is done through a register.

movl stores 4 bytes and sets the upper 4 bytes of a 64-bit register to 0. movb and movw update only the bytes they name. movzbq zero-extends a byte into a quad word, and movsbq sign-extends one.

The width picture starts from the bit pattern 0x1122334455667788. After movl of 0xaabbccdd the register holds 0x00000000aabbccdd. After a one-byte write, only the low byte has changed.

3.4.3 · an example

Swap, and hand back the old value

Kenji’s box holds 4. Lucia wants to put 3 in the box and keep the old 4. One function does both jobs.

The pointer arrives in %rdi and the new value arrives in %rsi. The function reads through the pointer, writes the new value through the same pointer, and leaves the old value in %rax, which is how a function returns a number.

Try it: Press Step three times. The arrows are the loads and stores. Reset puts 4 back in the box. The code panel has the C and the assembly; the highlighted line is the step you are on.

What the book says

The book’s exchange takes a pointer xp and a value y. It saves the old *xp, stores y through xp, and returns the old value. With a = 4 and b = 3, the call exchange(&a, b) leaves a equal to 3 and returns 4, so b becomes 4.

The compiled form is movq (%rdi), %rax, then movq %rsi, (%rdi), then ret. The first instruction both reads memory and sets the return value. No extra register is required.

A pointer in this code is just an address sitting in a register. The C type says what size to read. The machine sees the address.

3.4.4 · push and pop

Two short instructions for the stack

The stack is a pile of 8-byte slots. The top is the lowest address. %rsp points at that top.

pushq subtracts 8 from %rsp and then stores a register there. popq reads that slot and adds 8 back. You could write the same work as a subtract plus a move. pushq encodes it in one byte instead of eight. After popq, the old value is still sitting in memory until something else writes there.

Try it: Press Step to push 0x123, then again to pop it into %rdx. Reset restores %rsp to 0x108. The lower box is the top of the stack.

What the book says

Figure 3.9 starts with %rsp equal to 0x108 and %rax equal to 0x123. pushq %rax sets %rsp to 0x100 and writes 0x123 at that address. popq %rdx reads 0x123 into %rdx and sets %rsp back to 0x108.

The value 0x123 remains at address 0x100 after the pop. Popping does not erase memory. It only moves the stack pointer.

pushq is encoded in 1 byte. The two-instruction form subq $8, %rsp and movq %rax, (%rsp) takes 8 bytes. The machine treats them as the same state change.

3.5.1 · load effective address

An add that pretends to be an address

leaq uses the memory formula but does not read memory. It writes the address it computed into a register. Compilers use that as a cheap multiply-and-add.

7(%rdx,%rdx,4) is 7 + x + 4x when %rdx holds x. That is 5x + 7, and no memory was touched. A longer recipe, three leaq instructions, computes x + 4y + 12z with no multiply instruction at all.

Try it: Move the sliders, or press x = 3. Switch to scale() to see the three-instruction recipe. The code panel shows the leaq lines and the value they just wrote.

What the book says

leaq computes an effective address and stores it in a register. The destination must be a register. The instruction does not load from memory, and it does not set the condition codes.

The book’s example leaq 7(%rdx,%rdx,4), %rax computes 5x + 7 when %rdx holds x. Scale factors of 1, 2, 4, and 8 are the ones the machine can do in the address formula.

The function scale computes x + 4y + 12z with three leaq instructions: one for x + 4y, one for 3z, and one that adds four times that 3z. The compiler prefers this to an integer multiply when the factors are small.

3.5.2 · unary and binary

The second operand is the one that changes

In ATT spelling, subq %rax, %rdx means “subtract %rax from %rdx,” not the other way around. The destination is written last.

A unary instruction has one operand, and that operand is both the source and the destination. incq (%rsp) adds one to the value at the top of the stack. Two memory operands are still forbidden.

Try it: Press Run subq, then incq (%rsp). Reset puts the numbers back. The code panel is the instruction that just ran.

What the book says

Binary operations such as addq, subq, and xorq read the source and the destination and write the destination. In ATT format the source is first. subq %rax, %rdx performs %rdx ← %rdx − %rax.

Unary operations such as incq and decq update their only operand. That operand may be a register or a memory location. It may not be two memory locations, because no instruction here has two memory operands.

incq and decq update the other condition codes but leave the carry flag unchanged. The picture’s memory cell starts at 41 so the increment is easy to see.

3.5.3 · shift operations

The bit that falls off, and the bit that comes in

A left shift brings a 0 in on the right. A right shift has a choice: shr brings in a 0, and sar copies the sign bit so a negative number stays negative.

The shift amount is either a constant or the register %cl. For an 8-bit shift the machine uses only the low 3 bits of that amount. %cl equal to 0xFF means “shift by 7,” not by 255.

Try it: Press sal 1, sar 1, and shr 1. Then press sal by %cl to use the masked amount. Reset restores 11000001. The code panel names the instruction.

What the book says

sal and shl are the same left shift. sar is an arithmetic right shift: the sign bit is copied into the vacated bit. shr is a logical right shift: a 0 enters from the left.

The shift amount is an immediate or the single register %cl. The processor masks the amount to the low 3 bits for an 8-bit shift, the low 4 bits for a 16-bit shift, the low 5 bits for a 32-bit shift, and the low 6 bits for a 64-bit shift. So salb with %cl equal to 0xFF shifts by 7.

The picture is an 8-bit illustration of that rule, so a carry is easy to see. The masking widths are the book’s.

3.5.4 · discussion

Most arithmetic does not care about signed

Add, subtract, and, and xor do the same thing to the bits whether you think of them as signed or unsigned. The right shift is the exception, which is why it has two instructions.

The book’s arith example is a short straight-line function: an xor, a leaq that makes 3z, a shift that makes 48z, a mask, and a subtract. leaq is doing arithmetic again, and it still does not touch the condition codes.

Try it: Press Step arith until %rax holds the result. Then switch to sar vs shr and press sar and shr on the same byte. Reset restores the mode you are in.

What the book says

Figure 3.10 lists the arithmetic and logical operations. Addition, subtraction, and the bitwise operations are the same instruction for signed and unsigned data. Only the right shift splits: sar versus shr.

The arith example computes with x, y, and z. xorq forms t1. leaq (%rdx,%rdx,2), %rax forms 3z. salq $4, %rax multiplies that by 16, which is 48z. andl $252645135, %edi applies the mask 0x0F0F0F0F, and because it is a 4-byte operation it also clears the high half of the register. subq finishes the function.

leaq does not set the condition codes. A 4-byte logical operation zero-extends into the 64-bit register, just as movl does.

3.5.5 · special arithmetic

A product that needs two registers

Multiplying two 64-bit numbers can take 128 bits. mulq writes that full product in %rdx and %rax together. The book calls those 16 bytes an oct word.

Division needs the same pair as the dividend. idivq writes the quotient in %rax and the remainder in %rdx. If you still needed what used to be in %rdx, you have to save it first. The remainder takes the sign of the dividend.

Try it: On mulq, press Show product. Switch to idivq and press Step divide. The code panel is the instruction that just wrote %rdx and %rax.

What the book says

The one-operand mulq multiplies %rax by its operand and writes the full 128-bit product in %rdx:%rax. The two-operand imulq keeps only the low 64 bits, which is what a C multiplication of 64-bit values does.

Signed division uses cqto to sign-extend %rax into %rdx, then idivq. The quotient is left in %rax and the remainder in %rdx. The remainder has the sign of the dividend.

The book’s remdiv receives the destination pointer qp in %rdx. Because idivq will overwrite %rdx, the function first copies qp to %r8. The picture divides −7 by 2: the quotient is −3 and the remainder is −1, and −3 × 2 + (−1) = −7.

3.6.1 · condition codes

Four lamps the last operation left on

After an add, the processor does not only store the sum. It also sets four flags. CF means the unsigned sum did not fit. ZF means the stored bits are all zero. SF means the top bit is 1, so the result looks negative. OF means the signed sum did not fit.

leaq does not touch the lamps. inc and dec update the others but leave CF as it was. This picture uses 4-bit numbers so a carry is easy to see; the real flags watch 8, 16, 32, or 64 bits.

Try it: Drag the two sliders, or press 9 + 12 and 8 + 8. Then press leaq. The code panel is the operation whose flags you are looking at.

What the book says

The condition codes include CF, ZF, SF, and OF. CF is the carry out of unsigned addition. ZF is set when the result is zero. SF is a copy of the most significant bit. OF is set when signed overflow occurs, which is not the same event as unsigned carry.

Most arithmetic instructions set the codes. leaq does not. inc and dec set ZF, SF, and OF but leave CF unchanged, which matters when a loop is using CF for something else.

The four-bit adder is an illustration of those rules, not a figure from the book. 9 + 12 needs five bits unsigned and also leaves the signed 4-bit range. 8 + 8 stays inside the unsigned range and leaves the signed range.

3.6.2 · accessing the condition codes

A question that answers with one byte

cmpq subtracts two numbers, throws the difference away, and keeps only the flags. setl then writes a single byte: 1 if the signed comparison says “less,” and 0 otherwise.

The letter on set is the condition, not a size. setl and setb look at different flags, so a negative number can be “less” when read as signed and “above” when read as unsigned. movzbl widens that one byte to a full register by filling the rest with zeros.

Try it: Move x and y, then press setl, setb, and sete. Try a negative x. The code panel highlights the set you picked.

What the book says

cmpq S2, S1 sets the condition codes from S1 − S2 and does not write a register. The set family writes a single byte, 0 or 1, according to a condition. The suffix is the condition: setl is signed less, setb is unsigned below, sete is equal.

Because the result is one byte, the compiler follows it with movzbl to clear the rest of the destination register. There is no 32-bit or 64-bit form of set.

Signed and unsigned comparisons read different flags. A bit pattern with the top bit set is negative as a signed value and large as an unsigned value, so setl and setb can disagree.

3.6.3 · jump instructions

The program counter is just another register you can write

Normally the next instruction is the next line. A jump writes a new address into the program counter instead.

A direct jump names the label in the instruction. An indirect jump takes the address from a register or from memory: jmp *%rax, or jmp *(%rax). Conditional jumps can only be direct. They cannot take the target from a register.

Try it: On direct jmp, press Step and watch the null load get skipped. Switch to jmp *%rax and step again. The code panel marks the line the PC is on.

What the book says

jmp writes the program counter. A direct jump encodes the target in the instruction. An indirect jump reads the target from a register (jmp *%rax) or from memory (jmp *(%rax)).

Conditional jumps test the condition codes and, if the condition holds, write the program counter. They are direct only. An indirect conditional jump is not part of the instruction set.

The picture’s third instruction would load through %rax while %rax holds 0. The direct jump skips that line. Skipping it is the point of the control transfer.

3.6.4 · jump instruction encodings

The jump stores a distance, not a place

A short jump does not store the address it wants. It stores how far to go from the next instruction. Move the whole program, and that distance is still right.

In the object file, eb 03 means “from the next instruction, go forward 3 bytes.” The next instruction is at address 5, so the target is 8. The byte 7f f8 is −8. Adding that to the following address, 0xd, lands on 5. After linking, the addresses are larger and the distance bytes are the same.

Try it: Press Link it, then Object file. The distance bytes stay put. The code panel is the same listing, with the two PC-relative instructions marked.

What the book says

PC-relative jumps add a displacement to the address of the instruction that follows the jump. In the book’s object-code listing, the bytes at address 3 are eb 03, and 0x5 + 3 = 0x8. The bytes at address b are 7f f8, a displacement of −8, and 0xd + (−8) = 0x5.

After linking, the book shows those instructions at addresses such as 4004d3 and 4004db. The encoded bytes eb 03 and 7f f8 do not change, because the distance between the instructions did not change.

The listing ends with f3 c3, printed as repz retq. The rep prefix is a nop here. It keeps a conditional jump from landing directly on the ret, which matters for a particular processor quirk the book mentions.

3.6.5 · implementing conditional branches

One counter is allowed to change

An if that only picks a number can sometimes be done without a jump. An if that also counts how often each side ran cannot. The side that did not run must not touch its counter.

gcc therefore uses jge. When x is less than y, lt_cnt grows and ge_cnt does not. A conditional move would have had to compute both sides, and both counters would be wrong.

3.7.5 · local storage in registers

A promise about the registers you borrow

Some registers are caller-saved: if P still needs the value after a call, P must save it. Q is allowed to overwrite them.

3.7.6 · recursive procedures

Each call gets its own copy of n

A recursive function calls itself. Each call needs its own n. The register %rbx holds n, and because %rbx is callee-saved, each call pushes the previous n before it reuses the register.

On the way down, the calls nest until n is 1. On the way back, each call multiplies the returned value by the n it saved. The n’s do not collide, because each one was stored in that call’s frame.

Try it: Press Step to descend, then keep stepping to multiply on the way back. Reset clears the stack. The code panel marks the call or the multiply.

What the book says

The book’s rfact computes a factorial recursively. It copies n into %rbx, and if n is greater than 1 it calls rfact(n − 1) and multiplies the result by the saved n. %rbx is callee-saved, so pushq %rbx and popq %rbx surround the body.

The base case writes 1 into %eax and does not call further. Each nested call has its own saved %rbx on the stack, so the values of n are preserved across the recursive call.

3.8.1 · arrays

One start address, then a skip

An array is a row of equal-sized items. Item i lives at the start address plus i times the size of one item.

The machine can multiply by 1, 2, 4, or 8 inside the memory operand itself. That is why a char array, an int array, and an array of pointers compile to the same shape of instruction with a different scale.

Try it: Press char A[12], int C[6], or char *B[8], then tap an index. The code panel highlights the load, with the scale that matches the element size.

What the book says

For an array of elements of size L starting at address x, element i is at x + L × i. A char array uses L = 1, an int array uses L = 4, and an array of pointers uses L = 8.

The compiler puts the start in one register and the index in another. movb (%rdx,%rcx), %al has scale 1. movl (%rdx,%rcx,4), %eax has scale 4. movq (%rdx,%rcx,8), %rax has scale 8.

No extra multiply instruction is required when L is 1, 2, 4, or 8. The address arithmetic is the memory operand.

3.10.4 · thwarting buffer overflow attacks

Three ways to spoil the trick

fgets takes a limit, so the copy can be stopped. Three other defenses assume someone still overflowed the buffer.

A canary is a random value stored between the buffer and the return address and checked before ret. Stack randomization moves the stack so a guessed address is probably wrong. The NX bit lets the stack be written and forbids executing it, so bytes that landed there cannot run.

3.11.1 · floating-point movement and conversion

Floats live in a different set of registers

Floating-point values do not use %rax. They use the XMM registers. A double occupies the low 8 bytes of a 16-byte XMM register.

What the book says

Scalar floating-point data lives in the XMM registers. movss and movsd (and the AVX forms vmovss and vmovsd) move a single float or double between memory and the low bytes of an XMM register. The memory operand need not be aligned, though alignment is recommended.

To copy between two XMM registers, gcc uses vmovaps for single precision and vmovapd for double precision, moving the whole register.

vcvtsi2sd converts an integer to a double. vcvttsd2si converts a double to an integer, truncating toward zero. The picture’s last step turns the integer 7 into the double 7.0.

3.11.2 · floating-point code in a procedure

Two counting systems at once

Integer arguments and floating arguments are numbered separately. The next integer goes to the next integer register. The next float goes to the next XMM register.

That is why f1(int, double, long) and f2(double, int, long) put the double in %xmm0 and the two integers in %edi and %rsi either way. A floating result comes back in %xmm0. Every XMM register is caller-saved.

Try it: Press Next signature. Blue boxes are integer registers. The highlighted line is the signature you are looking at.

What the book says

The calling convention passes floating arguments in %xmm0 through %xmm7, separately from the integer argument registers. A floating-point return value comes back in %xmm0. All XMM registers are caller-saved.

The book’s f1(int x, double y, long z) puts x in %edi, y in %xmm0, and z in %rsi. f2(double y, int x, long z) uses the same assignment, because the integer arguments are numbered among themselves and the floating arguments among themselves.

A function such as g(float x, double *y, long *z) puts the float in %xmm0 and the two pointers in %rdi and %rsi. Pointers are integer arguments even when they point at floating-point data.

3.11.3 · floating-point arithmetic operations

Multiply, divide, subtract, in XMM registers

AVX arithmetic names its sources and a destination XMM register. The book’s funct computes a × x − b / i, with a, x, and b in XMM registers and i in an integer register.

x arrives as a float and has to be widened to a double before the multiply. i is an integer and has to be converted before the divide. The last instruction subtracts.

3.11.4 · floating-point constants

No room for a float inside the instruction

An integer instruction can hold a small constant. An AVX arithmetic instruction cannot hold a floating constant. The compiler stores 1.8 and 32.0 in memory and loads them.

Those constants are written as pairs of .long words, little-endian. The first word is the low half. The temperature formula is the familiar one: multiply by 1.8, then add 32.

3.11.5 · using bitwise operations in floating-point code

The sign is one bit

The sign of a double is a single bit in the high byte. AND with a mask whose sign bit is 0 clears it and leaves the rest. That is fabs.

XOR of a register with itself clears every bit. The result is +0.0, which is how gcc materializes a floating zero.

Try it: Press fabs, then xor to zero. The boxes are the little-endian bytes; the sign bit is in the high byte, drawn on the right. The code panel marks the instruction.

What the book says

Bitwise AVX instructions such as vandpd and vxorpd operate on the bits of XMM registers. The book shows fabs implemented by AND with a mask whose final word is 2147483647, so the sign bit is 0 and the other bits stay 1.

vxorpd %xmm0, %xmm0, %xmm0 clears the register. The all-zero pattern is +0.0.

The picture starts from the little-endian bytes of −2.5 so the sign bit is visible, then applies those two operations. The value −2.5 is an illustration; the mask word 2147483647 is the book’s.

3.11.6 · floating-point comparison operations

A comparison that can fail on both sides

ucomisd compares two doubles and sets ZF, CF, and the parity flag PF. Ordinary comparisons set ZF and CF. PF is the extra lamp, and it comes on when either value is not a number.

When PF is on, a C comparison is false. That includes x < y, and it includes x == x. The unordered case is how the machine reports a NaN.

Try it: Press Next pair, then NaN. The three lamps are ZF, CF, and PF. The code panel marks the jump that matches the flags.

What the book says

ucomisd S1, S2 sets the condition codes from the comparison of S2 − S1. ZF, CF, and PF record the result. If either operand is NaN, the comparison is unordered: ZF, CF, and PF are all set.

C comparisons are false when an operand is NaN. A later jp instruction can test PF when the program needs to detect the unordered case explicitly.

The picture’s ordered pairs are 1.5 compared with 2, 2 with 2, and 3 with 2. The fourth pair is a NaN compared with 2. The flag rules are the book’s; the four pairs are a small stand-in for the book’s table.

3.11.7 · observations

Same idea as integer code, wider registers

Floating-point machine code looks familiar: values sit in registers, and an instruction does one operation. The registers are XMM or YMM, and there are many more instruction names.

The extra speed the book points at is packed arithmetic. One instruction can add two doubles in an XMM register, or four in a YMM register. A scalar add does them one at a time.

Try it: Choose scalar, XMM ×2, or YMM ×4, then press Step until all four boxes have been added. The code panel names the instruction, and the tag is how many times it had to run.

What the book says

The book’s closing observation is that AVX2 floating-point code follows the same style as integer code: operands in registers, simple operations, and an explicit destination. The registers and the instruction names are the new part.

Packed instructions apply one operation to several values at once. An XMM register holds two doubles. A YMM register, introduced with AVX on Sandy Bridge and extended by AVX2 on Haswell, holds four.

The picture steps a four-element sum at those three widths. The counts, one step per scalar value versus one step for the whole YMM vector, are an illustration of that packing. The book’s point is the shape of the code and the parallelism inside one instruction.

3.12 · The seesaws from this chapter

Each row is a choice the compiler, the instruction set, or a defender makes. Chapter 4 opens the processor that runs these instructions.

-Og

Assembly still looks like the C. This chapter uses it so the mapping stays visible.

vs

-O1 / -O2

Faster, and the instructions may no longer follow the source line by line.

ATT

Source, then destination. The form gcc and objdump print by default.

vs

Intel syntax

Destination first, no % on registers. Same instruction, other spelling.

Jump

Any control flow, including side effects. A wrong guess costs about 15–30 cycles.

vs

cmov

No guess. Only when both sides are cheap and safe to evaluate.

if-else chain

One test per case. Fine when the cases are sparse.

vs

Jump table

A bounds check and one indirect jump, when the cases sit close together.

Callee-saved

%rbx, %rbp, and %r12–%r15 come back as the caller left them.

vs

Caller-saved

The caller stashes anything it still needs. The callee may overwrite the rest.

struct

Each field gets its own bytes, plus padding so the fields stay aligned.

vs

union

The fields share one patch of bytes. Smaller, and easier to misread.

gets

Copies until a newline. The return address may be next door.

vs

fgets, canary, NX

Bound the copy, detect a smash, and refuse to run bytes that landed on the stack.

Scalar float

One double per instruction, in the low half of an XMM register.

vs

Packed AVX

The same operation on two doubles, or four in a YMM register.

Words to know

The chapter’s grown-up words, in plain language.

ISA
The contract: registers, instruction formats, and the result of each instruction, as if they ran one at a time.
PC / %rip
The program counter. It holds the address of the next instruction.
word, dword, qword
Intel’s names for 2, 4, and 8 bytes. A long and a pointer on this machine are quad words.
immediate
A constant written inside the instruction, marked with $ in ATT format.
effective address
The address a memory operand computes: a constant, plus a base, plus an index times 1, 2, 4, or 8.
condition codes
CF, ZF, SF, and OF: carry, zero, sign, and overflow, left behind by arithmetic.
PC-relative
A jump that stores a distance from the next instruction, so the code can be moved without rewriting the distance.
cmov
A move that happens only when a condition is true. Both values are computed; there is no guess.
stack frame
The slice of stack one call uses: return address, saved registers, locals, and outgoing arguments.
callee-saved
A register the called function must restore. On this machine: %rbx, %rbp, and %r12 through %r15.
jump table
A list of code addresses. One indirect jump selects a switch case.
row-major
A grid stored one row at a time, so A[i][j] is at the start plus the element size times (columns × i + j).
alignment
The rule that a K-byte object wants an address that is a multiple of K. Compilers insert padding to get it.
canary
A random value parked between a buffer and the return address, checked before the function returns.
NX
A bit that marks memory not executable, so bytes written onto the stack cannot be run.
XMM / YMM
Registers for floating-point values. An XMM holds two doubles; a YMM holds four.
