Representing and Manipulating Information

The same eight switches can be a hex digit, a counting number, a negative number, or a fraction. Computers do not know which story you meant — and that is why 200 * 300 * 400 * 500 can print a negative answer.

2.1.1 · hexadecimal notation

Four bits, one letter

A byte is eight switches. Writing all eight as 11010100 is noisy. Writing 212 is tidy but hides the bits. So we group the switches in fours and give each group a hexadecimal digit: 0–9 then A–F.

One hex digit = exactly 4 bits = a number from 0 to 15. Two hex digits = one byte = 00…FF. In C we write that as 0xD4.

Flip any switch. Watch the two nibbles change. Binary ↔ hex is a lookup, not a calculation.

What the book says

Figure 2.2: hex digits 0–F encode 0000–1111. “Converting between binary and hexadecimal is straightforward, since it can be performed one hexadecimal digit at a time.”

C constants starting with 0x or 0X are hexadecimal. 0xFA1D37B, 0xfa1d37b, and mixed case are the same number.

Practice 2.1 trains the grouping: split binary into 4-bit chunks, pad the left with zeros if needed, then replace each chunk by its hex digit.

2.1.2 · data sizes

A word is however wide the program is

Memory is a row of bytes. A word is the natural chunk the machine likes: 4 bytes on a 32-bit program, 8 bytes on a 64-bit one. C types are just “this many bytes, please.”

int stays 4 bytes even on 64-bit machines. long and pointers grow from 4 to 8. int32_t / int64_t (C99) lock the size so you are not guessing.

Switch 32-bit / 64-bit. Watch which bars grow. Historically many programs stuffed a pointer into an int — that breaks when pointers become 8 bytes.

What the book says

Figure 2.3 (typical sizes): char 1, short 2, int 4, long 4 or 8, char * 4 or 8, float 4, double 8. Fixed-size int32_t / int64_t are always 4 and 8.

“Most 64-bit machines can also run programs compiled for use on 32-bit machines” with gcc -m32.

“Many programmers historically assumed that an object declared as type int could be used to store a pointer. This works fine for most 32-bit programs, but it leads to problems for 64-bit programs.”

2.1.3 · addressing and byte ordering

Which end of the egg?

A 4-byte int at address 0x100 occupies 0x100, 0x101, 0x102, 0x103. The fight is only about which byte sits at the smallest address.

Big endian stores the most significant byte first (01 23 45 67). Little endian stores the least significant byte first (67 45 23 01). Intel and almost every phone OS you use are little-endian. The names come from Swift’s Gulliver’s Travels — Lilliput arguing about which end of an egg to crack (Aside, p. 79).

Drop 0x01234567 into memory both ways. Then run the book’s show_bytes(12345).

What the book says

Figure on p. 78: variable x = 0x01234567 at 0x100. Big endian: 01,23,45,67. Little endian: 67,45,23,01.

Figure 2.6: 12345 = 0x00003039. Linux/Windows/x86-64 print 39 30 00 00 (little). Sun SPARC prints 00 00 30 39 (big). The float bytes of 12345.0 are the same bits in reverse order. Pointers differ completely — they are addresses, not the number 12345.

Byte order matters for networks (Chapter 11), for reading disassembly, and when a cast peeks at the raw bytes (Figure 2.4 show_bytes).

        2.1.6–2.1.9 · Boolean, C bits, logic, shifts
        
A mask, a question, a shove

        
Boolean algebra gives four bit-by-bit jobs: AND &, OR |, XOR ^, NOT ~. A mask keeps the bits you care about and throws the rest away.

        
C also has logical && || !. Those do not walk the bits. They ask “is this zero?” and answer 0 or 1. And there are shifts: << invents zeros on the right. Right shift is either logical (fill with 0) or arithmetic (copy the sign bit) — C uses arithmetic for signed values.

        
Pick an operation. Flip bits in A and B. Compare a bitwise & with a logical && on the same numbers.

        

          What the book says
          

            
§2.1.7: C uses | & ~ ^ on any integral type. A common trick: x ^ y then swap without a temp (Practice 2.10).

            
§2.1.8: logical operators treat nonzero as true and always yield 0 or 1. They short-circuit.

            
§2.1.9: logical right shift fills with zeros; arithmetic right shift fills with the most significant bit “useful for operating on signed integer data.” Shift amounts should stay < w — C does not define x << 32 on a 32-bit int. And 1<<2+3<<4 is not 52, because + binds tighter than <<.

        2.2.2–2.2.3 · B2U and B2T
        
The left-hand switch can be +8 or −8

        
Unsigned is ordinary binary: bit i is worth 2i. Four bits count 0…15. The biggest value is UMax = 2w − 1.

        
Two’s complement uses the same bits, but the top bit is worth −2w−1. That is the sign bit. Four bits now mean −8…+7. The most negative pattern 1000 is TMin = −8. The most positive 0111 is TMax = 7. There is no +8 — the range is lopsided because 0 sits on the positive side.

        
Flip the four bits. Both readings update. When the sign bit turns on, unsigned jumps up and signed falls through the floor.

        

          What the book says
          

            
Equation 2.1: B2Uw(x) = Σ xi 2i. Equation 2.3: B2Tw(x) = −xw−1 2w−1 + Σ xi 2i. Both mappings are bijections.

            
Figure 2.12 / 2.13 (w = 4): [1011] is 11 unsigned and −5 two’s complement — same bits, sign bit weight +8 vs −8.

            
Figure 2.14: |TMin| = |TMax| + 1. UMax = 2 TMax + 1. Pattern 111…1 is −1 in two’s complement and UMax unsigned. Pattern 100…0 is TMin.

        2.2.4–2.2.5 · conversions and C promotions
        
−1 is also 15. Context decides.

        
Casting signed ↔ unsigned on almost every machine keeps the bits and changes the glasses. Two’s-complement −1 (all ones) becomes unsigned UMax. Unsigned 8 on four bits becomes signed −8 (TMin).

        
C has a trap. If either side of < is unsigned, the other side is quietly turned unsigned too. So -1 < 0 is true, but -1 < 0U is false — because −1 became 4,294,967,295.

        
Step the conversion on the four-bit word, then open the book’s comparison table (Figure 2.19).

        

          What the book says
          

            
Principle (2.5): T2Uw(x) = x + 2w if x < 0, else x. Principle (2.7): U2Tw(u) = u − 2w if u > TMax, else u.

            
“Most systems follow the rule that the underlying bit representation does not change.”

            
Figure 2.19: -1 < 0U evaluates to 0. “When either operand of a comparison is unsigned, the other operand is implicitly cast to unsigned.” Printing int x = -1 with %u yields 4294967295.

        2.2.6–2.2.7 · expanding and truncating
        
New bits on the left, or bits thrown away

        
Growing a number: zero-extend unsigned values (fill new high bits with 0). Sign-extend two’s-complement values (copy the sign bit leftward) so −5 stays −5 when it moves from 4 bits to 8.

        
Shrinking is rougher. Truncation keeps the low bits and drops the rest — which is “mod 2k” and then re-read. A number that fitted can become a different number, even a different sign.

        
Widen 4 → 8, then truncate 8 → 4. Try −5 and 13.

        

          What the book says
          

            
§2.2.6: converting to a larger size “should always be possible.” Unsigned → zero extension. Two’s complement → sign extension (repeat xw−1).

            
§2.2.7: truncating to k bits is x mod 2k, then interpret with U2Tk or B2Uk. Relative order of size-change and signed/unsigned conversion can change the result (the short sx = -12345; unsigned uy = sx; mystery).

        2.3.1–2.3.3 · integer arithmetic
        
The clock face has only sixteen hours

        
Four-bit unsigned add is mod 16 (Figure 2.23). 9 + 12 = 21, which is 5 on the clock, and 5 < 9 so you know it overflowed. C does not raise a flag. The book’s infamous 200 * 300 * 400 * 500 wraps to −884,901,888 on a 32-bit int — a product of positives that is negative.

        
Two’s-complement add uses the same adder. Overflow is now “the true sum is outside TMin…TMax.” And TMin is its own negation: -TMin cannot be represented, so -(-8) stays −8 on four bits.

        
Add two 4-bit numbers. Watch unsigned wrap and signed overflow independently — same bits, two verdicts.

        

          What the book says
          

            
Opening example (p. 68): 200 * 300 * 400 * 500 yields −884,901,888. Multiplication is still associative: every parenthesization gives that same wrong number.

            
Unsigned overflow iff s < x (or s < y). Two’s-complement overflow: negative overflow when x+y < TMin, positive when x+y > TMax (Figure 2.25).

            
Principle: -t TMinw = TMinw. “TMin_w is its own additive inverse.”

        2.3.6–2.3.7 · multiply and divide by powers of two
        
Shifting is multiplying, with a catch

        
A left shift by k is multiply by 2k — until bits fall off the left. Compilers love this: x * 20 can become (x << 4) + (x << 2).

        
Right shift by k is divide by 2k, rounded toward −∞ for arithmetic shifts. For a negative number the book first adds a bias of 2k−1 so the hardware shift matches C’s “round toward zero” division (Figure 2.30).

        
Shift a signed byte. Compare logical fill-with-zeros to arithmetic copy-the-sign.

        

          What the book says
          

            
§2.3.6: x << k equals x * 2k modulo 2w. Compilers generate shifts and adds instead of imul.

            
§2.3.7 / Figure 2.30: dividing a negative two’s-complement number by 2k needs a bias of 2k−1 before an arithmetic right shift so the result matches rounding toward zero.

        2.4 · IEEE floating point
        
Scientific notation, with a budget of bits

        
Integers are exact but short-ranged. Floats are the opposite: a huge range, but most numbers are only nearby. IEEE 754 writes V = (−1)s × M × 2E packed as sign, exp, frac.

        
If exp is all zeros, the number is denormalized (including ±0, and the tiny values that fill the gap around zero). If exp is all ones: ±∞ or NaN. Otherwise it is normalized: an implied leading 1, exponent = e − bias.

        
That is why (3.14 + 1e20) - 1e20 becomes 0.0, while 3.14 + (1e20 - 1e20) stays 3.14. Addition is not associative.

        
Edit a toy 8-bit float (1 + 4 + 3 bits, bias 7 — Figure 2.35). Then run the book’s 1e20 experiment.

        

          What the book says
          

            
p. 69: “(3.14+1e20)-1e20 will evaluate to 0.0 on most machines, while 3.14+(1e20-1e20) will evaluate to 3.14.” Integers overflow to a wrap; floats overflow to +∞ and stay positive.

            
Figure 2.32: single = 1+8+23 (bias 127), double = 1+11+52 (bias 1023). Figure 2.33: exp all 0 → denorm; all 1 → inf/NaN; else normalized with E = e − Bias, M = 1 + f.

            
Figure 2.35 (k=4, n=3, bias 7): largest denorm 7/512 and smallest norm 8/512 meet smoothly because denorms use E = 1 − Bias, not −Bias.

            
Default rounding is round-to-even (Figure 2.37).

Hold on to these
Chapter 2 in six pockets. Chapter 3 will assume you can read a hex dump and a two’s-complement immediate.

      

        
Bits + hex
Group bits in fours. 0xD4 is 1101 0100. Figure 2.2 is the whole language.

        
Endian
The number is the same. Only the address of the least-significant byte changes. Networks must agree (Chapter 11).

        
Two’s complement
Top bit weighs −2w−1. TMin has no positive twin. −1 is all ones, which is also UMax.

        
C conversions
Bits stay. Glasses change. One unsigned operand poisons a comparison (Figure 2.19).

        
Wrap-around add
Unsigned: mod 2w, overflow iff s < x. Signed: same adder, overflow if the true sum leaves the TMin…TMax window.

        
IEEE float
sign × significand × 2E. Tiny, normal, ∞, NaN. Precise integers; approximate reals. Not associative.

      

    

  


  

    

      
Words to know
The chapter’s grown-up words, in plain language.

      

        
hexadecimal
Base 16. One digit (0–F) names four bits. C writes it 0x….

        
word
The machine’s natural chunk: 4 bytes (32-bit program) or 8 bytes (64-bit).

        
little / big endian
Least-significant byte at the lowest address, or most-significant byte first.

        
mask
A bit pattern used with & or | to keep, clear, or set chosen bits.

        
logical vs bitwise
&& || ! ask “zero or not?” and yield 0/1. & | ~ ^ walk every bit.

        
arithmetic right shift
Fill vacated left bits with copies of the sign bit. C does this for signed types.

        
unsigned / B2U
Ordinary binary. Range 0 … 2w−1 (UMax).

        
two’s complement / B2T
Sign bit weighs −2w−1. Range TMin = −2w−1 … TMax = 2w−1−1.

        
TMin / TMax / UMax
Most-negative signed, most-positive signed, most-positive unsigned. Figure 2.14.

        
T2U / U2T
Re-read the same bits as the other type. Negative x maps to x+2w.

        
sign extension
When widening a signed value, copy the sign bit into the new high bits.

        
overflow
The true mathematical result does not fit. Unsigned wraps. Signed wraps to a different sign. Floats become ∞.

        
IEEE 754
The 1985 standard: V = (−1)s M 2E, with normalized, denormalized, ∞, and NaN.

        
denormalized / NaN
Exp all 0: no implied 1, including ±0. Exp all 1 and frac ≠ 0: not-a-number.

        
round-to-even
IEEE default: ties go to the even last bit, so rounding error does not always drift the same way.
