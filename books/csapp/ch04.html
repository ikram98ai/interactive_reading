4.1 · The Y86-64 ISA

Fifteen cubbies, three lamps, one bookmark

Priya’s desk is the only world her program can see. Fifteen program registers sit in a row — %rax through %r14. Three lamps remember the last bit of arithmetic: zero, negative, overflow. A bookmark named the program counter points at the next ticket. A status stamp says whether she is still working or has stopped.

She does not have the x86-64 register %r15. That missing cubby is how the tickets stay short enough to decode. %rsp is the only cubby with a job: it names the top of the stack for push, pop, call, and return.

Step Figure 4.17. Watch irmovq $9, %rdx, then irmovq $21, %rbx, then subq %rdx, %rbx write 12 and turn the three lamps off.

What the book says

Figure 4.1 is the programmer-visible state: 15 registers (%rax, %rcx, %rdx, %rbx, %rsp, %rbp, %rsi, %rdi, %r8–%r14), condition codes ZF, SF, OF, the PC, memory, and Stat. x86-64’s %r15 is omitted to simplify encoding. Each register holds a 64-bit word. %rsp is the stack pointer for push, pop, call, and return; the others have no fixed meaning.

Y86-64 is a subset of x86-64: only 8-byte integer operations, fewer addressing modes, a simple byte encoding. The four moves are named by source then dest: irmovq, rrmovq, mrmovq, rmmovq. Memory uses base plus displacement only. No memory-to-memory move, and no immediate-to-memory move. OPq is addq, subq, andq, xorq — registers only — and those four set ZF, SF, OF.

Figure 4.5 status codes: 1 AOK (normal), 2 HLT (halt), 3 ADR (invalid address), 4 INS (invalid instruction). This design stops on any code other than AOK. Figure 4.17 is the running example: irmovq $9, %rdx at 0x000, irmovq $21, %rbx at 0x00a, subq %rdx, %rbx at 0x014.

4.1.3–4.1.4 · encoding and exceptions

A ticket is nibbles, then maybe cubbies, then a number

Mateo writes kitchen tickets as bytes. The first byte splits in half: the high nibble is icode (which dish, 0 through 0xB) and the low nibble is ifun (which extra). Some tickets then name one or two cubbies as rA and rB. Some finish with an 8-byte number valC — an immediate, a displacement, or a jump target.

Cubbies are numbered 0 for %rax through 0xE for %r14. The number 0xF means “no cubby.” Integers are little-endian, so a printed hex dump looks backwards. A ticket that is not on the menu stamps Stat with INS and stops the kitchen.

Pick an instruction. The machine splits the bytes the way the fetch stage will. Start with the book’s rmmovq %rsp, 0x123456789abcd(%rdx).

What the book says

Instruction encodings range between 1 and 10 bytes. “An instruction consists of a 1-byte instruction specifier, possibly a 1-byte register specifier, and possibly an 8-byte constant word.” Codes 0–0xB: halt, nop, rrmovq/cmovXX, irmovq, rmmovq, mrmovq, OPq, jXX, call, ret, pushq, popq. Function codes (Figure 4.3): addq 0, subq 1, andq 2, xorq 3; jmp 0 through jg 6; rrmovq is the unconditional move with fn 0.

Figure 4.4 register IDs match x86-64: 0 %rax … 7 %rdi, 8 %r8 … 0xE %r14, 0xF no register. Branches and calls store absolute destinations, not PC-relative ones. The worked encoding: rmmovq %rsp, 0x123456789abcd(%rdx) is 40 42 cd ab 89 67 45 23 01 00 — icode 4, rA=4 (%rsp), rB=2 (%rdx), displacement little-endian.

Every legal byte sequence has a unique split into instructions. Y86-64 mixes CISC traits (condition codes, variable length, stack return address) with RISC traits (load/store, regular encoding, arguments in registers).

4.2 · Logic design and HCL

Wires that never wait, and a fork that picks a word

Yuki does not run a program. She hangs gates on wires. AND, OR, and NOT sit there all day: if an input flips, the output flips a moment later. High voltage near 1.0 volt is a 1; near 0.0 volts is a 0. A loop of gates is forbidden — the answer would argue with itself.

A multiplexor is a polite fork: control bit s picks input a or b. An ALU is four forks in one box, with a function code that matches Y86-64’s OPq: 0 add, 1 sub, 2 and, 3 xor. HCL is just a way to write those forks as cases.

Toggle s, a, and b on the mux. Then switch to the ALU and pick addq / subq / andq / xorq — subtraction is B minus A, the same order as subq.

What the book says

Three ingredients: combinational logic, memory elements, and a clock. Logic 1 is about 1.0 volt; logic 0 is about 0.0 volts. HCL writes AND as &&, OR as ||, NOT as !. Combinational networks must be acyclic, each input driven by exactly one source, and outputs not tied together. Bit equality: bool eq = (a && b) || (!a && !b); Bit mux (Figure 4.11): bool out = (s && a) || (!s && b);

Word-level muxes use HCL case expressions; the first matching select wins, and a final 1 : default is the usual last case. Figure 4.15 ALU function codes match Figure 4.3: 0 add, 1 sub, 2 and, 3 xor. For subtraction the A input is subtracted from the B input, anticipating subq rA, rB.

Clocked registers capture their input on the rising edge and hold it until the next rise. The register file has read ports A/B (srcA/srcB → valA/valB) and write port W (dstW, valW). ID 0xF means do not write. SEQ also clocks the PC, the condition codes, and data-memory writes.

Always-on logic
Gates do not wait for a clock. Toggle a bit and the output follows.
4.3.1–4.3.2 · Sequential Y86-64

One ticket through six rooms, then the next

Amina walks a single ticket through the building. Fetch reads the bytes at the bookmark and splits icode, ifun, maybe rA/rB, maybe valC, and computes valP (where the next sequential ticket lives). Decode opens up to two cubbies. Execute asks the ALU to add, subtract, make an address, or bump the stack pointer.

Memory may read or write a word. Write-back puts results in cubbies. PC update moves the bookmark to valP, or to a jump/call target, or to a popped return address. SEQ does all six rooms in one long clock cycle. That is correct, and painfully slow.

Step the book’s subq %rdx, %rbx at address 0x014. The rooms fill with the exact numbers from the aside: 21 − 9 = 12.

What the book says

SEQ executes a complete instruction every cycle. The six stages: fetch, decode, execute, memory, write-back, PC update. Fetch reads icode:ifun from M1[PC], maybe rA:rB, maybe valC, and sets valP to PC plus the instruction length. Decode reads valA/valB (sometimes %rsp). Execute produces valE and maybe sets CC or Cnd. Memory may write or produce valM. Write-back updates the register file. PC becomes valP, valC, or valM.

The aside “Tracing the execution of a subq instruction” follows line 3 of Figure 4.17. Previous irmovqs left %rdx = 9 and %rbx = 21. At PC 0x014 the bytes are 0x61 and 0x23. Fetch: icode:ifun = 6:1, rA:rB = 2:3, valP = 0x016. Decode: valA = 9, valB = 21. Execute: valE = 21 − 9 = 12; ZF, SF, OF all 0. Write-back: %rbx ← 12. PC ← 0x016.

Figure 4.22 draws the flow clockwise from a PC in the lower left. Hardware is shared: one ALU, one register file with ports A/B/E/M, one data memory. The book draws stages bottom to top so a pipeline listing still reads like the program.

4.3.3 · SEQ timing

Wires settle. Then the clock stamps.

Luca thought the six rooms happened one after another, like a recipe. The hardware is ruder: almost everything is combinational. Read the cubbies, run the ALU, pick the next PC — the wires just settle. Only four things wait for a clock edge: the PC, the condition-code register, data-memory writes, and register-file writes.

At the start of a cycle the boxes still hold yesterday. By the end, new numbers sit at their inputs. When the clock rises, those numbers become the new state at once. SEQ never has to read back what it just wrote in order to finish the same instruction.

Walk Figure 4.25. Cycle 3 runs addq %rdx, %rbx. Cycle 4 runs je dest, which is not taken because ZF is still 0 after the add.

What the book says

Instruction memory and register-file reads act like combinational logic. The four sequenced units — PC, CC, data memory, register file — share one clock. CC updates only on OPq. Data memory writes only for rmmovq, pushq, or call. Register ID 0xF means a write port is idle.

“The processor never needs to read back the state updated by an instruction in order to complete the processing of this instruction.” That is the no-reading-back principle. pushq computes valE = valB − 8 and uses valE both as the store address and as the new %rsp, so the write and the memory update can happen together on the rising edge.

Figure 4.25: after two irmovqs, cycle 3 starts with PC = 0x014, %rbx = 0x100, CC = 100. By the end of the cycle combinational logic has %rbx ← 0x300, CC ← 000, next PC 0x016, but the state boxes still hold the old values until the clock rises. Cycle 4 fetches je dest; ZF is 0, so the branch is not taken and the next PC is 0x01f.

4.4 · General principles of pipelining

More shirts per hour, one shirt a little later

Fatima’s laundry has three stations: wash, dry, fold. If she waits for one load to finish before starting the next, the dryer sits cold. If she slides a wet load into the dryer and starts a new wash, she finishes more loads per hour. That rate is throughput. The time one shirt spends in the building is latency, and the extra hand-off trays can make that a bit longer.

The book’s toy circuit spends 300 ps in combinational logic and 20 ps stuffing a register: 320 ps per instruction, about 3.12 GIPS. Split into three 100 ps stages plus a 20 ps register each, the clock is 120 ps and throughput jumps to about 8.33 GIPS. One instruction now takes 360 ps. The slowest stage sets the clock. Deep pipes hit a wall because those 20 ps trays eat the cycle.

Play sequential, then pipelined. Watch I1, I2, I3 share the three stations — or wait in line.

What the book says

Everyday pipes: a cafeteria line, a car wash. “A key feature of pipelining is that it increases the throughput of the system (i.e., the number of customers served per unit time), but it may also slightly increase the latency (i.e., the time required to service an individual customer).”

Figure 4.32 unpipelined: 300 ps combinational plus 20 ps register, delay 320 ps, throughput about 3.12 GIPS. Figure 4.33 three-stage: 100 ps + 20 ps = 120 ps clock, throughput about 8.33 GIPS, latency 360 ps. Speedup 8.33/3.12 = 2.67; latency ratio 360/320 = 1.12. Nonuniform stages (Figure 4.36) are limited by the slowest (150 + 20 = 170 ps, 5.88 GIPS). Six stages of 50 ps yield 70 ps clocks and 14.29 GIPS — not double the three-stage design, because register overhead is 28.6% of the cycle. Real processors use 15 or more stages.

Feedback is the real problem. irmovq $50, %rax then addq %rax, %rbx then mrmovq 100(%rbx), %rdx is a chain of data dependencies. A jne is a control dependency. A naive three-stage pipe would feed I1’s result to I4, not I2 — the ISA would be broken.

4.5.1–4.5.4 · SEQ+ and PIPE registers

Trays between the rooms, bookmark first

Omar’s first trick is SEQ+: compute today’s bookmark at the start of the cycle, from leftovers of yesterday (pIcode, pCnd, pValC, pValM, pValP). There is not even a PC register any more — just enough saved scraps to rebuild it. That is legal, as long as programs still see a correct bookmark.

Then he slides a tray between rooms: F (predicted PC), D (fetched instruction), E (decoded values), M (ALU result and branch flags), W (values heading home to cubbies). Five irmovqs can sit in the five rooms at once. For most tickets he can even guess the next PC: valC for jumps and call, valP otherwise. Conditional jumps are guessed taken.

Step Figure 4.42. Five instructions enter, one per cycle. By cycle 5 each tray holds a different ticket.

What the book says

SEQ+ is circuit retiming: the same PC mux, now fed by pipeline-like leftovers pIcode, pCnd, pValC, pValM, pValP. The aside asks “Where is the PC in SEQ+?” — it is computed, not stored. PIPE− inserts registers F, D, E, M, W. Signals in a register get an uppercase prefix (M_stat); signals just computed in a stage get a lowercase one (m_stat). Destination register IDs travel with the instruction all the way to write-back so a write uses that instruction’s dst, not decode’s.

Figure 4.42: irmovq $1, %rax … irmovq $4, %rdx, then halt. In cycle 5 the five stages hold I1 in W through I5 in F. PIPE predicts the next PC in fetch: valC for IJXX and ICALL, else valP. Conditional branches are predicted always taken (about a 60% success rate). ret is not predicted; fetch stalls until ret reaches write-back. Select-PC can also take M_valA after a not-taken jump or W_valM after ret.

4.5.5 · Data hazards and forwarding

The add reads too soon — unless a side door is open

Soren writes 10 into %rdx and 3 into %rax, then immediately addq %rdx, %rax. Decode opens the cubbies three beats before write-back stamps them. If the cubbies still hold 0, the add is a lie. That is a data hazard: a later ticket needs a number a earlier ticket has not written yet.

He could freeze the add until the writes finish (stalls, like stuffing nops into the line). Better: a side door. The number sitting in execute, memory, or write-back is handed straight to decode. That is forwarding. Five sources can feed valA or valB: e_valE, m_valM, M_valE, W_valM, W_valE.

Run prog4 both ways. Without forwarding both operands are 0. With it, decode steals 10 from memory-stage M_valE and 3 from execute-stage e_valE.

What the book says

prog1–prog4 (Figures 4.43–4.46) are irmovq $10, %rdx, irmovq $3, %rax, then zero to three nops, then addq %rdx, %rax. Registers start at 0. Three nops (prog1) let both writes finish before decode. Two nops (prog2): %rax is still in W, so add reads 0. One nop (prog3): both pending. No nops (prog4): %rdx is in M (M_valE = 10) and %rax is being born in E (e_valE = 3).

Stalling holds the consumer in D, stalls F, and injects a bubble into E — a dynamic nop. Forwarding compares srcA/srcB with destination IDs in E, M, and W and substitutes the pending value. Newer stages win when several match. PIPE (Figure 4.52) adds Sel+Fwd A and Fwd B. Most register hazards need no stall once those paths exist.

4.5.5 · Load/use hazards

The locker opens one beat too late

Mei loads a word from a locker into %rax (mrmovq) and the very next ticket adds it. Decode wants that word now. The locker does not open until the memory room — one whole beat later. Forwarding cannot send a number backward in time. She must pause.

The pause is a load interlock: hold the add in decode, freeze fetch, shove a bubble into execute. Next cycle the word is sitting in memory-stage m_valM and can be handed forward. Other pending numbers (here 10 in %rbx) still use the ordinary side doors.

4.5.4–4.5.8 · Prediction and squash

Guess the door, throw away the wrong hallway

Kwame’s jump is guessed taken, so two tickets from the target walk in before execute even looks at the lamps. If the guess was wrong, those two have not written cubbies yet. The pipeline cancels them — injects bubbles into decode and execute — and fetches the real next ticket. Two beats of work vanish. That is a misprediction squash.

A ret is worse: the return address is not known until the ticket reaches write-back. Fetch sits still and three bubbles walk through. Always-taken jumps are right about 60% of the time. On the book’s sample mix those wasted bubbles, plus load interlocks and returns, push CPI from a dream of 1.00 up to about 1.27.

Play the book’s not-taken jne after xorq %rax, %rax. Then switch to ret and watch three bubbles before the return point is fetched.

What the book says

Always-taken prediction is used; studies cited in the book give about a 60% success rate (never-taken about 40%; BTFNT about 65%). Figure 4.56: xorq %rax, %rax then jne target (not taken). Fetch starts the target irmovq $2, %rdx and the next target instruction. In cycle 4 execute sees Cnd = 0. Cycle 5 bubbles D and E and fetches the fall-through irmovq $1, %rax.

Figure 4.55: ret is fetched in cycle 3 and reaches W in cycle 7. Decode, execute, and memory inject three bubbles. Select-PC then uses W_valM. Fetch-stage HCL: f_predPC is valC for jumps and call, else valP. f_pc prefers M_valA on a mispredicted jump, W_valM on ret, else F_predPC.

Section 4.5.9 sample mix: loads 25% and 20% of those interlock (lp = 0.05); conditional branches 20% and 40% not taken with two bubbles (mp = 0.16); ret 2% with three bubbles (rp = 0.06). CPI = 1.0 + 0.27 = 1.27. Mispredicts are the largest penalty.

Words to know

The chapter’s grown-up words, in plain language.

ISA
The contract: registers, instructions, encodings, exceptions. Programs see this, not the wiring.
Y86-64
The book’s teaching ISA: a slim, regular cousin of x86-64 with 15 registers.
icode / ifun
The two nibbles of the first instruction byte: which instruction, and which extra.
valC / valP
The 8-byte constant in the ticket; the address of the next sequential instruction.
HCL
Hardware control language: Boolean and case expressions that name control wires.
combinational
Gates with no memory. Outputs follow inputs after a delay. No loops.
SEQ
Sequential processor: all six stages in one long cycle, one instruction done.
SEQ+
Same SEQ, but the PC is computed at the start of the cycle from yesterday’s leftovers.
throughput
Finished instructions per second. Pipelining’s main prize.
latency
Time one instruction spends from fetch to write-back. Pipes can make this a bit worse.
hazard
A dependency that would make the pipe compute the wrong ISA result.
forwarding
Hand a pending result from a later stage back to decode, instead of waiting for the cubby.
bubble
A dynamic nop injected into a stage so a stalled instruction does not slide forward.
load interlock
One-cycle stall when a load’s value is needed by the next instruction.
branch prediction
Guess the next PC for a jump so fetch does not wait for execute.
CPI
Clock cycles per instruction. PIPE’s sample mix lands near 1.27, not 1.00.
