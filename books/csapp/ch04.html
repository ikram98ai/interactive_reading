4.1.1 · Programmer-visible state

Fifteen cubbies, three lamps, one bookmark

Priya’s program can see only a small desk. Fifteen program registers hold 64-bit words: %rax through %r14. Three lamps — ZF, SF, OF — remember the last arithmetic. A bookmark, the program counter, names the instruction happening now. A stamp called Stat says whether work is still normal.

There is no %r15. Leaving that cubby out keeps every register number inside four bits. %rsp is the only cubby with a reserved job: it names the top of the stack for push, pop, call, and return. Memory is one long row of bytes, addressed by virtual addresses. For now, treat it as one big array.

The wiring inside the chip does not have to look like this desk. It only has to make every program behave as if the desk were real.

Try it: press Step. The picture walks the opening of the book’s running example: 9 into %rdx, 21 into %rbx, then subq writes 12 and the lamps stay off. The highlighted line under the picture is the instruction being applied.

What the book says

Figure 4.1 is the programmer-visible state. There are 15 program registers: %rax, %rcx, %rdx, %rbx, %rsp, %rbp, %rsi, %rdi, and %r8 through %r14. The x86-64 register %r15 is omitted to simplify the instruction encoding. Each register stores a 64-bit word. %rsp is the stack pointer for push, pop, call, and return. The others have no fixed meaning.

Three single-bit condition codes, ZF, SF, and OF, store information about the most recent arithmetic or logical instruction. The PC holds the address of the instruction currently being executed. Memory is a large byte array addressed with virtual addresses; Chapter 9 explains the translation to physical addresses. Stat indicates normal operation or an exception such as an invalid address (Section 4.1.4).

The processor need not organize this state the way the ISA draws it, as long as machine-level programs appear to have access to it.

4.1.2 · Y86-64 instructions

Four ways to move a word, and no shortcuts

Mateo’s kitchen only cooks 8-byte integers. A move says where the word comes from and where it goes: irmovq (immediate to register), rrmovq (register to register), rmmovq (register to memory), mrmovq (memory to register). The first letter is the source. The second is the destination.

Memory addresses are only base plus displacement. There is no second index and no scale. A word cannot jump from one memory locker to another, and an immediate cannot land in memory by itself. Arithmetic — addq, subq, andq, xorq — uses registers only, and those four set the lamps.

Jumps and conditional moves share the same tests. call pushes a return address. ret pops it. halt stops the processor with status HLT. nop does nothing but move the bookmark.

Try it: pick an instruction. Watch what it reads, what it writes, and whether the lamps change. Then press not allowed — that memory-to-memory move is missing on purpose.

What the book says

Y86-64 is largely a subset of x86-64: only 8-byte integer operations, fewer addressing modes, and a smaller set of operations. The movq instruction is split into irmovq, rrmovq, mrmovq, and rmmovq, so the source and destination forms are explicit. Memory uses a base-and-displacement format only. Direct memory-to-memory moves and immediate-to-memory moves are not allowed.

OPq is addq, subq, andq, and xorq, on registers only. They set ZF, SF, and OF. The seven jumps are jmp, jle, jl, je, jne, jge, and jg. The six conditional moves use the same conditions and the same encoding shape as rrmovq. call pushes the return address and jumps. ret returns. halt stops execution and sets the status code to HLT. nop is the do-nothing instruction.

4.1.3 · Instruction encoding

A ticket is nibbles, then maybe cubbies, then a number

Every ticket starts with one byte split in half. The high nibble is icode (which kind, 0 through 0xB). The low nibble is ifun (which extra). Some tickets then name one or two registers as rA and rB. Some finish with an 8-byte constant valC: an immediate, a displacement, or a jump target.

Register numbers run from 0 for %rax to 0xE for %r14. The number 0xF means “no register.” Constants are stored little-endian, so a hex dump of a big number looks backwards. rrmovq shares icode 2 with the conditional moves; function code 0 means “always.” Jumps and calls store an absolute destination, not a distance from the PC.

Every legal byte string has exactly one way to be chopped into instructions. That is what lets the fetch stage be a fixed recipe.

Try it: start with the book’s rmmovq %rsp, 0x123456789abcd(%rdx). Press Next field and watch the caret move through the bytes under the picture. The little-endian displacement is the part that looks reversed.

What the book says

An instruction consists of a 1-byte instruction specifier, possibly a 1-byte register specifier, and possibly an 8-byte constant word. Encodings range from 1 to 10 bytes. The first byte splits into a code and a function. Codes run from 0 to 0xB: halt, nop, rrmovq/cmovXX, irmovq, rmmovq, mrmovq, OPq, jXX, call, ret, pushq, popq. Function codes matter when several instructions share a code. rrmovq is the unconditional move, function code 0, just as jmp is the unconditional jump.

Figure 4.4 numbers the registers the same way x86-64 does: 0 %rax through 7 %rdi, 8 %r8 through 0xE %r14, and 0xF for no register. The worked example rmmovq %rsp, 0x123456789abcd(%rdx) encodes as 40 42 cd ab 89 67 45 23 01 00: icode 4, rA = 4 (%rsp), rB = 2 (%rdx), displacement little-endian.

Branches and calls store absolute destinations. The design mixes CISC traits (condition codes, variable length, a stack return address) with RISC traits (load/store, a regular encoding, arguments in registers).

4.1.4 · Y86-64 exceptions

Four stamps, and only one means “keep going”

Amina’s processor keeps a status stamp. AOK (1) means the program is fine. HLT (2) means it executed halt. ADR (3) means it tried to read or write an address past the end of memory, while fetching or while touching data. INS (4) means the bytes are not a real instruction.

In this design, any stamp other than AOK stops the processor. A fuller machine would call an exception handler, a procedure the operating system set up. Chapter 8 is where handlers abort a program or run a signal handler. Here, stop is enough.

Try it: press the four stamps. The normal add keeps AOK. halt becomes HLT. A load past the end of this picture’s memory becomes ADR. The byte 0xFF becomes INS, and the next instruction never runs.

What the book says

Figure 4.5 lists the status codes. Value 1, AOK, is normal operation. Value 2, HLT, means a halt instruction was executed. Value 3, ADR, means an invalid address, either while fetching an instruction or while reading or writing data. The maximum address depends on the implementation; any access beyond it triggers ADR. Value 4, INS, means an invalid instruction code.

For Y86-64, the processor simply stops when it hits any exception other than AOK. A more complete design would invoke an exception handler, a procedure designated to handle that exception. Chapter 8 describes handlers that can abort the program or invoke a user-defined signal handler.

4.1.5 · Y86-64 programs

The same loop, with the constants pulled out

Leila wants the sum of a list. x86-64 can add a memory word straight into a register. Y86-64 cannot. She loads the word with mrmovq, then addq. She also cannot add an immediate, so the step “pointer plus 8” and “count minus 1” live in %r8 and %r9.

subq sets the lamps, so she does not need a separate test. She does need one andq before the loop, so the first jne sees a real zero flag. The picture uses a tiny list, 3 + 5 + 7, so each add fits on the screen. The book’s four-word array sums to 0xabcdabcdabcdabcd.

4.1.6 · Some instruction details

What do you push when the pointer is the thing you push?

pushq both shrinks %rsp by 8 and stores a register at the new top. If the register is %rsp, two stories are possible: store the old pointer, or store the pointer after it has already moved. Hiro runs a tiny experiment. Copy %rsp into %rax, push %rsp, pop into %rdx, subtract. The result is 0. The old value was the one stored.

popq %rsp has the twin puzzle. A test pushes 0xabcd and pops it into %rsp. The function returns 0xabcd. So the popped register becomes the value read from memory, not the incremented pointer. That is exactly what mrmovq (%rsp), %rsp does.

The 8086 did the other push. Later Intel machines push the old value. Two conventions for one instruction make programs and manuals harder. Y86-64 picks the later x86-64 rule and sticks to it.

Try it: run pushq %rsp with the x86-64 rule, then switch to the other rule and run it again. The subtraction stops being 0. Then run popq %rsp and watch %rax become 0xabcd.

What the book says

pushq %rsp could push the original %rsp or the decremented value. Practice Problem 4.7 runs pushtest: copy %rsp to %rax, pushq %rsp, popq %rdx, subq %rdx, %rax. The function always returns 0, so the old value of %rsp is what gets pushed. Y86-64 adopts that convention.

Practice Problem 4.8 runs poptest: save %rsp, pushq $0xabcd, popq %rsp, return the new %rsp. It always returns 0xabcd, so popq %rsp sets the stack pointer to the value read from memory. That is equivalent to mrmovq (%rsp), %rsp.

An Intel note records the inconsistency: from the 286 on, PUSH ESP pushes the value from before the instruction; the 8086 PUSH SP pushes the value after SP has been decremented by 2. Different modes, different results, extra documentation. Deciding the detail once keeps later implementations consistent.

4.2.1 · Logic gates

Wires that answer immediately

Yuki does not run a program. She hangs gates on wires. A high voltage near 1.0 volt is a 1. A low voltage near 0.0 volts is a 0. AND is 1 only when both inputs are 1. OR is 1 when either input is 1. NOT flips its one input.

HCL writes those gates with the single-bit C operators: &&, ||, and !. The word operators &, |, and ~ are the wrong tool — they act on whole words. A three-input AND is still written a && b && c. Gates never wait for a clock. Change an input, and a moment later the output follows.

Try it: tap the inputs on each gate. The output moves at once. The code under the picture is the same three HCL lines, with live 0s and 1s on the ends.

What the book says

Logic value 1 is a high voltage of around 1.0 volt. Logic value 0 is a low voltage of around 0.0 volts. A digital system needs combinational logic, memory elements, and a clock. HCL describes the control portion. Verilog and VHDL are the hardware description languages used to synthesize real circuits; HCL is the book’s smaller notation for control, and it can be translated into Verilog.

Figure 4.9 shows AND, OR, and NOT. HCL uses &&, ||, and ! because the gates operate on single bits, not words. N-way AND and OR are still written with the binary operators. Gates are always active: if an input changes, the output changes after a small delay.

4.2.2 · Combinational circuits and HCL

A network of gates, with three house rules

One gate is a toy. A network of them is a combinational circuit. Three rules keep the answer unambiguous. Every input connects to exactly one source. Two outputs may not be tied onto the same wire — they would fight over the voltage. And the network may not contain a loop.

Bit equality is the useful example: 1 when both inputs match. A multiplexor is a polite fork. Control bit s picks a when it is 1 and b when it is 0. HCL names the expression; it does not “store” the result the way a C assignment does. And unlike C, every gate always looks at every input. There is no short-circuit.

Try it: toggle a and b on the equality circuit, then switch to the mux and toggle s. The broken mode ties two outputs together — the picture stops claiming an answer.

What the book says

Combinational networks obey three restrictions. Every gate input connects to exactly one of: a primary input, the output of a memory element, or the output of a gate. Gate outputs are not tied together. The network is acyclic, because a loop can make the computed function ambiguous.

Figure 4.10 is bit equality: bool eq = (a && b) || (!a && !b);. The HCL = names an expression. It is not a store into memory. Figure 4.11 is a single-bit multiplexor: bool out = (s && a) || (!s && b);. The output equals a when s is 1 and b when s is 0.

Combinational outputs keep responding to inputs. C logical operators accept any integer and may skip the second argument; these gates only see bits 0 and 1, and they always react to every input. Practice Problem 4.9 asks for exclusive-or: bool xor = (!a && b) || (a && !b);. It is the complement of eq.

4.2.3 · Word-level circuits

Sixty-four bit-gates, wearing one name

A word is a bundle of bits: an integer, an address, an instruction code, a register id. Word equality is 64 copies of the bit-equality circuit, AND-ed together. HCL just writes bool Eq = (A == B); and calls the bundle an int, without spelling out the width.

A word multiplexor is the same idea with a case expression. Cases are tried in order. The first one that is 1 wins, even if a later case is also 1. A final 1 : is the usual default. The ALU picks add, subtract, and, or xor. Subtract is B minus A, so it matches subq.

Try it: flip bits until A and B match. On the mux, set s to 1 and notice that case s wins even though the default 1 is also true. On the ALU, subtract 9 from 21.

What the book says

HCL declares word-level signals as int and does not specify the width. Figure 4.12 builds 64-bit equality from 64 bit-equality circuits and one AND. In HCL that is bool Eq = (A == B);. Thick lines in the drawings are words. A dashed line is a single bit.

Figure 4.13 is a word multiplexor. Case expressions try selection conditions in order and take the first one that yields 1. The mux is word Out = [ s : A; 1 : B; ];. The trailing 1 is the default. Selection expressions need not be mutually exclusive; a synthesis tool turns them into exclusive hardware by keeping only the first match. Figure 4.14 is the 4-way mux, and the later cases can be shortened because earlier cases already covered the other patterns.

Figure 4.15 is the ALU. Function codes match Figure 4.3: 0 add, 1 subtract, 2 and, 3 xor. For subtraction the A input is subtracted from the B input, anticipating subq rA, rB. The three-word minimum is a case expression on comparisons; the book’s solution rewrites the second arm as B <= C : B.

4.2.4 · Set membership

One question: is this code in the club?

Processor control is full of questions like “is this an instruction that has a register byte?” Writing code == 2 || code == 3 works. HCL also lets you say code in { 2, 3 }. Same wires, easier to read.

Noor’s 4-way mux from the previous section needs two control bits, s1 and s0, taken from a 2-bit code. s1 is on for codes 2 and 3. s0 is on for codes 1 and 3. The set test builds those bits, and the case expression from before picks the word.

Try it: press code 0, 1, 2, or 3. Watch s1 and s0 and which of A, B, C, D comes out. The highlighted HCL line is the case that won.

What the book says

Set membership tests whether one integer expression matches any expression in a brace list: iexpr in { iexpr1, iexpr2, ..., iexprk }. The 4-way mux controls can be written bool s1 = code == 2 || code == 3; and bool s0 = code == 1 || code == 3;, or more compactly bool s1 = code in { 2, 3 }; and bool s0 = code in { 1, 3 };.

The same form shows up constantly in the processor, whenever an instruction code has to be matched against a category: instructions that need a register byte, instructions that write %rsp, instructions that use the ALU, and so on.

4.2.5 · Memory and clocking

The clock is the only moment anything is stored

Gates forget as soon as you look away. A clocked register holds a word. For the whole cycle its output stays at the old value, even while the input wire has already settled on a new one. When the clock rises, the input is captured and becomes the output until the next rise. That edge is a barrier: values cross it once per cycle.

A register file is a small memory addressed by register ids. Ports A and B read like combinational logic: set srcA to 3 and, after a short delay, %rbx appears on valA. The write port waits for the clock. Destination 0xF means “do not write.” If you read and write the same id, the read output changes from the old value to the new one as the clock rises.

Data memory reads the same way, and it raises error when the address is out of range. Writes wait for the clock, and only if the write signal is 1. Instruction memory, in this design, is read-only and is treated as combinational too.

Try it: change the register’s input, then press Rising edge. On the register file, read %rbx before and after a write. On data memory, turn write on and clock it — then ask for an address past the end.

What the book says

Combinational circuits store nothing. Sequential circuits add storage controlled by one clock. Clocked registers hold individual bits or words and load the input on the rising edge (Figure 4.16). Random-access memories hold many words. The register file holds the 15 program registers. “Register” means two things: a hardware register wired into the circuit, and a program register addressed by an id inside the register file.

The register file in the figure has read ports A and B (srcA/srcB produce valA/valB) and write port W (dstW, valW). Reads behave like combinational logic. Writes happen when the clock rises. dstW of 0xF writes nothing. Reading and writing the same id makes the read output change from the old value to the new one on that edge. Y86-64 processors use clocked registers for the PC, the condition codes, and the program status.

Data memory has an address, a data input, a data output, read, write, and error. Reads are combinational when write is 0. Writes happen on the clock when write is 1 and the address is valid. error is combinational: it depends only on the address. Instruction memory is a separate read-only memory; real chips usually merge the two into one dual-ported memory.

4.3.1 · Organizing processing into stages

Six rooms, even for a ticket that skips some

SEQ walks every instruction through the same hallway, so one set of hardware can serve all of them. Fetch reads bytes at the PC and splits icode, ifun, maybe rA and rB, maybe valC, and computes valP, the address of the next sequential instruction. Decode reads up to two registers. Execute runs the ALU: the operation, an address, or a stack-pointer bump. It may also set the lamps or decide a condition.

Memory may read or write one word. Write-back updates registers. PC update sets the bookmark to valP, or to a jump or call target, or to a popped return address. A nop still walks the hall. It just does almost nothing in the later rooms.

Try it: step the book’s subq %rdx, %rbx at 0x014. Then switch to irmovq $128, %rsp and see which rooms stay empty. The code panel lists the computations for the stage you are in.

What the book says

SEQ performs every step of one instruction on each clock cycle. The stages are fetch, decode, execute, memory, write-back, and PC update. Fetch reads up to 10 bytes from instruction memory at the PC, splits the first byte into icode and ifun, maybe reads a register specifier, maybe reads valC, and sets valP to the next sequential address.

The aside “Tracing the execution of a subq instruction” follows line 3 of Figure 4.17. Earlier instructions left %rdx = 9 and %rbx = 21. At PC 0x014 the bytes are 0x61 and 0x23. Fetch: icode:ifun = 6:1, rA:rB = 2:3, valP = 0x016. Decode: valA = 9, valB = 21. Execute: valE = 21 − 9 = 12, and ZF, SF, OF are 0. Write-back stores 12 in %rbx. PC becomes 0x016.

The solution for the irmovq $128, %rsp at 0x016 reads bytes 0x30 and 0xf4, valC = 128, valE = 0 + 128, writes %rsp, and sets PC to 0x020. Decode and memory do no work for that instruction.

4.3.2 · SEQ hardware structure

One ALU, shared by every kind of ticket

The hallway is not six copies of the kitchen. Fetch, decode, execute, memory, and write-back share one instruction memory, one register file, one ALU, one data memory, and one condition-code register. What changes from ticket to ticket is which inputs those boxes are handed.

The register file in SEQ has two read ports and two write ports, named E and M, so an instruction can update two registers on one clock. Hardware is drawn with the PC at the bottom and write-back toward the top, so a pipeline listing later still reads like the program, bottom to top.

Try it: pick OPq, rmmovq, jump, or call. The boxes that this instruction actually uses light up. OPq needs the ALU and the lamps. A jump needs the lamps and the PC mux, and it leaves the data memory dark.

What the book says

SEQ’s hardware (Figures 4.22 and 4.23) shares one instruction memory, one register file, one ALU, one data memory, and the condition-code register across every instruction. The register file has read ports A and B and write ports E and M. Control logic, drawn as the computations of Figures 4.18 through 4.21, steers values into those shared units.

The book draws the stages bottom to top, PC at the lower left, so that a later pipeline diagram still reads in program order. Different instructions exercise different subsets: an integer operation uses the ALU and updates the condition codes; a store uses the ALU as an address adder and writes data memory; a jump consults the condition codes and the PC mux; a call also writes the return address and the new stack pointer.

4.3.3 · SEQ timing

The wires settle. Then one edge stamps everything.

The stage tables look like a recipe: do this, then that. The circuit is ruder. Almost everything is combinational, including instruction-memory reads and register-file reads. Only four things wait for the clock: the PC, the condition codes, data-memory writes, and register-file writes. They all share one rising edge, and they all update together.

That works because of a rule the book states flatly: the processor never needs to read back the state updated by an instruction in order to finish that same instruction. pushq does not decrement %rsp and then read it back for the store address. It computes valE = valB − 8 and uses that wire both as the store address and as the new stack pointer.

No instruction both writes the lamps and reads them. The next instruction will see the new lamps, because the write happens on the edge that starts the next cycle.

Try it: step Figure 4.25. At the end of cycle 3 the wires already say %rbx = 0x300 and CC = 000, but the state boxes still hold 0x100 and 100. The rising edge is what makes them switch. Cycle 4’s je is not taken, because ZF is 0.

What the book says

Instruction memory and register-file reads act like combinational logic. The four units that need explicit sequencing — program counter, condition-code register, data memory, and register file — share one clock. The condition codes load only for an integer operation. Data memory writes only for rmmovq, pushq, or call. Register id 0xF leaves a write port idle.

The book’s no-reading-back principle: “The processor never needs to read back the state updated by an instruction in order to complete the processing of this instruction.” pushq computes valE = valB − 8 and uses valE both as the memory address and as the new %rsp, so the register write and the memory write can happen together on the rising edge. Condition codes are written by OPq and read by later conditional moves and jumps, never by the same instruction.

Figure 4.25 starts cycle 3 with PC = 0x014, %rbx = 0x100, and CC = 100 (ZF SF OF). By the end of the cycle, combinational logic has produced %rbx ← 0x300, CC ← 000, and next PC 0x016, while the state boxes still hold the old values. The rising edge commits them. Cycle 4 fetches je dest. ZF is 0, so the branch is not taken and the next PC is 0x01f.

4.3.4 · SEQ stage implementations

The length of a ticket is two yes/no wires

Fetch reads 10 bytes and then asks two questions. need_regids: does this icode carry a register byte? need_valC: does it carry an 8-byte constant? If the PC is p, the register bit is r, and the constant bit is i, then valP = p + 1 + r + 8i. That is the whole length formula.

If the instruction address is illegal, fetch pretends it saw a nop. If there is no register byte, rA and rB become 0xF. Decode turns icode into the four register-file addresses. The srcA block is a case expression: most instructions want rA, popq and ret want %rsp, and everyone else wants no register.

Try it: pick an instruction. The picture shows the two yes/no wires and the valP they imply, starting from PC 0x000. Switch to srcA and the same buttons show which register port A reads. The matching HCL line lights up.

What the book says

Fetch reads 10 bytes at the PC (Figure 4.27). The first byte splits into icode and ifun. If imem_error is set, those fields are replaced by a nop. From icode the control computes instr_valid, need_regids, and need_valC. The book’s HCL for the register byte is bool need_regids = icode in { IRRMOVQ, IOPQ, IPUSHQ, IPOPQ, IIRMOVQ, IRMMOVQ, IMRMOVQ };. When that signal is 0, both register specifiers are set to 0xF (RNONE). valC is bytes 1–8 or bytes 2–9 depending on need_regids.

For PC value p, need_regids value r, and need_valC value i, the incrementer produces p + 1 + r + 8i. Figure 4.26 gives the constant names used in the HCL: IHALT 0 through IPOPQ 0xB, RESP 4, RNONE 0xF, ALUADD 0.

4.4.1 · Computational pipelines

More shirts per hour, one shirt a little later

Fatima’s unpipelined box spends 300 ps thinking and 20 ps stuffing a register: 320 ps per instruction, about 3.12 GIPS. The time one instruction spends inside is the latency, also 320 ps. Split the thinking into three stages of 100 ps, each with its own 20 ps register, and the clock can tick every 120 ps.

In the steady state a new instruction finishes every tick, about 8.33 GIPS. That is throughput. One instruction now takes three ticks, 360 ps. Throughput rose by 8.33 / 3.12 = 2.67. Latency rose by 360 / 320 = 1.12. The extra registers are the reason a single shirt is slightly slower even though the shop finishes more shirts per hour.

Try it: press Play on sequential, then on the three-stage pipe. I1, I2, and I3 either wait in line or occupy A, B, and C together. The numbers under the picture are the book’s.

What the book says

A key feature of pipelining is that it increases the throughput of the system, the number of customers served per unit time, but it may also slightly increase the latency, the time required to service an individual customer. The unpipelined example (Figure 4.32) spends 300 ps in combinational logic and 20 ps loading a register. Delay is 320 ps. Throughput is about 3.12 GIPS. Latency equals that delay.

Figure 4.33 divides the logic into stages A, B, and C of 100 ps each, plus a 20 ps register per stage. The clock is 120 ps, throughput about 8.33 GIPS, latency 3 × 120 = 360 ps. The speedup is 8.33 / 3.12 = 2.67. The latency ratio is 360 / 320 = 1.12, from the added pipeline registers. In steady state one instruction leaves and a new one enters every clock cycle.

4.4.2 · A detailed look at pipeline operation

Between edges the stages think. On the edge they hand off.

Every 120 ps the clock rises and each instruction steps into the next register. Between rises, the combinational logic of that stage is working on whatever the register captured. Figure 4.34 draws I1, I2, and I3 against those edges, from 0 out to 600 ps.

Look at the window from 240 to 360. Just before 240, the registers still hold the previous hand-off. Just after 240, I1 is in C, I2 is in B, I3 is in A, and the logic starts computing. By 360 the results are waiting at the next registers, ready for the following edge. Run the clock faster than the logic can settle, and the registers capture nonsense.

4.4.3 · Limitations of pipelining

The slow stage sets the clock. The registers eat the rest.

If the three stages take 50, 150, and 100 ps, the clock still has to wait for the slow one. Add the 20 ps register and the cycle is 170 ps, about 5.88 GIPS, and latency grows to 510 ps. Stages A and C sit idle for part of every cycle. Balancing the delays is a real design job. An ALU or a memory often refuses to be sliced evenly.

Slice the original 300 ps into six stages of 50 ps and the clock is 70 ps, about 14.29 GIPS. Doubling the number of stages did not double the throughput of the three-stage design: 14.29 / 8.33 = 1.71. The register delay is now 28.6% of the cycle. Modern processors use 15 or more stages anyway, and then the clock network itself has to arrive everywhere at the same instant.

If each of k stages takes 300/k ps plus a 20 ps register, throughput climbs toward 50 GIPS and never past it. Latency grows without a ceiling. That is the wall.

Try it: switch between the lopsided pipe and the deep pipe. Then drag k. Watch throughput rise and latency = 300 + 20k grow. The code panel is the formula, with live numbers in the tags.

4.4.4 · Pipelining a system with feedback

The next ticket needs an answer that is still inside the pipe

Laundry loads do not care about each other. Instructions do. irmovq $50, %rax writes a register that the very next addq reads, and that add writes %rbx, which the mrmovq uses as an address. A jne decides whether the following instruction should have been fetched at all. Those are data dependencies and a control dependency.

SEQ handles them with feedback around the whole cycle: the new register value and the new PC come back before the next instruction starts. A naive pipeline inserts registers and then feeds an instruction the values from three instructions ago. The ISA would be broken. The add would see 0 in %rax, and the load would use the old %rbx.

Try it: run the three instructions the naive way, then the SEQ way. Naive leaves %rax at 50 but adds 0 into %rbx and loads the wrong address. SEQ gets %rbx = 50 and loads address 150.

What the book says

Until this section the pipeline carried independent objects. A machine program has dependencies. The sequence irmovq $50, %rax, addq %rax, %rbx, mrmovq 100(%rbx), %rdx is a chain of data dependencies. A jne creates a control dependency: the condition decides whether the next instruction is the fall-through or the target.

In SEQ those dependencies use the feedback paths of Figure 4.22, sending updated register values back to the register file and the new PC back to the PC register. Figure 4.38 shows what a naive pipeline does with that feedback: the result of one instruction is not available to the instruction that needs it, only to some later one. The ISA behavior would not be preserved. The rest of the chapter is the repair.

4.5.1 · SEQ+

Compute today’s bookmark at the start of the day

Pipelining wants the next PC decided at the beginning of a cycle, not at the end. SEQ+ is the same processor with that one move. It keeps a few leftovers from yesterday — pIcode, pCnd, pValC, pValM, pValP — and runs the same PC mux on them as the cycle opens. There is no PC register anymore. The bookmark is computed.

That is legal. The ISA says programs can observe a program counter. It does not say a particular hardware box must store it. Moving state across a cut in the circuit without changing the results is called circuit retiming. SEQ+ is a small example. Out-of-order machines, in Chapter 5, take the idea much further.

Try it: step an irmovq and then a taken jmp. Watch the p* leftovers appear at the end of a cycle, and watch SEQ+ turn them into today’s PC at the start of the next one.

What the book says

SEQ+ moves the PC update to the start of the clock cycle (Figure 4.39). State registers hold the signals computed during an instruction — pIcode, pCnd, pValC, pValM, pValP — and the next cycle runs the same PC logic on those leftovers to produce the PC of the instruction that is now current. Figure 4.40 is the SEQ+ hardware: the same blocks as SEQ, with the PC logic at the bottom of the diagram instead of the top.

The aside “Where is the PC in SEQ+?” points out that no hardware register stores the program counter. It is computed from state saved by the previous instruction. That is allowed as long as every machine-language program still sees the right PC. The shift is an example of circuit retiming: change the state representation without changing the logical behavior, often to balance pipeline delays.

4.5.3 · Rearranging and relabeling signals

A lowercase birth, an uppercase crossing

Once a value can live in several places, its name has to say where. A signal sitting in pipeline register M is M_stat. The same status, freshly computed in the memory stage and not yet stored, is m_stat. Uppercase means “captured in that register.” Lowercase means “computed in that stage, this cycle.”

The destination register is the reason the convention matters. Decode of a later instruction is computing some other dstE at the same moment write-back wants to store an earlier result. The write port must use W_dstE, the id that traveled with the finishing instruction, not the id decode is producing right now.

Try it: step until irmovq $1, %rax is in write-back and addq is in decode. The cubby that changes is %rax, because that id is sitting in W — even though decode is talking about %rbx.

What the book says

Signals stored in a pipeline register are written with an uppercase prefix, such as M_stat. Signals computed in a stage during the current cycle use a lowercase prefix, such as m_stat. PIPE’s HCL differs from SEQ’s mostly by those prefixes: srcA becomes d_srcA, and the instruction fields it reads come from D_icode and D_rA.

Write-port register ids come from the write-back stage (W_dstE and W_dstM), not from decode. Otherwise a write would use whatever destination the instruction currently in decode happens to name. The destination travels in the pipeline registers with the rest of that instruction.

4.5.4 · Next PC prediction

Guess the next bookmark before execute has looked at the lamps

Fetch has to choose a next PC in the same cycle it reads an instruction. It cannot wait to see whether a conditional jump is taken. The guess is simple. If the instruction is a jump or a call, predict the constant in the instruction, valC. Otherwise predict valP, the next sequential address. Conditional jumps are therefore predicted taken.

Studies the book cites get that guess right about 60% of the time. Never-taken would be right about 40%. Backward-taken, forward-not-taken does a bit better, about 65%. ret is not guessed from the instruction bytes. Its return address appears only when the instruction reaches write-back, so fetch stalls. The select-PC block can also grab M_valA after a jump that was not taken, or W_valM after a return.

Try it: fetch a jmp, a jne, a plain rrmovq, and a ret. The predicted PC changes. The HCL line that fired is the one highlighted below.

What the book says

PIPE predicts the next PC in fetch. The HCL is word f_predPC = [ f_icode in { IJXX, ICALL } : f_valC; 1 : f_valP; ];. Conditional branches are predicted taken. The book cites success of about 60% for always-taken, about 40% for never-taken, and about 65% for backward taken, forward not taken.

ret is not predicted from valC. The return address is not known until the instruction has read memory. Select-PC, written in the next sections, prefers M_valA when a jump in the memory stage was not taken, W_valM when a return reaches write-back, and F_predPC otherwise. Fetch of a return therefore stalls rather than running ahead.

4.5.5 · Pipeline hazards

The number exists. It just is not in the cubby yet.

A hazard is a dependency that would make the pipe compute a different answer from SEQ. Soren writes 10 into %rdx and 3 into %rax, then adds them at once. Decode opens the cubbies while those writes are still in M and E. Without help, the add reads 0 and 0.

Forwarding opens a side door. The pending value in execute, memory, or write-back is handed straight to decode. Five sources, newest first: e_valE, m_valM, M_valE, W_valM, W_valE. A load is the exception. Its word does not exist until the memory stage, one cycle after decode wanted it. The pipe stalls: hold the add in D, freeze F, and put a bubble — a made-up nop — into E.

Control hazards get the same tools. A not-taken jump cancels the two instructions fetched from the target. A ret injects bubbles until the return address shows up in W.

Try it: step prog4 with forwarding off, then on. Decode should steal 10 from M and 3 from E. Then step the load/use stall, the not-taken jne, and the ret.

What the book says

4.5.6 · Exception handling

Carry the bad news in the tray. Act on it only at the end.

Several instructions can look exceptional in the same cycle: a halt in fetch, a bad address in memory. The one further down the pipe happened first in program order, so it wins. And a bad byte fetched because of a wrong branch guess must not raise anything, once the branch cancels it.

The fix is to put a stat field in every pipeline register. The exception travels with the instruction. Nobody stops the pipe early. When the bad instruction reaches memory, later instructions are blocked from changing the condition codes or the data memory. When it reaches write-back, the processor halts and reports that status. Canceled instructions take their status with them into the bubble.

Chioma’s pushq with %rsp equal to 0 tries to write address 0xfffffffffffffff8. That is ADR, discovered in memory. The addq behind it would have set the lamps. It must not.

Try it: step the push that faults. Watch stat move from stage to stage. When it sits in M, the add’s lamp update is crossed out. Switch to the canceled 0xFF and see the illegal instruction disappear with the bad guess.

What the book says

Y86-64 stops on halt, an illegal instruction, or an invalid address. In a pipeline, several exceptions can be in flight, and an instruction can be canceled after it has already raised one. The rule is to honor the exception of the instruction furthest along the pipeline, because that instruction is earlier in program order. An invalid instruction fetched on a mispredicted branch must not be reported after the branch cancels it.

Each pipeline register carries stat. If an instruction faults, the status is recorded and travels with it. Updating of the condition codes and data memory is disabled while an excepting instruction is in memory or write-back, so younger instructions cannot change programmer-visible state. When the excepting instruction reaches W, execution stops and W_stat becomes the program status. The book’s example sets %rsp to 0 and then pushq %rax, which tries to write 0xfffffffffffffff8. The following addq must not update the condition codes.

The mispredict example fetches .byte 0xFF at the target of a not-taken jne. Decode can see an illegal instruction. The cancel throws that status away with the instruction.

Same blocks as SEQ. The names say which copy of the value.

4.5.8 · Pipeline control logic

Stall, bubble, or let it slide

Forwarding and prediction cover the common case. Four leftovers need a controller. A load/use hazard holds F and D still and pushes a bubble into E. A ret stalls fetch for three cycles; the instruction after ret is fetched and then replaced by a bubble in D, because fetch itself cannot inject a bubble. A mispredicted branch bubbles D and E and fetches the fall-through on the same beat the mistake is known.

An exception is quieter. The pipe keeps moving, but once the bad instruction is in memory the controller blocks condition-code writes, bubbles the memory stage so data memory is not written, and stalls write-back when the exception arrives there. Combinations of these — a return meeting a load/use, a branch meeting a return — are where the design gets picky. The book’s systematic tests exist because those combinations are easy to get wrong.

Try it: press the four cases. F, D, and E show Normal, Stall, or Bubble. The code panel is the condition that made the controller do it.

What the book says

Pipeline control handles load/use hazards, ret, mispredicted branches, and exceptions. Load/use: if the instruction in E is mrmovq or popq and its dstM matches a source of the instruction in D, keep F and D fixed and inject a bubble into E. Processing ret: stall until the return address is available. Fetch still reads memory every cycle, predicting valP, so the following instruction is fetched and then replaced by a bubble in D for three cycles (Figure 4.62).

A mispredicted branch is discovered when the jump is in execute. The next cycle injects bubbles into D and E and fetches the fall-through (Figure 4.56). For an exception, status already travels in the pipeline registers. As the excepting instruction reaches memory, condition-code updates are disabled, a bubble is injected toward memory so data memory is not written, and write-back stalls when it holds the exception, halting the machine (Figure 4.63).

The special cases can overlap. The book works through the combinations so that a single setting of the stall and bubble signals does the right thing when, for example, a load/use and a mispredicted branch are discovered together. The testing aside lists ctest: 22 control combinations.

4.5.9 · Performance analysis

The dream CPI is 1. The sample lands at 1.27.

If every cycle issued a new instruction, CPI would be 1. Bubbles push it up. A load/use inserts one bubble, a mispredicted branch inserts two, a return inserts three. CPI = 1 + lp + mp + rp, where each penalty is how often that bubble happens per instruction.

The book’s mix: loads are 25% of instructions and 20% of those stall, so lp = 0.05. Conditional branches are 20%, and 40% of them are not taken, two bubbles each, so mp = 0.16. Returns are 2%, three bubbles each, so rp = 0.06. The sum is 0.27. CPI is 1.27. Mispredicts are the biggest slice. A predictor that is right 65% of the time, such as backward-taken forward-not-taken, drops the miss rate to 35% and the CPI to 1.25.

Try it: drag the miss rate. Leave it at 40% to see 1.27, or set the success near 65% and read 1.25. The three products sit in the tags on the formula.

What the book says

CPI is the average number of clock cycles per instruction, the reciprocal of throughput measured in cycles. If execute processes Ci instructions and Cb bubbles, CPI = (Ci + Cb) / Ci = 1 + Cb / Ci. Only three causes inject bubbles, so CPI = 1.0 + lp + mp + rp.

The book’s frequencies, comparable to measurements it cites: loads (mrmovq and popq) are 25% of instructions and 20% of them cause a load/use hazard (1 bubble) so lp = 0.05. Conditional branches are 20%, 40% not taken, 2 bubbles, so mp = 0.16. Returns are 2%, always 3 bubbles, so rp = 0.06. Total penalty 0.27, CPI 1.27. Mispredicted branches are the largest part, 0.16 of 0.27.

Practice Problem 4.43 asks about a predictor with a 65% success rate. The solution recomputes the mispredict penalty as 0.20 × 0.35 × 2 = 0.14, and the CPI as 1.25. 4.5.10 · Unfinished business

A divide that sits in execute, and a cache that sometimes misses

Every Y86-64 instruction finishes execute in one cycle. A real integer divide can take as many as 64. Floating-point add is more like 3 or 4. The simple repair is to let the instruction sit in execute and stall fetch and decode until it is done. That works, and it is slow. A faster design issues the divide to its own functional unit and lets the rest of the pipe keep moving, forwarding the result back when it is ready. The stalls and side doors are the same ideas as before. There are just more of them.

The other shortcut in PIPE is memory that always answers in one cycle. A first-level cache usually does. A miss costs about 3 to 20 cycles while the pipe holds the instruction in fetch or memory. A page that lives on disk takes millions of cycles: the hardware raises a page fault, the operating system fetches the page, and the instruction runs again. From the pipeline’s point of view that is just another exception.

Try it: set the divide to 4 cycles and press Step. Fetch and decode freeze while execute counts down. Then switch to a cache miss and hold the load in memory for a few beats.

What the book says

Multicycle operations such as integer multiply and divide, and floating-point arithmetic, do not finish in one execute cycle. In a processor like PIPE, floating-point addition might take 3 or 4 cycles and integer division as many as 64. One approach expands execute and stalls fetch and decode while the instruction remains there. Better performance comes from separate functional units that accept an issued instruction and run alongside the main pipe, with forwarding and stalls to honor dependencies.

PIPE also assumes instruction and data memory respond in one cycle, ignores self-modifying code, and treats virtual addresses as if they were physical. Caches and a TLB make the one-cycle assumption true most of the time. A cache miss typically costs 3 to 20 cycles and is handled by stalling the instruction in fetch or memory. A reference that reaches disk raises a page-fault exception; the operating system brings the page in, which can take millions of cycles, and the instruction is re-executed. Chapters 6 and 9 are the memory side of this story.

4.6 · Summary

Two kitchens, one plate

The ISA tells a sequential story: each instruction finishes before the next begins. SEQ implements that story almost literally, one long cycle per instruction. PIPE keeps five instructions in the building. The plate that comes out — the registers, the memory, the PC, the status — has to be the same plate.

Three lessons close the chapter. Keep the hardware uniform so every instruction shares it. Do not implement the ISA’s story directly if a faster story can be made to match. And be meticulous: once the chip exists, a wrong stall signal is not a patch you ship later. The design’s own tests missed a bug in one control combination until a more systematic pass found it.

Try it: press Play. SEQ finishes subq before the next instruction starts. PIPE overlaps them. Both leave %rbx at 12. The code is the four-line program both machines run.

What the book says

The ISA is an abstraction between the instructions a program may use and the way a processor implements them. It presents sequential execution. The chapter defines Y86-64 by simplifying x86-64, organizes execution into stages, builds SEQ, then retimes it into SEQ+ and adds pipeline registers to make PIPE−. Forwarding and extra control logic turn that into PIPE, preserving the sequential behavior.

The closing lessons: manage complexity by a simple uniform framework that shares hardware; you do not need to implement the ISA directly, because a pipeline can be made to match the sequential results; hardware designers must be meticulous, because a fabricated chip is nearly impossible to patch. The PIPE control logic had a subtle bug that showed up only under a systematic analysis of control combinations.

A five-stage pipeline was the state of the art in the mid-1980s (the Berkeley RISC work that became SPARC, the Stanford work that became MIPS, and the Intel i486). CPI for such a pipe cannot drop below 1.0. Superscalar and out-of-order designs, the subject of Chapter 5, can. Most processors sold today are simpler pipes in embedded systems, where cost and power matter. The CPI discussion also notes that the measure people quote for superscalar chips is often IPC, the reciprocal of CPI.

4.6.1 · Y86-64 simulators

Trust yis. Then make the pipeline agree.

The lab gives SEQ and PIPE simulators in two costumes. The picture version shows memory, code, and state, and it lets you reset, step, or run. The text version prints the same run, which is less friendly and much easier to script. Both are driven by the HCL. A translator turns the control expressions into C, and that C is compiled and linked with the rest of the simulator. Edit the HCL, rebuild, and you are testing a different processor.

The reference answer is still yis, which only knows the instruction set. Idris reverses the two write-back forwarding cases. popq %rsp then a move should put the memory value 5 into %rax. The reversed priority forwards the incremented stack pointer, 0x108, instead. yis does not budge. The pipeline simulator does. That gap is the bug.

Try it: press Step through assemble, yis, and the pipeline simulator. Then turn on reversed priority and step again. yis still says 5. The pipe says 0x108.

What the book says

The lab materials include simulators for SEQ and PIPE. Each has a GUI version, which shows memory, code, and processor state and can reset, single-step, or run, and a text version that prints to the terminal for automated testing. Control logic is generated by translating the HCL into C, then compiling and linking it with the simulator. Editing the HCL and rebuilding is how the exercises try new instructions and new pipeline behavior. Testing scripts exercise instructions and hazards.

The solution to the write-back priority exercise uses irmovq $5, %rdx, irmovq $0x100, %rsp, a store of %rdx at (%rsp), popq %rsp, two nops, and rrmovq %rsp, %rax. With the nops, the pop is in write-back when the move is in decode. Reversing the two write-back forwarding sources delivers the incremented stack pointer instead of the value read from memory. yis remains the reference for the programmer-visible result.

Words to know

The chapter’s grown-up words, in one plain sentence each.

ISA
The contract: registers, instructions, encodings, and exceptions. Programs see this, not the wiring.
Y86-64
The book’s teaching instruction set: a smaller, more regular cousin of x86-64, with 15 registers.
icode / ifun
The two nibbles of the first instruction byte: which instruction, and which extra.
valC / valP
The 8-byte constant inside an instruction, and the address of the next sequential instruction.
Stat
AOK, HLT, ADR, or INS. Anything but AOK stops this processor.
HCL
The hardware control language: Boolean expressions and case expressions that name control wires.
combinational
Gates with no memory. Outputs follow inputs after a delay. Loops and tied outputs are forbidden.
SEQ
The sequential processor: all six stages in one long cycle, one instruction done.
SEQ+
SEQ with the PC computed at the start of the cycle, from leftovers of the previous instruction.
throughput
Finished instructions per second. Pipelining’s main prize.
latency
How long one instruction spends from start to finish. A pipe can make this a little worse.
hazard
A dependency that would make the pipeline disagree with the sequential ISA.
forwarding
Hand a result from execute, memory, or write-back straight to decode, instead of waiting for the register file.
bubble
A nop injected into a stage so a stalled instruction does not have to slide forward.
load interlock
The one-cycle stall when the very next instruction needs a value a load has not read yet.
CPI
Clock cycles per instruction. On the book’s sample mix, PIPE lands at 1.27 rather than 1.00.
