23 · all-pairs shortest paths: the problem

One table, every distance

A road atlas has a table of distances: find a city in the rows, another in the columns, read the number where they cross. The all-pairs shortest-paths problem asks for that whole table at once. The input is a weighted, directed graph; the output is, for every pair of vertices i and j, the weight δ(i, j) of a shortest path from i to j. A real use is a network's diameter, the longest of all the shortest paths: the slowest message the network can ever have to carry.

The graph arrives as a matrix W: row i, column j holds the weight of the edge (i, j), 0 on the diagonal, and ∞ where there is no edge. The answer is a matrix D of the shortest distances. To get the routes as well, a second matrix Π remembers, for each pair, the vertex just before j on a shortest path from i; PRINT-ALL-PAIRS-SHORTEST-PATH follows those predecessors back and prints the path.

The obvious plan is to run a single-source algorithm once from every vertex, one row at a time. It works, and it is the yardstick the rest of the chapter has to beat.

Try it: click any cell of the table to choose a pair: the graph lights the shortest path, and the tabs switch between W, D and Π. Press Step or Play to watch PRINT-ALL-PAIRS-SHORTEST-PATH read the path out of Π, one recursive call at a time. Click an edge to cut it: ∞ and NIL appear, and the procedure reports “no path”. Then try Fill it by n runs and watch the table grow a row per run.

What the book says

The input is a weighted, directed graph G = (V, E) with a weight function w : E → ℝ, and the goal is to find, for every pair of vertices u, v ∈ V, a shortest (least-weight) path from u to v. The output typically takes a tabular form in which the entry in u’s row and v’s column is the weight of a shortest path from u to v. “A legitimate application of all-pairs shortest paths is to determine the diameter of a network: the longest of all shortest paths.” A road atlas is the classic example, but not a true one: an atlas might list 100 cities, while the United States has approximately 300,000 signal-controlled intersections.

You can run a single-source algorithm |V| times. With nonnegative weights, Dijkstra’s algorithm with a linear-array priority queue takes O(V3); a binary min-heap gives O(V(V + E) lg V), faster than O(V3) when the graph is sparse; a Fibonacci heap gives O(V2 lg V + VE). With negative-weight edges, running Bellman-Ford from every vertex takes O(V2E), which is O(V4) on a dense graph. The chapter shows how to guarantee a much better asymptotic running time.

Most algorithms in this chapter represent the graph by an adjacency matrix W = (wij) of an n-vertex graph with vertices numbered 1, …, n: wij = 0 if i = j, the weight of the directed edge (i, j) if i ≠ j and (i, j) ∈ E, and ∞ if i ≠ j and (i, j) ∉ E. Negative-weight edges are allowed, but for the time being there are no negative-weight cycles. Johnson’s algorithm, in Section 23.3, uses adjacency lists.

A full solution also includes a predecessor matrix Π = (πij), where πij is NIL if i = j or there is no path from i to j, and otherwise the predecessor of j on some shortest path from i. The subgraph induced by the ith row of Π should be a shortest-paths tree with root i. PRINT-ALL-PAIRS-SHORTEST-PATH is a modified version of PRINT-PATH from Chapter 20. Matrices are written in uppercase (W, L, D), their entries in subscripted lowercase, and iterates with parenthesized superscripts.

23.1 · shortest paths and matrix multiplication

Matrix multiplication in disguise

Take a shortest path from i to j that uses at most r edges and cut off its last edge (k, j). What is left is a shortest path from i to k with at most r − 1 edges, because every piece of a shortest path is itself a shortest path. So the cheapest path with at most r edges comes from trying every possible last stop k: lij(r) = min over k of ( lik(r−1) + wkj ). Choosing k = j means “no extra edge”, since wjj = 0.

Look at its shape: one entry of a new matrix is built from a row of one matrix and a column of another. That is matrix multiplication, with min where the usual product adds and + where it multiplies. EXTEND-SHORTEST-PATHS is MATRIX-MULTIPLY’s triple loop under that swap, and SLOW-APSP applies it n − 1 times: L(1) = W, then W2, W3, … Since a shortest simple path has at most n − 1 edges, L(n−1) holds every δ(i, j). That is n − 1 products of Θ(n3) each: Θ(n4).

Try it: press Step to build L(1), L(2), …: entries can only fall as more edges are allowed. Click any cell of the right-hand matrix M to see its five candidates, k = 1…5: the row of L and the column of W that meet there, the minimum lit, and its path drawn on the graph. Click a candidate to draw that one instead, and Walk the k loop to count them one by one. After the last product press Step once more: nothing changes. Switch to + and × to run the same three loops with ordinary arithmetic.

What the book says

The section follows the steps of dynamic programming from Chapter 14: characterize the structure of an optimal solution, define its value recursively, compute it bottom up. The fourth step, constructing an optimal solution, is left to the exercises. By Lemma 22.1 all subpaths of a shortest path are shortest paths. For a shortest path p from i to j with at most r edges, if i = j then p has weight 0 and no edges; otherwise decompose p into a path p′ from i to some k with at most r − 1 edges and the edge (k, j), so δ(i, j) = δ(i, k) + wkj.

Let lij(r) be the minimum weight of any path from i to j that contains at most r edges. For r = 0 it is 0 if i = j and ∞ otherwise. For r ≥ 1, one way to achieve the minimum is a path with at most r − 1 edges; another is a path of at most r − 1 edges to some k followed by the edge (k, j). To examine paths with at most r edges, “try all possible predecessors k of j”, which gives equation (23.3); the two cases merge because wjj = 0. Without negative-weight cycles a path with more than n − 1 edges cannot beat a shortest one, so δ(i, j) = lij(n−1) = lij(n) = lij(n+1) = ⋯.

EXTEND-SHORTEST-PATHS implements (23.3) for all i and j; its output matrix is initialized to ∞, and it runs in Θ(n3) time because of the three nested loops. Substituting l(r−1) → a, w → b, l(r) → c, min → +, and + → · in (23.3), and replacing ∞ (the identity for min) by 0 (the identity for +), yields MATRIX-MULTIPLY. The book notes in a footnote that this operation lives in what is known as the “tropical semiring”, with min for ⊕, + for ⊗, ∞ for the identity of ⊕ and 0 for the identity of ⊗.

SLOW-APSP computes L(1) = L(0) · W = W1, L(2) = W2, and so on up to L(n−1) = Wn−1. It uses two n × n matrices L and M; the invariant at the start of iteration r is L = L(r−1). The n − 1 calls of EXTEND-SHORTEST-PATHS dominate: Θ(n4) in total. Figure 23.1 shows the graph and L(1) through L(4); the figure’s caption notes that L(5) equals L(4).

23.1 · repeated squaring

Doubling instead of crawling

SLOW-APSP crawls: one more edge per product, n − 1 products in all. But the goal is only L(n−1), not every matrix on the way there. And the min-plus product is associative, as the ordinary one is, so powers can be built by repeated squaring: L(1) = W, L(2) = W ⊗ W, L(4) = W2 ⊗ W2, L(8) = W4 ⊗ W4, … Each product doubles the number of edges a path may use.

Overshooting is harmless: L(r) = L(n−1) for every r ≥ n − 1, because no shortest path needs more edges. So FASTER-APSP squares until r ≥ n − 1: only ⌈lg(n − 1)⌉ products instead of n − 1. Each product still costs Θ(n3), so the total is Θ(n3 lg n) against Θ(n4), with no elaborate data structure behind it.

Try it: press Step or Play. The left matrix is multiplied by itself into the right one, which then becomes the new left matrix, and the ladder below marks which edge counts have been reached. In Ring of 7 the last squaring reaches 8 edges when only 6 are ever needed, and nothing changes. In Count drag n up to a million and watch n − 1 products shrink to about twenty.

What the book says

The goal is not to compute all the L(r) matrices: only L(n−1) matters. In the absence of negative-weight cycles, equation (23.4) implies L(r) = L(n−1) for all integers r ≥ n − 1. “Just as traditional matrix multiplication is associative”, so is the matrix multiplication defined by EXTEND-SHORTEST-PATHS (Exercise 23.1-4). Therefore L(n−1) can be computed with only ⌈lg(n − 1)⌉ matrix products by repeated squaring: L(1) = W, L(2) = W2 = W · W, L(4) = W4 = W2 · W2, and so on up to L(2^⌈lg(n−1)⌉). Since 2⌈lg(n−1)⌉ ≥ n − 1, the final product is L(n−1).

FASTER-APSP takes just W and n. Each iteration of its while loop starts with the invariant L = Wr, which it squares with EXTEND-SHORTEST-PATHS to get M = L2 = W2r. At the end of each iteration r doubles and L becomes M, restoring the invariant. When the loop exits with r ≥ n − 1 the procedure returns L = Wr = L(r) = L(n−1). As in SLOW-APSP, the assignments to n × n matrices in lines 2, 5 and 8 take Θ(n2) time each.

Because each of the ⌈lg(n − 1)⌉ matrix products takes Θ(n3) time, FASTER-APSP runs in Θ(n3 lg n) time. The code is tight, with no elaborate data structures, and the constant hidden in the Θ-notation is therefore small.

23.2 · the Floyd-Warshall algorithm

One more stopover at a time

Number the airports 1 to n. Today you may change planes only at airport 1. Tomorrow at 1 or 2, the day after at 1, 2 or 3. Each day you ask every pair of airports the same question: is there now a cheaper trip that stops over at the newest one? After n days all the stopovers are allowed, so every price is final.

That is the Floyd-Warshall algorithm. An intermediate vertex of a path is any vertex except its two ends, and d(k)ij is the weight of the cheapest path from i to j whose intermediates all come from {1, …, k}. With k = 0 no stopover is allowed, so d(0)ij is just the edge weight wij.

Going from k − 1 to k there are only two kinds of best path. One never stops at k, so its price is the old d(k−1)ij. The other stops at k exactly once: a best path i to k followed by a best path k to j, both built from the older stopovers. The recurrence keeps the smaller price. Three nested loops, so Θ(n3) time, and nothing fancier than a table.

Try it: press Step to test one pair at a time: the two blue cells are the halves of the detour through k, the yellow cell is the one being tested, and mint means it just got cheaper. Next k finishes the round and Play runs all five. Before you start, click an edge to cut it and watch ∞ stay ∞. Then flip to In place and look at the memory strip: one matrix instead of two, same answer.

What the book says

The Floyd-Warshall algorithm is another dynamic-programming solution to the all-pairs problem. It runs in Θ(V3) time; negative-weight edges may be present, but not negative-weight cycles. The book develops it by the dynamic-programming process and then uses a similar method for the transitive closure of a directed graph.

It looks at the intermediate vertices of a shortest path, where an intermediate vertex of a simple path ⟨v1, v2, …, vl⟩ is any vertex other than v1 or vl. Number the vertices 1, …, n, fix k, and let p be a minimum-weight path from i to j among those whose intermediates all lie in {1, …, k}. If k is not an intermediate vertex of p, then p is also a shortest path with intermediates in {1, …, k − 1}. If it is, split p at k into p1 from i to k and p2 from k to j: by Lemma 22.1 each is a shortest path, and because k is not an intermediate vertex of either, each uses only {1, …, k − 1}.

That gives recurrence (23.6): d(k)ij = wij if k = 0, and min{d(k−1)ij, d(k−1)ik + d(k−1)kj} if k ≥ 1. Every path has all its intermediates in {1, …, n}, so the matrix D(n) holds the answer, d(n)ij = δ(i, j).

FLOYD-WARSHALL computes the matrices bottom up in increasing k; Figure 23.4 shows them for the graph of Figure 23.1, which is the graph in the machine. Line 6 takes O(1) time and sits in three nested loops, so the running time is Θ(n3). The code is tight, with no elaborate data structures, so the hidden constant is small and the algorithm is practical even for moderate-sized graphs.

As written, the procedure creates a new matrix for every k and needs Θ(n3) space. 23.2 · constructing shortest paths and transitive closure

A breadcrumb for every pair

A distance table says how far, not which way. So Floyd-Warshall keeps a second table, the predecessor matrix Π: πij is the vertex just before j on a cheapest path from i, or NIL if there is none. It starts as πij = i for every edge. Whenever stopping at k wins, the new route to j ends exactly like the best route from k to j, so the cell copies πkj.

To print a route read row i only: j, then j's predecessor, then that vertex's predecessor, back to i. PRINT-ALL-PAIRS-SHORTEST-PATH does it by recursion and prints on the way back out, so the route reads in the right order. After k rounds, Π(k) describes the best routes that stop only at 1 … k, so you can slide k and watch a route change.

Sometimes you only want yes or no: is there any path from i to j? That is the transitive closure. Run the same three loops with ∨ and ∧ in place of min and +: tij becomes 1 if it already is 1, or if tik and tkj both are. Still Θ(n3), but every entry is one bit instead of a number.

Try it: in Shortest paths, click a vertex for where the route starts (i), another for where it ends (j), and press Print path: the recursion piles up in the memory strip, then prints on the way out. Drag rounds done to see Π at any stage; at 0 some routes do not exist yet. Build Π replays the five rounds. Add edge 2→1 creates a negative cycle: watch the diagonal. In Reachability, click a vertex to see what it reaches, or an edge to cut it, and slide the rounds.

What the book says

There are several ways to construct shortest paths in the Floyd-Warshall algorithm. One is to compute the matrix D of shortest-path weights and then build the predecessor matrix Π from it (Exercise 23.1-7 asks for that in O(n3) time). Alternatively Π can be computed while the algorithm computes D(0), D(1), …, D(n): a sequence Π(0), …, Π(n) with Π = Π(n), where π(k)ij is the predecessor of j on a shortest path from i with all intermediate vertices in {1, …, k}.

Equation (23.7) starts it: π(0)ij is NIL if i = j or wij = ∞, and i if i ≠ j and wij < ∞. For k ≥ 1, equation (23.8) says π(k)ij is π(k−1)kj if d(k−1)ij > d(k−1)ik + d(k−1)kj (k is an intermediate vertex), and π(k−1)ij otherwise. Exercise 23.2-3 asks you to build this into FLOYD-WARSHALL and to prove that each predecessor subgraph is a shortest-paths tree; the machine's first listing is that modified procedure, so it is a sketch, not the book's own pseudocode. Figure 23.4 shows the matrices Π(k) for the graph of Figure 23.1.

PRINT-ALL-PAIRS-SHORTEST-PATH (p. 648) is a modified version of the PRINT-PATH procedure from Chapter 20. It assumes that each predecessor subgraph Gπ,i is a shortest-paths tree rooted at i, which is why it only ever looks at row i of Π.

The transitive closure of a directed graph G = (V, E) is the graph G* = (V, E*) with E* = {(i, j) : there is a path from vertex i to vertex j in G}. One way to get it in Θ(n3) time is to give every edge weight 1 and run Floyd-Warshall: a finite dij means a path exists, and ∞ means none. Another substitutes the logical operations ∨ (OR) and ∧ (AND) for min and +. Define t(k)ij to be 1 if there is a path from i to j with all intermediate vertices in {1, …, k}, and 0 otherwise; recurrence (23.9) is t(k)ij = t(k−1)ij ∨ (t(k−1)ik ∧ t(k−1)kj).

TRANSITIVE-CLOSURE, like Floyd-Warshall, runs in Θ(n3) time. On some computers, logical operations on single bits execute faster than arithmetic on integer words, and because the algorithm uses only boolean values, its space requirement is smaller by a factor corresponding to the size of a word of storage. Figure 23.5 shows the matrices T(k) for a sample graph, which is the graph in the machine's second mode. Exercise 23.2-6 asks how to use the output of Floyd-Warshall to detect a negative-weight cycle; the machine's diagonal row is one answer.

23.3 · Johnson's algorithm: reweighting

Shift every vertex, keep every route

Dijkstra's algorithm is quick, but it trusts that no edge is negative. Johnson's trick is to re-price the graph first. Give every vertex v a number h(v), like a height, and charge each edge (u, v) the new price ŵ(u, v) = w(u, v) + h(u) − h(v). Leaving a high vertex costs extra, arriving at a low one is refunded.

Why routes survive: add up the new prices along any path from a to b. Each middle vertex is charged once on the way in and refunded once on the way out, so everything cancels and the path's weight changes by exactly h(a) − h(b). That shift depends only on the two ends. Every path between the same two vertices moves by the same amount, so the cheapest one stays the cheapest. A cycle starts and ends at the same vertex, so it does not move at all: a negative cycle stays negative, and nothing else becomes one.

Which heights remove every negative edge? Add a new vertex s with a 0-weight edge to every vertex, and let h(v) = δ(s, v), the shortest distance from s, found by Bellman-Ford. Distances obey h(v) ≤ h(u) + w(u, v), and that is the same statement as ŵ(u, v) ≥ 0. Now Dijkstra can run.

Try it: in Choose h use the − and + buttons to move each vertex's h. Edge labels read w → ŵ, and an edge turns coral when its new price is negative. Click an edge to see its sum. Can you clear both coral edges by hand? Then press Bellman-Ford h and watch h settle, pass after pass. In Compare paths click two vertices to list every simple path between them (the same vertex twice lists its cycles), then press Random h a few times: the prices move, the winner never does.

What the book says

Johnson's algorithm finds shortest paths between all pairs in O(V2 lg V + VE) time, so for sparse graphs it is asymptotically faster than repeated squaring of matrices or the Floyd-Warshall algorithm. It returns a matrix of shortest-path weights, or reports that the input graph contains a negative-weight cycle, and it uses both Dijkstra's algorithm and the Bellman-Ford algorithm as subroutines.

The technique is reweighting. If all weights are nonnegative, running Dijkstra from every vertex solves the problem; with a Fibonacci heap that takes O(V2 lg V + VE). If G has negative-weight edges but no negative-weight cycles, first compute new nonnegative weights ŵ with two properties: for all pairs u, v, a path is a shortest path under w if and only if it is one under ŵ, and every ŵ(u, v) is nonnegative. Computing ŵ takes O(VE) time.

Lemma 23.1 (“Reweighting does not change shortest paths”): for any function h : V → ℝ and ŵ(u, v) = w(u, v) + h(u) − h(v) (equation 23.10), a path p = ⟨v0, v1, …, vk⟩ is a shortest path under w if and only if it is one under ŵ; also G has a negative-weight cycle under w if and only if it has one under ŵ. The proof shows ŵ(p) = w(p) + h(v0) − h(vk) (equation 23.11) because the sum telescopes. The added term does not depend on the path, and for a cycle v0 = vk, so ŵ(c) = w(c).

To make every weight nonnegative, build G′ with V′ = V ∪ {s} for a new vertex s, E′ = E ∪ {(s, v) : v ∈ V}, and w(s, v) = 0. No edges enter s, so no shortest path other than one starting at s contains it, and G′ has a negative-weight cycle if and only if G does. If neither does, define h(v) = δ(s, v). By the triangle inequality (Lemma 22.10), h(v) ≤ h(u) + w(u, v) for every edge, so ŵ(u, v) ≥ 0. 23.3 · Johnson's algorithm for sparse graphs

Level the road, then send Dijkstra everywhere

Dijkstra is fast but trusts that no edge is negative. Bellman-Ford copes with negative edges but is slow, and running it from every vertex costs O(V2E). Johnson's algorithm pays for Bellman-Ford exactly once, and then uses Dijkstra for all the rest.

First add a new vertex s with a 0-weight edge to every vertex. One Bellman-Ford run from s gives every vertex a height h(v) = δ(s, v). Then reweight each edge: ŵ(u, v) = w(u, v) + h(u) − h(v). Every new weight is non-negative, and every path from a to b changes by the same amount, h(a) − h(b), so the shortest paths stay the shortest paths.

Now run Dijkstra from each vertex on the new weights and undo the shift: duv = δ̂(u, v) + h(v) − h(u). With a Fibonacci heap the whole thing takes O(V2 lg V + VE); with a plain binary heap, O(VE lg V), still faster than Floyd-Warshall when the graph is sparse.

Try it: press Step to walk down the book's lines: s appears, Bellman-Ford settles h in two passes, the lightest edge goes from −5 to 0, then Dijkstra runs from vertex after vertex and each converted row lands in D. Next row finishes one vertex's turn. The four phase buttons jump to the start of a phase. Then press Make 3 → 2 cost 3 (vertices are numbered from 0 in the Rust view, so it reads 2 → 1 there): that closes a cycle of weight −1, h never settles, and line 3 reports it. In Rust, watch h change hands: Bellman-Ford's vector is moved, not copied.

What the book says

Johnson's algorithm finds shortest paths between all pairs in O(V2 lg V + VE) time, so for sparse graphs it is asymptotically faster than repeated squaring of matrices or the Floyd-Warshall algorithm. “The algorithm either returns a matrix of shortest-path weights for all pairs of vertices or reports that the input graph contains a negative-weight cycle.” It uses both Dijkstra's algorithm and the Bellman-Ford algorithm as subroutines, assumes that the edges are stored in adjacency lists, and numbers the vertices from 1 to |V|.

The technique is reweighting. If all weights are non-negative, Dijkstra's algorithm run once from each vertex finds all pairs. If G has negative-weight edges but no negative-weight cycles, first compute a new weight function ŵ with two properties: a path is a shortest path under w if and only if it is one under ŵ, and every new weight ŵ(u, v) is non-negative. Computing ŵ takes O(VE) time. Lemma 23.1 shows that ŵ(u, v) = w(u, v) + h(u) − h(v) preserves shortest paths for any function h from vertices to reals, because the sum telescopes: ŵ(p) = w(p) + h(v0) − h(vk). A cycle has v0 = vk, so its weight does not change either.

To make the weights non-negative, build G′ with a new vertex s and a 0-weight edge (s, v) for every vertex v. No edges enter s, and G′ has a negative-weight cycle if and only if G does. Setting h(v) = δ(s, v), the triangle inequality gives h(v) ≤ h(u) + w(u, v), which is exactly ŵ(u, v) ≥ 0.

JOHNSON builds G′ in line 1, runs Bellman-Ford in line 2 and reports a negative-weight cycle in line 3. Lines 4–5 set h, lines 6–7 compute ŵ, and the loop of lines 9–12 calls Dijkstra once from each vertex and stores duv = δ̂(u, v) + h(v) − h(u). With a Fibonacci-heap min-priority queue the running time is O(V2 lg V + VE); the simpler binary min-heap gives O(VE lg V). problem 23-1 · transitive closure of a dynamic graph

A new road, and everyone's reach changes

The transitive closure says who can reach whom. As a boolean matrix T, the entry T[i, j] is 1 when some path leads from i to j; every vertex reaches itself. Floyd-Warshall builds it in Θ(n3). But suppose the graph keeps growing, one new one-way road at a time. Recomputing everything after each road is wasteful.

Add the edge (u, v). A pair (i, j) gains a path exactly when i could already reach u and v could already reach j: walk to u, take the new edge, walk on from v. So the new 1s form one block: the rows of everyone who reaches u, crossed with the columns of everyone v reaches. Two loops over the matrix find it in O(V2). One edge can really need that much: join a long chain to another and about V2/4 entries flip at once.

Still, the matrix has only V2 cells, and a cell only ever changes from 0 to 1. A row that already reaches v already holds all of row v, so it can be skipped. Every row that is merged gains at least one new 1, so over any sequence of insertions there are at most V2 merges, each costing O(V): O(V3) in all, the cost of a single static closure.

Try it: press Insert next edge a few times. Two chains grow; then 3 → 4 joins them and nine entries flip at once; then 6 → 1 closes a cycle and the last fifteen do. Blue marks the rows that reach u, yellow the columns v reaches. Or click a vertex and then another to insert an edge of your own (tail first), or Two chains to jump to just before the big one. In Rust, look at why row v is cloned.

What the book says

Problem 23-1 asks you to maintain the transitive closure of a directed graph as edges are inserted. In the book's words: “That is, after inserting an edge, you update the transitive closure of the edges inserted so far. Start with G having no edges initially, and represent the transitive closure by a boolean matrix.”

Part (a) asks how to update the closure G* = (V, E*) of a graph G = (V, E) in O(V2) time when a new edge is added. Part (b) asks for a graph and an edge e for which Ω(V2) time is required to update the closure after inserting e, no matter what algorithm is used. Part (c) asks for an algorithm that, for any sequence of r insertions, runs in total time Σ ti = O(V3), where ti is the time to update the closure upon inserting the ith edge, and for a proof that it attains the bound.

Section 23.2 defines the closure G* = (V, E*), where E* holds every pair (i, j) such that G has a path from i to j, and computes it in Θ(n3) time with TRANSITIVE-CLOSURE, whose starting matrix has tij = 1 when i = j or (i, j) is an edge. The book leaves Problem 23-1 as a problem; the procedure under the machine is a sketch of one answer, in the book's style.

problem 23-2 · shortest paths in ε-dense graphs

Tune the tree to the graph

A Fibonacci heap makes Dijkstra's algorithm fast, but it is a complicated structure. Can the plain d-ary heap of Problem 6-2 do as well? It can when the graph is dense enough. A graph is ε-dense if |E| = Θ(V1+ε) for a constant ε between 0 and 1: ε near 0 is nearly a tree, ε = 1 is as dense as a graph gets.

Dijkstra pays two bills: V EXTRACT-MINs and up to E DECREASE-KEYs. In a d-ary heap with V items, both walk about logd V levels. A decrease-key does one comparison per level; an extract-min must compare all d children on each level. So raising d makes the E bill smaller and the V bill bigger, and the two cross near d = E/V = Vε.

Pick d = Vε and the tree has only about 1/ε levels, a constant. Both bills are then about V1+ε/ε = O(E): single-source shortest paths in O(E) time, all pairs in O(VE), and with Johnson's reweighting even negative edges cost only O(VE), with no Fibonacci heap anywhere.

Try it: in One run, drag d along the curves: blue is the V extract-mins, lilac the E decrease-keys, black their sum. Press Find best d to watch BEST-D sweep d, and d = V^ε to jump to the book's choice, where the blue and lilac bills meet. Then change ε and V. In Across ε, the cost per edge of the binary heap grows with lg V; the d-ary heap's stays flat.

What the book says

A graph G = (V, E) is ε-dense if |E| = Θ(V1+ε) for some constant ε in the range 0 < ε ≤ 1. The problem says that d-ary min-heaps (see Problem 6-2) provide a way to match the running times of Fibonacci-heap-based shortest-path algorithms on ε-dense graphs without using as complicated a data structure.

Part (a) asks for the asymptotic running times of INSERT, EXTRACT-MIN and DECREASE-KEY as a function of d and the number n of elements in a d-ary min-heap, and again when d = Θ(nα) for a constant 0 < α ≤ 1, compared with the amortized costs of the same operations for a Fibonacci heap. Part (b) asks for single-source shortest paths in O(E) time on an ε-dense directed graph with no negative-weight edges, with the hint to pick d as a function of ε. Part (c) asks for all pairs in O(VE) time on such a graph, and part (d) for all pairs in O(VE) time when negative-weight edges are allowed but no negative-weight cycles exist.

The book leaves all four parts as problems. The machine's cost model is the page's own sketch: V calls of EXTRACT-MIN at d⌈logd V⌉ comparisons each, and E calls of DECREASE-KEY at ⌈logd V⌉ comparisons each, with every hidden constant set to 1 and |E| = V1+ε.

The chapter on one page

Chapter 23 in eight cards. Each one points at the scenes that act it out.

A table, not a tree

All-pairs shortest paths wants δ(i, j) for every pair, as an n × n matrix D, plus a predecessor matrix Π so any path can be printed. The graph arrives as an adjacency matrix W: 0 on the diagonal, ∞ for no edge. Running a single-source algorithm V times is the baseline: Bellman-Ford that way costs O(V2E), O(V4) on a dense graph. → 23 All pairs

Multiply with min and plus

lij(r) = min over k of ( lik(r−1) + wkj ) is the cheapest path with at most r edges. That is matrix multiplication with min where it adds and + where it multiplies. SLOW-APSP applies it n − 1 times, Θ(n4), and L(n−1) is the answer. → 23.1 Matrix paths

Square instead of crawl

The min-plus product is associative, so L(2), L(4), L(8), … come from squaring, and overshooting n − 1 is harmless. FASTER-APSP needs only ⌈lg(n − 1)⌉ products: Θ(n3 lg n) in total. → 23.1 Repeated squaring

One more stopover at a time

Floyd-Warshall asks which intermediate vertices a path may use: dij(k) = min( dij(k−1), dik(k−1) + dkj(k−1) ): skip k, or go i to k and on to j. Three nested loops give Θ(n3) with a small constant, and dropping the superscripts needs only Θ(n2) space. → 23.2 Floyd-Warshall

Breadcrumbs and reachability

Π(k) follows D(k): when going through k wins, πij copies πkj; otherwise it stays. With ∨ and ∧ in place of min and +, the same loops compute the transitive closure in Θ(n3) on single bits. A negative number on the diagonal gives a negative-weight cycle away. → 23.2 Paths and closure

Re-price the edges

Reweighting with ŵ(u, v) = w(u, v) + h(u) − h(v) shifts every path from a to b by the same h(a) − h(b), so shortest paths stay shortest. Add a vertex s with 0-weight edges, let h(v) = δ(s, v), and every new weight is ≥ 0. → 23.3 Reweighting

Bellman-Ford once, Dijkstra everywhere

JOHNSON runs Bellman-Ford once from s (or reports a negative cycle), reweights, runs Dijkstra from every vertex and converts back with duv = δ̂(u, v) + h(v) − h(u). It takes O(V2 lg V + VE) with a Fibonacci heap and O(VE lg V) with a binary heap, which beats Floyd-Warshall on sparse graphs. → 23.3 Johnson

The problems

Inserting an edge (u, v) updates a transitive closure in O(V2): every i that reaches u gains every j that v reaches, and any sequence of insertions can be handled in O(V3) in total. In an ε-dense graph, d-ary heaps with d = Θ(Vε) match Fibonacci heaps: all pairs in O(VE). → 23-1 Dynamic closure, 23-2 Dense graphs

Words to know

The book's words from this chapter, in plain language.

all-pairs shortest-paths problem
For every pair of vertices u, v of a weighted, directed graph, find the weight of a shortest path from u to v, and ideally the path too.
weight matrix W
The graph as an n × n table: wij is 0 if i = j, the edge's weight if there is an edge (i, j), and ∞ if there is none.
distance matrix D
The answer table: dij = δ(i, j), the weight of a shortest path from i to j.
predecessor matrix Π
πij is NIL if i = j or no path exists, otherwise the vertex just before j on some shortest path from i. Row i is a shortest-paths tree rooted at i.
diameter
The longest of all shortest paths in a network: the largest finite entry of D.
negative-weight cycle
A cycle whose weights add up to less than 0. Going round it again and again lowers any path, so shortest paths stop making sense; the chapter assumes there is none, and Johnson's algorithm reports one.
L(r)
The matrix of lij(r), the minimum weight of any path from i to j with at most r edges. L(0) has 0 on the diagonal and ∞ elsewhere; L(n−1) = D.
EXTEND-SHORTEST-PATHS
The step that allows one more edge: matrix “multiplication” with min for the sum and + for the product. Three nested loops, Θ(n3).
tropical semiring
The name the book gives to this algebra: min plays the part of addition, + the part of multiplication, ∞ the part of zero and 0 the part of one.
repeated squaring
Building Wr by squaring W, W2, W4, …, which doubles r with every product. It relies on the min-plus product being associative.
intermediate vertex
Any vertex of a simple path other than its first and last.
dij(k)
The weight of a shortest path from i to j all of whose intermediate vertices lie in {1, …, k}. D(0) = W and D(n) = D.
Floyd-Warshall algorithm
The dynamic program that computes D(k) for k = 1, …, n with three nested loops: Θ(n3) time.
transitive closure G*
The graph with an edge (i, j) whenever G has a path from i to j. As a boolean matrix T it is computed with ∨ and ∧ in place of min and +.
reweighting
Replacing w by ŵ(u, v) = w(u, v) + h(u) − h(v) for any function h from vertices to numbers. A path's weight changes by h(start) − h(end), so shortest paths are preserved.
telescoping sum
A sum whose middle terms cancel in pairs: along a path every h(v) is added once and subtracted once, except at the two ends.
h(v) = δ(s, v)
Johnson's choice of h: the shortest distance from a new vertex s that has a 0-weight edge to every vertex, found by Bellman-Ford. By the triangle inequality every ŵ is then ≥ 0.
Johnson's algorithm
Add s, run Bellman-Ford once, reweight, run Dijkstra from every vertex, and convert back with duv = δ̂(u, v) + h(v) − h(u).
sparse / dense
Sparse: |E| is much smaller than |V|2, and Johnson's algorithm shines. Dense: close to |V|2, where Floyd-Warshall's Θ(V3) is competitive.
ε-dense graph
A graph with |E| = Θ(V1+ε) for a constant ε with 0 < ε ≤ 1.
d-ary min-heap
A heap in which every node has up to d children (Problem 6-2). Choosing d = Θ(nα) balances the cost of EXTRACT-MIN against DECREASE-KEY.
dynamic graph
A graph that changes over time. In Problem 23-1 edges are only inserted, and the transitive closure is kept up to date after each insertion.

Rust words from the code panels

For readers coming from another language. Each one shows up in a listing above.

[[i64; N]; N]
A fixed-size array of arrays: N × N numbers in one block on the stack, no heap. When its items are Copy the array is Copy too, so let mut d = *w; duplicates the whole matrix.
Vec<Vec<i64>>
A matrix on the heap: an outer Vec of row Vecs, each with its own buffer. vec![vec![INF; n]; n] clones the inner row n times.
type alias
type Mat = Vec<Vec<i64>>; gives a long type a short name. It is the same type, not a new one.
const, static, const fn
const is a value fixed at compile time; static is one value at one address in read-only memory; a const fn may run at compile time, so it can fill a table.
INF and the guard before +
i64::MAX stands for ∞, and adding anything to it overflows (a panic in debug builds), so the code tests d[u] != INF first. A variant uses i64::MAX / 2, so that two infinities can still be added.
&Mat and &mut Mat
A shared borrow lends a matrix read-only; a mutable borrow lends it for writing. You may have many readers or one writer, never both, so extend(&l, &l, &mut m) compiles but a third &mut l would not.
move, copy, clone
l = m moves a Vec: three words change hands and the old matrix is dropped, freeing its heap. Arrays of Copy items are copied instead, and .clone() makes an explicit deep copy.
Option<usize> as NIL
None means no predecessor, Some(k) the vertex k. A match on it must handle both cases, which is how a path printer meets “no path”.
for &(u, v, w) in &EDGES
Loops over a borrowed list of tuples and takes each one apart in the loop header; the & pattern copies the small numbers out of the reference.
BinaryHeap and Reverse
A BinaryHeap pops its largest item; wrapping items in Reverse flips the order, which turns it into the min-priority queue Dijkstra needs.
?, ok_or and Result
ok_or turns a None into an Err, and ? returns that error from the function at once: the book's “report a negative cycle” as a type.
iterator chains
dist.iter().flatten().max().unwrap() walks every row and takes the largest entry; .map(…).collect() builds a new Vec from a closure applied to each item; zip pairs two rows entry by entry.
