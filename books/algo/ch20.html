part vi + 20.1 · graphs and how their size is measured

Dots, and the lines between them

A subway map, a friendship network and a build system look different, but they share one shape: some things, and some links between them. A graph G = (V, E) is a set V of vertices and a set E of edges, each edge a pair of vertices. In an undirected graph the edge (u, v) is the same as (v, u): a street open both ways. In a directed graph it has a direction, a one-way street, and an edge can even run from a vertex to itself.

The size of a graph's input is two numbers, |V| and |E|, so a running time like O(V + E) has two parameters. The degree of a vertex counts the edges that touch it. Each undirected edge touches two vertices, so the degrees add up to 2|E|. A directed edge leaves exactly one vertex and enters exactly one, so the out-degrees add up to |E| and so do the in-degrees. Section 20.1 uses this when it sizes the adjacency lists.

A path follows edges one after another. If a path leads from s to t, then t is reachable from s. In a directed graph reachability is not symmetric: you can reach 5 from 1 and still not 1 from 5.

Try it: click one vertex, then another, to add or remove the edge between them (in the directed graph, click the same vertex twice for a loop). Press Step or Play under Count degrees and watch each edge add one at both of its ends. Switch to Directed, then to Find a path: click where the path starts and where it ends, and try 5 to 1.

What the book says

Part VI opens with the remark that “Hundreds of interesting computational problems are couched in terms of graphs.” Chapter 20 shows how to represent a graph and how to search it breadth-first or depth-first, with two applications of depth-first search: topological sort of a directed acyclic graph and strongly connected components. Chapter 21 computes minimum spanning trees, Chapters 22 and 23 shortest paths, Chapter 24 maximum flow, and Chapter 25 matchings in bipartite graphs.

The size of the input to a graph algorithm is measured by two parameters, the number of vertices |V| and the number of edges |E|. Inside asymptotic notation, and only there, the symbol V denotes |V| and E denotes |E|, so “the algorithm runs in O(VE) time” means O(|V||E|). In pseudocode, the vertex set of a graph G is written G.V and its edge set G.E: attributes of the graph.

A graph G = (V, E) can be directed or undirected. The sum of the lengths of all adjacency lists is |E| for a directed graph, since an edge (u, v) puts v in Adj[u]; for an undirected graph it is 2|E|, because u appears in v's list and vice versa. 20.1 · adjacency lists vs adjacency matrices

An address book or a seating chart

There are two standard ways to write a graph down. An adjacency list is an address book: each vertex has a list of the vertices it is joined to. An adjacency matrix is a seating chart: a grid with a 1 in row u, column v when the edge (u, v) exists, and a 0 when it does not.

The lists take room in proportion to what is there: one slot per vertex plus one entry per edge end, which is Θ(V + E). The grid always has |V|² cells, whatever the edges, so it only pays off when the graph is dense, with |E| close to |V|². The grid wins one race: asking is (u, v) an edge? is one look at a cell, while the list has to be scanned for v.

An undirected edge sits in two lists and in two mirrored cells, so its matrix equals its own transpose. Weights ride along: store w(u, v) beside v in u's list, or in the cell itself.

Try it: click a vertex, then a second one (or click a matrix cell), and compare how many steps the list and the matrix need to answer is it an edge? Switch to Directed and the matrix stops being symmetric; a loop lands on the diagonal. Weighted adds made-up weights; Complete shows a dense graph, where the lists are no smaller than the grid.

What the book says

A graph G = (V, E) can be represented as a collection of adjacency lists or as an adjacency matrix, and either way applies to directed and undirected graphs. Adjacency lists are usually the method of choice because they are compact for sparse graphs, those with |E| much less than |V|². A matrix is preferable when the graph is dense, or when you must tell quickly whether an edge joins two given vertices.

The adjacency-list representation is an array Adj of |V| lists; Adj[u] contains all vertices v such that (u, v) ∈ E. The lists' lengths sum to |E| for a directed graph and to 2|E| for an undirected one, so the memory is Θ(V + E), and so is finding every edge, since each of the |V| lists must be examined. A weight w(u, v) is stored with v in u's list. A potential disadvantage is that no edge test is quicker than searching Adj[u] for v.

The adjacency matrix is the |V| × |V| matrix A = (aij) with aij = 1 if (i, j) ∈ E and 0 otherwise. It needs Θ(V²) memory regardless of the number of edges, and finding every edge takes Θ(V²) time. For an undirected graph A = AT, so only the entries on and above the diagonal need storing. A weight is stored as the entry itself, with NIL, 0 or ∞ where there is no edge. For unweighted graphs a matrix needs only one bit per entry.

Vertex and edge attributes, such as v.d, can live in additional arrays that parallel Adj, for instance d[1 : |V|]; the book notes there is no one best way to store them.

20.2 · breadth-first search

Ripples in a pond

Drop a pebble in a pond. The ripple touches everything one step away first, then everything two steps away, then three. Breadth-first search explores a graph the same way from a chosen source vertex s: first all of s's neighbours, then their neighbours, until every vertex s can reach has been discovered.

To keep track of the ripple it paints each vertex. White means not discovered yet. Gray means discovered and waiting on the frontier, in a first-in, first-out queue Q. Black means all its neighbours have been looked at, so it is behind the frontier. Every vertex also gets a distance d and a parent π, the vertex that discovered it.

Each vertex is enqueued at most once and each adjacency list is scanned at most once, so the whole search costs O(V + E): linear in the size of the graph.

Try it: press Step a few times, then Next vertex to finish one trip round the while loop (one panel of the book's figure), then Play. Before you start, click a vertex to make it the source, or click an edge to cut it: a vertex that s can no longer reach stays white, with d = ∞, for the whole run. In Rust, watch the queue's buffer: dequeuing only moves the head.

What the book says

Given a graph G = (V, E) and a distinguished source vertex s, breadth-first search systematically explores the edges of G to “discover” every vertex reachable from s. It computes the distance from s to each reachable vertex, the smallest number of edges needed to get there, and produces a breadth-first tree with root s that contains all reachable vertices. It works on both directed and undirected graphs, and expands the frontier between discovered and undiscovered vertices uniformly, in waves.

A single first-in, first-out queue holds some vertices at distance k, possibly followed by some at distance k + 1, so it contains portions of two consecutive waves at any time. All vertices start out white; vertices not reachable from s stay white the entire time. A vertex becomes gray when first discovered, and black once all its edges have been explored. The queue contains all the gray vertices; the loop invariant is “At the test in line 10, the queue Q consists of the set of gray vertices.”

BFS attaches three attributes to each vertex v: v.color, v.d (the distance from s, as computed by the algorithm) and v.π (its predecessor in the breadth-first tree, NIL for the source or an undiscovered vertex). Lines 1–4 initialise every vertex except s; lines 5–7 paint s gray with d = 0; lines 8–9 make the queue; the while loop of lines 10–18 runs as long as gray vertices remain.

The analysis is aggregate: after initialisation no vertex is whitened again, so each is enqueued, and dequeued, at most once, for O(V) of queue work. Each adjacency list is scanned only when its vertex is dequeued, and the lists' lengths sum to Θ(E), so the total is O(V + E). The tree may vary with the order in which line 12 visits neighbours, but the distances d do not. The procedure can also stop early once every vertex has a finite d.

20.2 · shortest paths and breadth-first trees

Follow the parent pointers home

BFS does more than visit vertices. Every time it discovers v from u, it writes down who found it: v.π = u. Start at any vertex and keep following π, and you walk back to the source along the way the search first reached it. The book proves that this way is a shortest path: the distance δ(s, v) is the fewest edges on any path from s to v (∞ if there is none), and when BFS stops, v.d = δ(s, v) for every vertex.

Why can't some other path be shorter? The queue always holds distances in the order k, …, k, k + 1, …, k + 1, so vertices are enqueued in non-decreasing distance, and a vertex found from u gets exactly u.d + 1. The edges (v.π, v) form the breadth-first tree: one simple path from s to each reachable vertex, and that path is a shortest one.

PRINT-PATH walks the pointers with a recursion: print the path to the parent, then print v. The machine has already run BFS from s.

Try it: click a vertex to make it the target, then Step or Play to watch the recursion dive to s and print on the way back. Press Another path to lay a different route over the graph and compare its length with d: none is ever shorter. Switch the neighbour order and the tree changes, but every d stays. Click an edge to cut it and pick a vertex s can no longer reach.

What the book says

The shortest-path distance δ(s, v) from s to v is the minimum number of edges in any path from s to v, and ∞ if there is no path. A path of length δ(s, v) is a shortest path. Lemma 20.1: for any edge (u, v), δ(s, v) ≤ δ(s, u) + 1, because a shortest path to v cannot be longer than a shortest path to u followed by that edge.

Lemma 20.2 shows that BFS never undershoots: at all times v.d ≥ δ(s, v), by induction on the number of ENQUEUE operations. Lemma 20.3 describes the queue ⟨v1, …, vr⟩: vr.d ≤ v1.d + 1 and vi.d ≤ vi+1.d, so the d values are all the same or run k, …, k, k + 1, …, k + 1. Corollary 20.4: the d values at the times vertices are enqueued increase monotonically.

Theorem 20.5 (correctness of breadth-first search): BFS discovers every vertex reachable from s, and on termination v.d = δ(s, v) for all v. Moreover, for any reachable v ≠ s, one of the shortest paths from s to v is a shortest path from s to v.π followed by the edge (v.π, v). The proof takes a vertex v with the wrong d and minimum δ, and shows that whether v is white, black or gray when its supposed predecessor u is dequeued, v.d ≤ u.d + 1, contradicting the assumption.

The predecessor subgraph Gπ has vertices {v : v.π ≠ NIL} ∪ {s} and edges {(v.π, v) : v ∈ Vπ − {s}}. It is a breadth-first tree if it contains the reachable vertices and, for each, a unique simple path from s that is also a shortest path in G. Lemma 20.6: BFS builds π so that this is true. PRINT-PATH runs in time linear in the number of vertices printed, “since each recursive call is for a path one vertex shorter.”

20.3 · depth-first search

The ball of string

Explore a cave with a ball of string. Walk down any tunnel you haven't tried, as deep as it goes. At a dead end, or a tunnel that only leads back to places you have already been, reel the string in to the last junction that still has an untried tunnel. That is depth-first search: always continue from the most recently discovered vertex that still has unexplored edges. If the cave has rooms the string never reached, pick one of them and start again, so the result is a depth-first forest of several trees, not just one.

Each vertex carries a colour and two timestamps. White means never seen. Gray means discovered but not finished: these are the vertices on your string, the calls of DFS-VISIT still open. Black means finished, its adjacency list fully examined. The clock ticks once when a vertex is discovered, giving u.d, and once when it is finished, giving u.f, so the stamps are integers from 1 to 2|V| and u.d < u.f always.

DFS-VISIT runs exactly once per vertex, because the first thing it does is paint its vertex gray, and its loop runs |Adj[v]| times, so all of DFS costs Θ(V + E). The recursion is a real call stack: in Rust, every gray vertex is one stack frame. The order in which line 5 picks roots and line 4 picks neighbours can change the forest, and the second mode shows it.

Try it: press Step a few times and watch the row of active calls grow and shrink as you go deeper and back up. Then press Play to finish Figure 20.4. Pick Start at w and Play again: u ends up alone in its own tree although it has edges going out. In Rust, the memory strip shows one frame per gray vertex.

What the book says

Depth-first search explores edges out of the most recently discovered vertex that still has unexplored edges, then backtracks. If undiscovered vertices remain, it selects one as a new source and repeats, so the predecessor subgraph is a forest, unlike breadth-first search, whose predecessor subgraph is a tree. The book notes that breadth-first search usually serves to find shortest-path distances, while depth-first search is often a subroutine in another algorithm.

Each vertex is initially white, grayed when discovered, and blackened when finished, that is, when its adjacency list has been examined completely. The first timestamp v.d records when v is first discovered, the second v.f when the search finishes examining v’s adjacency list. These are integers between 1 and 2|V|, and u.d < u.f (inequality 20.4). Vertex u is white before time u.d, gray between u.d and u.f, and black thereafter. DFS works on directed or undirected graphs; time is a global variable.

Lines 1–3 of DFS paint every vertex white and set π to NIL, line 4 resets the clock, and lines 5–7 call DFS-VISIT on every white vertex; each such call makes its vertex the root of a new tree. In DFS-VISIT, lines 1–3 increment the clock, record u.d and paint u gray, lines 4–7 examine each neighbour and recursively visit it if white, and lines 8–10 stamp u.f and paint u black. The results “may depend upon the order” in which the loops visit vertices and neighbours, but many applications can use the result from any depth-first search.

Running time: the loops of lines 1–3 and 5–7 of DFS take Θ(V) apart from the calls; DFS-VISIT is called exactly once per vertex, and its loop runs |Adj[v]| times, which sums to Θ(E). So DFS takes Θ(V + E) time. Figure 20.4 traces DFS on the graph of Figure 20.2 with letters for vertices; the machine reproduces it.

20.3 · properties of depth-first search and edge classification

Four kinds of edge

Every time DFS explores an edge (u, v) for the first time, the colour of v tells you what kind of edge it is. WHITE: the edge discovers v, a tree edge. GRAY: v is an open call, an ancestor of u, so the edge climbs back up, a back edge (a self-loop counts). BLACK: v is already finished, so the edge is a forward edge if v was discovered after u, and a cross edge otherwise.

The timestamps give a second view. Draw each vertex as the interval [d, f]. By the parenthesis theorem two intervals are either disjoint or one sits entirely inside the other, never a partial overlap, and nested means descendant. By the white-path theorem, v is a descendant of u exactly when, at time u.d, there is a path from u to v made only of white vertices.

In an undirected graph, (u, v) and (v, u) are one edge, and whichever end is explored first decides it. Then a forward or cross edge cannot exist: every edge is a tree edge or a back edge. That is why back edges, and nothing else, signal cycles, which the next two scenes use.

Try it: in Edge types, press Play and watch each edge turn yellow, then take the colour of its type. When it is done, click any vertex to test the white-path theorem. Then try Undirected: only T and B appear, and every edge is met twice. In Intervals, press Finish and click two bars.

What the book says

The predecessor subgraph of DFS is a forest because the structure of the depth-first trees mirrors the structure of recursive calls of DFS-VISIT: u = v.π if and only if DFS-VISIT(G, v) was called during a search of u’s adjacency list, and v is a descendant of u if and only if v is discovered while u is gray. If DFS-VISIT printed a left parenthesis when it discovers u and a right parenthesis when it finishes u, the result would be well formed, properly nested.

Theorem 20.7 (parenthesis theorem): for any two vertices, exactly one holds: the intervals [u.d, u.f] and [v.d, v.f] are entirely disjoint and neither is a descendant of the other; or one interval lies entirely within the other, and that vertex is a descendant. Corollary 20.8: v is a proper descendant of u if and only if u.d < v.d < v.f < u.f. Theorem 20.9 (white-path theorem) is the statement about white paths at time u.d.

The depth-first forest can contain four types of edge. Tree edges are the edges of the forest. Back edges connect a vertex to an ancestor, and self-loops are counted as back edges. Forward edges are nontree edges to a proper descendant. Cross edges are all others: between vertices of one tree when neither is an ancestor of the other, or between different trees. “You can redraw any graph in this fashion,” with tree and forward edges pointing down and back edges up (Figure 20.5(c)).

DFS can classify an edge as it first explores it: WHITE means a tree edge, GRAY a back edge, BLACK a forward or cross edge. The gray vertices form “a linear chain of descendants corresponding to the stack of active DFS-VISIT invocations.” Exercise 20.3-5 shows that a black edge is forward if u.d < v.d and cross if u.d > v.d. Theorem 20.10: in a depth-first search of an undirected graph, “every edge of G is either a tree edge or a back edge.”

20.4 · topological sort

Getting dressed in the right order

You cannot put your shoes on before your socks, but socks and trousers can go on in either order. Draw an arrow from each garment to the ones that must come after it, and you have a directed acyclic graph, a dag. A topological sort lines every vertex up so that all arrows point left to right. It exists only when there is no cycle: nothing can come before itself.

The algorithm is depth-first search plus one line: as each vertex finishes, put it at the front of a list. Why does it work? When a vertex finishes, everything it points to has already finished and sits to its right in the list. So every arrow ends further right than it begins. Run DFS, read the list, done, in Θ(V + E).

What if the graph has a cycle? Then DFS meets a back edge, an arrow to a gray vertex, and the list will have an arrow pointing the wrong way. In fact a directed graph is acyclic exactly when DFS finds no back edge (Lemma 20.11).

Try it: press Play: each garment drops into the list the moment it finishes, so the list fills from the right. Then press Add jacket → shirt (the professor insists the jacket goes on first) and Play again: a back edge appears and one arrow in the list points left. You can also click any two garments to add or remove an arrow of your own.

What the book says

A topological sort of a dag G = (V, E) is a linear ordering of all its vertices such that if G contains an edge (u, v), then u appears before v in the ordering. It is defined only on directed graphs that are acyclic: no linear ordering is possible when a directed graph contains a cycle. It helps to think of the ordering along a horizontal line with all directed edges going from left to right, and the book stresses that this differs from the usual kind of sorting studied in Part II.

Dags indicate precedences among events. Figure 20.7 shows Professor Bumstead getting dressed: a directed edge (u, v) means garment u must be donned before garment v, socks before shoes, while other items, such as socks and pants, may go on in any order. Figure 20.7(b) shows the sorted dag with vertices in order of decreasing finish time, all edges going from left to right.

TOPOLOGICAL-SORT has three steps: call DFS(G) to compute finish times v.f; as each vertex is finished, insert it onto the front of a linked list; return the list. It runs in Θ(V + E) time: DFS takes Θ(V + E) and each of the |V| front insertions takes O(1).

Lemma 20.11: a directed graph is acyclic if and only if a depth-first search yields no back edges. A back edge (u, v) makes v an ancestor of u, so the edge completes a cycle. Conversely, if a cycle exists, let v be its first discovered vertex and (u, v) the preceding edge: at time v.d the cycle is a path of white vertices, so by the white-path theorem u becomes a descendant of v and (u, v) is a back edge. Theorem 20.12 then shows that for every edge (u, v) of a dag, v.f < u.f: v cannot be gray, and whether it is white or black it finishes first. The book calls this a “remarkably simple and efficient algorithm.”

20.5 · strongly connected components

Reverse the arrows, search again

On a map of one-way streets, some neighbourhoods have the property that you can drive from any junction to any other and back again. That is a strongly connected component: a maximal set of vertices that are all reachable from one another. Finding them splits a directed graph into pieces that can be handled one at a time.

Two depth-first searches do it. First, run DFS on G and keep the finish times. Second, build the transpose GT: the same vertices with every arrow turned around, which has exactly the same components. Third, run DFS on GT, but start each new tree from the unvisited vertex with the largest finish time. Fourth, each tree of that second forest is one component. Everything costs Θ(V + E).

Why does the second pass stay inside one component? The vertex that finished last in pass one sits in a component that, in GT, has no arrow leading out to a component not yet visited. The search is trapped in it, so its tree is exactly that component; the next scene proves this. In Rust, the transpose is a function that takes a borrowed graph and returns a brand-new one.

Try it: press Next phase to run the first DFS and watch the finish times, the row of roots sorted by them, then the arrows flipping. Press Next phase twice more to see the second search colour each tree as it ends, or use Step to go line by line. In Rust, the memory strip shows gt filling up as a separate heap block while g stays untouched.

What the book says

A strongly connected component of a directed graph G = (V, E) is a maximal set of vertices C ⊆ V such that for every pair u, v in C, both u ⇝ v and v ⇝ u: the vertices are reachable from each other. Figure 20.9 shows an example, with each component shaded.

The algorithm uses the transpose GT = (V, ET), where ET consists of the edges of G with their directions reversed (Exercise 20.1-3). Given an adjacency-list representation, creating GT takes Θ(V + E) time. “The graphs G and G T have exactly the same strongly connected components”: u and v are reachable from each other in G if and only if they are in GT.

STRONGLY-CONNECTED-COMPONENTS(G) has four lines: call DFS(G) to compute finish times u.f; create GT; call DFS(GT), but in the main loop of DFS consider the vertices in order of decreasing u.f as computed in line 1; output the vertices of each tree in the depth-first forest formed in line 3 as a separate strongly connected component. It is a linear-time, Θ(V + E), procedure that uses two depth-first searches, one on G and one on GT.

In Figure 20.9(a), the first DFS stamps the vertices with discovery and finish times; in (b), the depth-first forest of GT has roots b, c, g and h, one for each of the four components, {a, b, e}, {c, d}, {f, g} and {h}. The machine follows that figure, using the same search order, so its numbers match. The correctness proof, through the component graph, is the subject of the next scene.

20.5 · the component graph and why the algorithm works

Squash every loop into a dot

Picture a map of towns joined by one-way roads. Towns that can all reach each other form a loop; squash each loop into a single dot and keep only the roads between dots. The map you get is the component graph, and it can never contain a loop of its own: if dot A led to dot B and B back to A, everyone in both could reach everyone, and they would have been one dot all along.

The first search stamps a finish time on every vertex. Give a component the latest finish time among its vertices, f(C). Then every road from a component C′ into another component C satisfies f(C′) > f(C). Whichever component the search enters first, it either swallows both before finishing the one it started in, or it finishes the target first because there is no way back. So sorting components by decreasing f is a topological order of the component graph.

Now the second search runs on the transpose, where every road between dots points the other way. It starts at the vertex with the largest f, in a component with no road out in the transpose except toward dots that were already visited, because those all have larger f. The search cannot leak into a new component, so each depth-first tree is exactly one component.

Try it: in Contract press Play: edges inside a loop fade, the rest merge into the five edges of the component graph, and the vertices slide together. Then pick g → c next to Add an edge: it points against the flow, so two components merge and the picture shrinks. In Order, tap an arrow to see its inequality, then press Play to run the second search in the transpose.

What the book says

A strongly connected component of a directed graph is a maximal set of vertices in which every two are reachable from each other. The procedure STRONGLY-CONNECTED-COMPONENTS calls DFS(G) for the finish times, creates the transpose GT, calls DFS(GT) with the main loop taking vertices in order of decreasing u.f, and outputs each tree of that second forest as a component. It runs in Θ(V + E) time.

The idea rests on the component graph GSCC, with one vertex per component and an edge between two components whenever G has an edge between them; Figure 20.9(c) shows it for the example. Lemma 20.13 shows that G cannot have paths u ❀ u′ and v′ ❀ v across two distinct components, which makes the component graph acyclic.

For a set U of vertices, d(U) is the earliest discovery time and f(U) the latest finish time of any vertex in it, both from the first search. Lemma 20.14: if there is an edge (u, v) with u in C′ and v in C, then f(C′) > f(C). The proof splits on which component was discovered first and uses the white-path theorem. Corollary 20.15 turns this around for the transpose: if f(C) > f(C′), then ET has no edge from C to C′.

Theorem 20.16 proves the algorithm correct by induction on the trees of the second search. The book also notes that the second search visits the vertices of GSCC in topologically sorted order. Exercise 20.5-5 asks for an O(V + E)-time algorithm for the component graph.

problem 20-1 · classifying edges by breadth-first search

No edge jumps ahead

A depth-first search dives, so an edge can lead to a deep descendant it has not met yet. A breadth-first search sweeps: first everything one step from s, then everything two steps away, wave by wave. Sort its edges the way the last section sorted depth-first ones, using the breadth-first tree that BFS built, and the sweep leaves a clear fingerprint.

An edge that discovers a white vertex is a tree edge, and it steps exactly one wave out. Any other edge points at a vertex that is already discovered. If that vertex is an ancestor of u in the tree, the edge is a back edge; otherwise it is a cross edge. A forward edge, from a vertex to a deeper descendant it did not discover, never appears: when u is dequeued, every descendant of u is still white, so the edge would simply have become a tree edge.

The queue holds only two consecutive waves, so an already-discovered v is at most one wave beyond u. That is the whole fingerprint: v.d ≤ u.d + 1 for a cross edge, v.d ≤ u.d for a back edge. In an undirected graph the reverse half of a tree edge is the same edge, which is why back edges vanish there.

Try it: press Play on the directed graph and watch each edge take a colour: mint tree, blue cross, coral back, and a forward row that stays at 0. Then tap Undirected: the same pairs now have no back edges. Finally tap two vertices to add or remove an edge, and try to build a forward edge. BFS will turn it into a tree edge or move the waves instead.

What the book says

Part (a), an undirected graph: there are no back edges and no forward edges; if (u, v) is a tree edge then v.d = u.d + 1; if it is a cross edge then v.d = u.d or v.d = u.d + 1.

Part (b), a directed graph: there are no forward edges; a tree edge has v.d = u.d + 1; a cross edge has v.d ≤ u.d + 1; a back edge has 0 ≤ v.d ≤ u.d. (Section 20.3 counts a self-loop as a back edge.)

problem 20-2 · articulation points, bridges, and biconnected components

Which single failure splits the network?

Nine offices are joined by cables. If one office loses power, can the others still talk? If one cable is cut? An articulation point is an office whose loss splits the network; a bridge is a cable whose loss does; and a biconnected component is a block of cables where any two lie on a common loop, so every link in it has a second route around.

One depth-first search finds all three. In an undirected graph it makes only tree edges and back edges, and a back edge is the only way a subtree can reach above its own root. So give each vertex a low value: the earliest discovery time reachable from its subtree through one back edge. When a child v of u comes back with v.low ≥ u.d, nothing in v's subtree reaches above u, so losing u cuts it off: u is an articulation point (the root is one only with two or more children). With the strict v.low > u.d not even the edge (u, v) has a way around, and it is a bridge.

Every time a child returns with v.low ≥ u.d, the edges pushed since (u, v) form one block: pop them. Several edges make a biconnected component; a lone edge is a bridge.

Try it: in Low-links press Play. Under each vertex is d/low; watch back edges pull low down, coral articulation points appear, bridges turn dashed, and each block of edges takes its own colour as the search returns. Then open Remove one, tap any vertex or edge, and see whether the rest falls apart. The answer always matches the low-link test.

problem 20-3 · Euler tour

Every street exactly once

A snowplough has to clear every one-way street in a town exactly once and end where it began. It may drive through the same junction many times; it may not clear any street twice. That closed route is an Euler tour of the street graph.

There is a cheap test before you start. Each time the plough drives into a junction it must drive out on a different street, so a junction needs as many streets in as out: in-degree = out-degree at every vertex. For a strongly connected graph that is also enough. Walk along unused edges until you are stuck. Because every vertex is balanced, the only place you can be stuck is where you started, so the walk is a closed cycle. If unused edges remain, some junction on that cycle still has one: start a second cycle there and splice it in.

Splicing looks expensive, but a stack does it for free. Keep one cursor per vertex pointing at its next unused edge, push the next endpoint while there is one, and pop a vertex onto the front of the tour when it has none. Each edge is touched once, so the whole thing takes O(E) time.

Try it: press Play. The first walk is blue; when it gets stuck back at a the stack unwinds to c, which still has an unused edge, and a second cycle in lilac is spliced in there. Then tap two vertices to add the edge d → e: d and e light up as unbalanced and the algorithm refuses at line 1. Add e → d as well and the tour returns.

The chapter on one page

Chapter 20 in eight cards. Each one points at the scenes that act it out.

Dots and lines

A graph G = (V, E) has vertices and edges, directed or undirected, and its size is two numbers, |V| and |E|. The adjacency lists' lengths add up to |E| for a directed graph and 2|E| for an undirected one. → 20.1 Graphs

List or grid

Adjacency lists take Θ(V + E) memory and suit sparse graphs, which is why most algorithms here assume them. An adjacency matrix takes Θ(V²) whatever the edges, suits dense graphs, and answers is (u, v) an edge? with one cell. → 20.1 List or matrix

Ripples with a queue

BFS spreads from a source in waves. A first-in, first-out queue holds the gray frontier, each vertex gets a distance d and a parent π, and every vertex and every adjacency list is touched once: O(V + E). → 20.2 BFS

d is the true distance

When BFS ends, v.d = δ(s, v), the fewest edges on any path. The π pointers form a breadth-first tree, and PRINT-PATH follows them back from v to s. The tree can change with the neighbour order; the distances cannot. → 20.2 Shortest paths

Dive, then back up

DFS goes as deep as it can along the newest vertex's edges, then backtracks. Each vertex gets a discovery time d and a finish time f, the recursion stack is the chain of gray vertices, and the result is a depth-first forest in Θ(V + E). → 20.3 DFS

Four kinds of edge

The colour of v when an edge is first explored classifies it: white, a tree edge; gray, a back edge; black, a forward or cross edge. Intervals [d, f] nest or are disjoint (the parenthesis theorem), and an undirected graph only ever gets tree and back edges. → 20.3 Edge types

Order, then clusters

A directed graph is acyclic exactly when DFS finds no back edge, and listing vertices by decreasing finish time topologically sorts it. Two DFS passes, the second on the transpose in that order, split a graph into strongly connected components, and the component graph is a dag. → 20.4 Topological sort, 20.5 SCCs, 20.5 Component graph

The problems

BFS edges are only tree, back and cross, with d never jumping by more than one across a tree or cross edge. DFS low-links find articulation points, bridges and biconnected components. A strongly connected graph has an Euler tour when in-degree = out-degree at every vertex. → 20-1 BFS edges, 20-2 Articulation points, 20-3 Euler tour

Words to know

The book's words from this chapter, in plain language.

graph G = (V, E)
A set of vertices and a set of edges, each edge a pair of vertices. In pseudocode they are the attributes G.V and G.E.
directed / undirected
In a directed graph the edge (u, v) goes from u to v; in an undirected graph (u, v) and (v, u) are the same edge.
|V| and |E|; V and E in O-notation
The two numbers that measure a graph's size. Inside asymptotic notation, and only there, V means |V| and E means |E|.
path, reachable
A route along edges. t is reachable from s if some path leads from s to t.
adjacency list
An array Adj with one list per vertex: Adj[u] holds every v with (u, v) ∈ E. Memory Θ(V + E).
adjacency matrix
A |V| × |V| grid with 1 in row i, column j when (i, j) ∈ E, else 0. Memory Θ(V²).
sparse / dense
Sparse: |E| is much less than |V|². Dense: |E| is close to |V|².
breadth-first search
Explores from a source in waves: all vertices at distance 1, then 2, then 3. It works on directed and undirected graphs.
white, gray, black
Not discovered yet; discovered and on the frontier; finished, with every neighbour looked at.
frontier
The boundary between discovered and undiscovered vertices. In BFS the queue holds exactly the gray vertices.
v.d and v.π
In BFS, the distance from the source and the parent that discovered v (NIL if none). In DFS, v.d is the discovery time.
shortest-path distance δ(s, v)
The fewest edges on any path from s to v, or ∞ if there is none. BFS computes it exactly.
breadth-first tree
The edges (v.π, v) BFS leaves behind. Its unique path from the root to each vertex is a shortest path.
depth-first search
Explores from the most recently discovered vertex that still has unexplored edges, and backtracks when none is left. It restarts from a new source until every vertex is found.
discovery and finish time
v.d and v.f: the moments DFS first meets v and finishes its adjacency list. Integers from 1 to 2|V|, with v.d < v.f.
depth-first forest
The trees DFS builds, one per restart. Every vertex lands in exactly one tree.
parenthesis theorem
For any two vertices the intervals [d, f] are disjoint or one lies inside the other, and nesting means descendant.
tree, back, forward, cross edge
The four kinds of edge in a depth-first forest: to a newly found child, up to an ancestor, down to a proper descendant, and everything else.
dag
A directed acyclic graph. A directed graph is a dag exactly when DFS yields no back edges.
topological sort
An ordering of a dag's vertices along a line so that every edge goes from left to right. Reverse finish order does it.
strongly connected component
A maximal set of vertices in which every vertex can reach every other.
transpose GT
G with every edge reversed. It has the same strongly connected components and takes Θ(V + E) to build from adjacency lists.
component graph
One vertex per strongly connected component, with an edge when some edge of G runs between the two. It is always acyclic.
articulation point, bridge
A vertex, or an edge, whose removal disconnects a connected undirected graph.
Euler tour
A cycle through a strongly connected directed graph that uses every edge exactly once, possibly visiting a vertex more than once.

Rust words from the code panels

For readers coming from another language. Each one shows up in a listing above.

Vec<Vec<usize>>
An adjacency list: the outer Vec has one slot per vertex, and each slot owns its own inner Vec of neighbour indices, so rows can have different lengths. vec![vec![false; n]; n] clones the inner Vec to make a matrix.
VecDeque
A double-ended queue. push_back and pop_front are O(1) because the buffer is a ring and only a head index moves. with_capacity(n) reserves room up front.
Option as ∞ and NIL
Option<u32> for a distance and Option<usize> for a parent: None means not reached yet or no parent, and the compiler forces you to handle it.
enum with derive

for &v in &adj[u]
Borrow the list and loop over references; the pattern &v copies each index out, so v is a plain usize and the borrow stays short.
&mut out-parameter
A recursive function that fills one buffer takes &mut Vec<usize> and passes it down. Every stack frame writes into the same heap buffer, so nothing is copied.
state struct, &mut self, lifetimes
A Dfs struct holds the colours, times and parents, and visit(&mut self, …) changes them. The graph is a separate shared borrow; struct Dfs<'a> with adj: &'a [Vec<usize>] says the borrowed graph must outlive the search.

HashSet::insert
Returns false when the value was already there, which is how an undirected edge, stored as (u.min(v), u.max(v)), is classified only once.
tuples and const arrays
An edge is a (usize, usize); a const array of them is the edge list, and for &(u, v) in edges splits each pair as it loops.
transpose with iter().enumerate() and .rev()
Building GT loops over every (u, list) pair and pushes u into gt[v]. The second search walks the finish order .rev()erse, with no copy of the Vec.
sort_by_key, Reverse, BTreeMap
