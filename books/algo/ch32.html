The chapter in five stops

Each stop asks the same question: what do you already know, so that you don't have to look again?

  1. The plain waySlide the word along the text, one column at a time, and check the letters. It works. On a text of all a's it does a huge amount of repeat work.
  2. Turn letters into a numberRead each window of the text as one number. Moving the window one column takes three quick sums. Only windows whose number fits get a letter check.
  3. A machine that remembersBuild a small machine from the word. It reads each letter once and always knows how much of the word has just gone by.
  4. The word overlaps itselfAfter a mismatch, the part you matched tells you where the word can land next. A short table, built by sliding the word along itself, gives the jump.
  5. Sort every endingList all the endings of the text in dictionary order. Then one binary search finds a word, and neighbours in the list reveal the longest repeat.

32 · the string-matching problem

Find a word inside a text

Slide a short word along a long text, and report every place where all its letters line up.

Here is a text of 13 letters: abcabaabcabac. You want to find the pattern abaa. Picture the pattern on a strip of paper under the text. You can slide the strip right, one column at a time.

How far you have slid it is called the shift. At shift 0 the strip starts under the first text letter. At shift 3 it starts under the fourth. A shift where every letter agrees is a valid shift. The whole problem is this: list all the valid shifts.

Read the maths
T[s + j] = P[j], for j = 1, 2, …, m
T, P
The text and the pattern, as arrays numbered from 1.
n, m
Their lengths. So there are n − m + 1 shifts to consider, from 0 to n − m.
s
The shift being tested.
j
Which letter of the pattern you are looking at.

With numbers: take s = 3. For j = 1 this asks if T[4] = P[1]. Both are a. For j = 4 it asks if T[7] = P[4]. Both are a. All four agree, so 3 is a valid shift.

Try it: press Next and watch the strip glide along. Green letters agree with the text above, and red ones don't. The row of numbers underneath remembers which shifts worked. Then pick the pattern aba, which fits in two places.

What the book says

The text is an array T[1 : n] and the pattern an array P[1 : m] with m ≤ n, with elements drawn from a finite alphabet Σ. Pattern P occurs with shift s in T (equivalently, beginning at position s + 1) if 0 ≤ s ≤ n − m and T[s + 1 : s + m] = P[1 : m]. Such an s is a valid shift, and otherwise it is an invalid shift. The problem is to find all valid shifts.

Figure 32.1 uses P = abaa and T = abcabaabcabac, where the only valid shift is s = 3. Every algorithm in the chapter except the naive one preprocesses the pattern and then does the matching; the total running time is the sum of the two. The table at the end of this page gives both times for all five algorithms.

The book states this as a definition rather than as numbered pseudocode. The listing below writes the definition out as a procedure. It checks every letter so that the picture can colour them all; section 32.1 stops at the first mismatch.

32 · notation and terminology

Beginnings and endings

A word's beginnings and its endings are the two kinds of piece this whole chapter is built on.

Take the word abcca. Its first two letters, ab, are a prefix. Its last three letters, cca, are a suffix. The word with no letters at all, the empty string, counts as both. A proper prefix or proper suffix is one that is shorter than the whole word.

One fact gets used again and again. Suppose two strings are both suffixes of the same word. They end in the same place, so the shorter one sits inside the end of the longer one. It is a suffix of it. Line them up by their right edges and you can see it.

Read the maths
w ⊏ x   w ⊐ x   P[:k]   T[:i]
w ⊏ x
w is a prefix of x. The open side faces the longer string.
w ⊐ x
w is a suffix of x.
P[:k]
The first k letters of the pattern. P[:0] is the empty string, written ε.
T[:i]
The first i letters of the text.

With numbers: ab ⊏ abcca and cca ⊐ abcca. If P = ababaca, then P[:3] = aba.

Try it: step through Prefixes and Suffixes. Then pick Two suffixes and change their lengths with the sliders. The shorter one always lands inside the longer one.

What the book says

Σ* is the set of all finite-length strings over the alphabet, and it includes the 0-length empty string ε. |x| is the length of x, and xy is the concatenation of x and y. A string w is a prefix of x, written w ⊏ x, if x = wy for some string y; w is a suffix of x, written w ⊐ x, if x = yw for some y. A proper prefix or proper suffix also has |w| < |x|. Both relations are transitive, and x ⊐ y if and only if xa ⊐ ya.

Lemma 32.1, the overlapping-suffix lemma: suppose x ⊐ z and y ⊐ z. If |x| ≤ |y|, then x ⊐ y. If |x| ≥ |y|, then y ⊐ x. If |x| = |y|, then x = y. Figure 32.2 proves it with a picture of the three cases.

The book states these as definitions. The listing writes them as two short procedures.

32.1 · the naive string-matching algorithm

Try every shift, and forget

The plain way tries every position from scratch, so it keeps rereading letters it has already seen.

Search for aab in acaabc. Put the pattern at shift 0 and compare letters from the left. a matches a. a against c fails, so stop and slide one column. Keep going until the strip runs out of text. This is the naive matcher, and it needs no preparation at all.

The trouble is how much it repeats. Search for aaa in a text of nothing but a's. Every shift is valid, and each one costs all 3 comparisons, even though the last shift already told you most of the letters.

Read the maths
worst case = (n − m + 1) × m comparisons
n − m + 1
How many shifts there are.
m
The most comparisons one shift can take: every pattern letter.

With numbers: for n = 10 and m = 5 there are 6 shifts of 5 comparisons, so 6 × 5 = 30. A text of 1,000 letters and a pattern of 500 needs 501 × 500 = 250,500.

Why it is wasteful: it uses nothing it learned at one shift when it moves to the next. Pick It forgets: after finding aaab at shift 0, you know text letter 4 is b. So shifts 1, 2 and 3 can't work, yet the naive matcher tries them all.

Try it: start with the book's example. Then pick All a's and drag both sliders: the red bar fills to its limit. Each step compares one pair of letters, and the arrow marks the text letter being read.

What the book says

NAIVE-STRING-MATCHER finds all valid shifts by checking the condition P[1 : m] = T[s + 1 : s + m] for each of the n − m + 1 possible values of s. The book pictures this as sliding a template containing the pattern over the text. The test on line 2 implicitly loops over the character positions until all match or a mismatch is found.

It takes O((n − m + 1)m) time, and the bound is tight: on the text an and pattern am, the implicit loop runs m times for each shift. That is Θ(n2) if m = ⌊n/2⌋. It needs no preprocessing, so its running time equals its matching time.

Figure 32.3 uses P = aab and T = acaabc, with the one occurrence at shift s = 2. The book calls the procedure inefficient because it entirely ignores information gained about the text for one value of s when it considers other values of s. Its example: if P = aaab and s = 0 is valid, then none of the shifts 1, 2, or 3 are valid, since T[4] = b. Exercise 32.1-3 shows that on randomly chosen strings it is quite efficient, at no more than 2(n − m + 1) expected comparisons.

Numbers on a clock

A remainder keeps a huge number small, and two numbers with different remainders can't be the same number.

Think of a clock with 13 marks, numbered 0 to 12. Count 31 ticks around it. You pass 0 twice, and you stop on 5. So the remainder of 31 divided by 13 is 5. The number you divide by, here 13, is the modulus.

This has two uses in the next scene. First, you never need the giant number. Going digit by digit, you can wrap around after each digit, and the answer comes out the same. Second, it gives a fast "no". If two numbers stop on different marks, they are different. If they stop on the same mark, they may or may not be equal.

Read the maths
a mod q    a ≡ b (mod q)
a mod q
The remainder when a is divided by q. It is always from 0 to q − 1.
a ≡ b (mod q)
a and b have the same remainder. They stop on the same mark.

With numbers: 31415 = 13 × 2416 + 7, so 31415 mod 13 = 7. And 67399 = 13 × 5184 + 7, so 67399 ≡ 31415 (mod 13), though they are different numbers.

Why wrapping early is safe: what you drop is a whole number of 13s. Multiply that by 10 and it is still a whole number of 13s, so it can't change the final remainder.

Try it: in Wrap around, drag the number and the size of the clock. In Digit by digit, watch 31415 reach 7 without any number going above 129. Two numbers shows one mark shared by different numbers.

What the book says

This scene is a warm-up, added to this page. Section 32.2 uses the equivalence of two numbers modulo a third number and points to Section 31.1 for the definitions. The digit-by-digit computation is Horner's rule, which the book uses to compute p in Θ(m) time, reducing modulo q as it goes.

The two uses are the book's too: ts ≡ p (mod q) does not automatically mean that ts = p, but if ts ≢ p (mod q), then you definitely know that ts ≠ p.

32.2 · the rabin-karp algorithm

Read the window as a number

If the letters are digits, a stretch of text is a number, and moving along one place takes only three quick sums.

Say the text is all digits, and the pattern is 31415. Call the five digits above the strip the window, and read them as one number. Now you can compare two whole numbers instead of five letters.

The clever part is moving on. The next window, 14152, shares four digits with 31415. So don't start again. Take off the 3 at the front, push everything one place left, and add the 2 at the end. That is one subtraction, one multiplication and one addition, however long the window is.

Read the maths
t′ = 10 × (t − 10m−1 × old) + new
t
The number in the window now. The book writes ts for shift s.
t′
The number in the window one column later. The book writes ts+1.
old
The digit leaving on the left, T[s + 1].
new
The digit arriving on the right, T[s + m + 1].
10m−1
What a 1 is worth in the window's first place. For m = 5, that is 10,000.

With numbers: 10 × (31415 − 10000 × 3) + 2 = 10 × 1415 + 2 = 14152.

Try it: One roll, slowly shows each of the three sums, with the digits gliding left when you multiply by 10. Then pick All the windows and raise m: recomputing gets more expensive, and rolling stays at 3 sums per move.

What the book says

The book assumes for exposition that Σ = {0, 1, 2, …, 9}, so a string of k consecutive characters represents a length-k decimal number. For a pattern P[1 : m], p is its decimal value, and ts is the decimal value of the length-m substring T[s + 1 : s + m], for s = 0, 1, …, n − m. Then s is a valid shift if and only if ts = p.

p and t0 take Θ(m) time by Horner's rule. Equation (32.1) gives each later value in constant time: ts+1 = 10(ts − 10m−1T[s + 1]) + T[s + m + 1]. Precomputing 10m−1 takes O(lg m) time with the techniques of Section 31.6, though an O(m) method suffices here. So all of t0, t1, …, tn−m take Θ(n − m + 1) time. For now the book sets aside how large p and ts can get.

The book states this as an equation. The listing writes it as a short procedure.

32.2 · the rabin-karp algorithm, with a modulus

A fast no, and a slow yes

Compare remainders first: different means no match, and equal means you must still check the letters.

Real windows make numbers far too large for one computer word. So keep only the remainder, modulo a prime q such as 13. The pattern 31415 has remainder 7. Now roll along the text and ask one question per window: is its remainder 7?

If not, the window can't be the pattern, and you didn't read a single letter. If so, that is a hit, and now you check the letters. You have to, because different numbers can share a remainder. In the book's example, 67399 also has remainder 7. A hit like that, with different letters, is a spurious hit.

Read the maths
t′ = (d × (t − old × h) + new) mod q
d
The radix, meaning how many different digits there are. It is 10 for decimal digits.
q
The modulus, a prime.
h
dm−1 mod q, what a 1 is worth in the window's first place, after wrapping.
t, old, new
As before: the window's value, the digit leaving, the digit arriving.

With numbers: for m = 5 and q = 13, h = 10000 mod 13 = 3. From window value 7, old digit 3, new digit 2: 10 × (7 − 3 × 3) + 2 = −18, and −18 mod 13 = 8. Indeed 14152 mod 13 = 8. A negative number wraps too: −18 + 26 = 8.

How long it takes, on an ordinary text
O(n) + O(m (v + n/q))
v
The number of valid shifts. Each one costs m letter checks.
n/q
About how many spurious hits to expect: n windows, each a 1 in q chance.

With numbers: a text of 1,000,000 letters with q = 1,000,003 expects about 1 spurious hit. If q is larger than m and v is small, the matching time is O(n).

Why it can't miss a match: a real occurrence has the same digits as the pattern, so it has the same number and the same remainder. It always gets a hit. Remainders only cause extra checks, never wrong answers.

Try it: run the book's digits with q = 13, then choose q = 3 and count the red hits. All the same digit shows the worst case: every window is real, so all the letter checks happen anyway.

What the book says

With a d-ary alphabet, choose q so that dq fits within a computer word, and compute modulo q with equation (32.2), where h = dm−1 mod q is the value of the digit 1 in the high-order position of an m-digit text window. In Figure 32.4, the text 2359023141526739921 is searched for P = 31415 modulo 13. The book finds two windows with value 7: the one beginning at text position 7 is an occurrence, and the one beginning at text position 13 is a spurious hit.

The test ts ≡ p (mod q) acts as a fast heuristic test to rule out invalid shifts. RABIN-KARP-MATCHER takes Θ(m) preprocessing time. Its matching time is Θ((n − m + 1)m) in the worst case, since like the naive algorithm it explicitly verifies every valid shift: on P = am and T = an, each of the n − m + 1 possible shifts is valid.

The book's heuristic analysis assumes that reducing values modulo q acts like a random mapping. The expected number of spurious hits is then O(n/q), and the expected matching time is O(n) + O(m(v + n/q)), where v is the number of valid shifts. That is O(n) if v = O(1) and q ≥ m. The method also generalizes to other pattern-matching problems, such as two-dimensional pattern matching.

32.3 · finite automata

A machine with one number for a memory

A small machine reads one letter at a time, and a table tells it what to remember next.

Think of a turnstile. It doesn't remember who came through yesterday. It only knows whether it is locked or unlocked now, and each coin or push moves it to another position. A finite automaton works the same way. It has a few states, numbered, and it is always in exactly one.

Here is one with two states. It starts in state 0. Reading a in state 0 moves it to state 1. Everything else moves it to state 0, or leaves it there. A table holds these moves, the transition function. State 1 is the accepting state: if the input ends there, the machine says yes. This little one says yes exactly when the input ends in an odd number of a's.

Read the maths
q → δ(q, a)
q
The state the machine is in.
a
The letter it just read.
δ
The Greek letter delta. It names the table: row q, column a.

With numbers: δ(0, a) = 1, so in state 0, reading a takes you to state 1. δ(1, b) = 0, so in state 1, reading b takes you back to state 0.

Try it: pick an input and press Next. The lit arrow and the lit table cell are the same fact drawn twice. The double ring marks the accepting state. See whether you can predict the result of abaaa before you get there.

What the book says

A finite automaton M is a 5-tuple (Q, q0, A, Σ, δ): a finite set of states Q, a start state q0, a distinguished set of accepting states A, a finite input alphabet Σ, and a transition function δ from Q × Σ into Q. If the automaton is in state q and reads character a, it moves from state q to state δ(q, a). Whenever its current state is in A, the machine has accepted the string read so far.

M induces a final-state function φ from Σ* to Q, where φ(w) is the state M ends up in after reading w. So M accepts w if and only if φ(w) ∈ A. Recursively, φ(ε) = q0 and φ(wa) = δ(φ(w), a).

Figure 32.5's automaton accepts those strings that end in an odd number of a's. On abaaa it enters the sequence of states ⟨0, 1, 0, 1, 0, 1⟩ and accepts. On abbaa it enters ⟨0, 1, 0, 0, 1, 0⟩ and rejects. The book describes the run in words; the listing writes it as a procedure.

32.3 · string-matching automata: the suffix function

The longest start of the pattern that ends here

As you read a text, keep one number: how much of the pattern's beginning has just gone by.

You are looking for ababaca, and you have read ababab so far. Stand at the last letter you read. How long a beginning of the pattern ends exactly here? The whole of ababab doesn't fit, because the pattern's first six letters are ababac. But abab does: the last four letters you read are abab. So the number is 4.

That number is called the suffix function. Don't worry about the name. It only means: the longest prefix of the pattern that ends here. If it ever reaches the pattern's full length, you have just read the whole pattern.

Read the maths
σ(x) = max { k : P[:k] ⊐ x }
σ(x)
Sigma of x: the number we want, for the string x read so far.
P[:k]
The first k letters of the pattern.
⊐ x
"is a suffix of x", meaning those letters end x.
max
Take the largest k that works. k = 0 always works, because the empty string ends everything.

With numbers: for P = ab, σ(ε) = 0, σ(ccaca) = 1 and σ(ccab) = 2.

Why one number is enough: the only part of your past that can still become a match is the part that is a beginning of the pattern. The longest such piece contains all the shorter ones, so nothing else needs to be remembered.

Try it: press Next and read the book's text one letter at a time. The green row is the longest start of the pattern that ends at the arrow. Watch step 7: it shrinks from 5 letters to 4, and it glides two columns to the right.

What the book says

The suffix function σ corresponding to P maps Σ* to {0, 1, …, m}, where σ(x) is the length of the longest prefix of P that is also a suffix of x. It is well defined since the empty string P[:0] = ε is a suffix of every string. For a pattern of length m, σ(x) = m if and only if P ⊐ x.

The book's examples use the pattern ab: σ(ε) = 0, σ(ccaca) = 1, and σ(ccab) = 2. Figure 32.6(c) runs P = ababaca on T = abababacaba, and the states it shows after each letter are exactly the σ values here. The book states σ as a formula; the listing writes it as a procedure.

Lemma 32.2 (suffix-function inequality): σ(xa) ≤ σ(x) + 1. Lemma 32.3 (suffix-function recursion): if q = σ(x), then σ(xa) = σ(P[:q]a). So reading one more letter can only depend on the current prefix and that letter. Theorem 32.4 then shows the automaton's state always equals σ of the text read so far.

32.3 · string-matching automata

Build the machine from the pattern

Give the machine one state per letter matched, and it finds the pattern by reading each text letter exactly once.

Turn that number into a machine. State 3 means "the last 3 letters I read are the pattern's first 3". The states line up in a row called the spine. If the next letter continues the pattern, move one state right along the spine. Reaching the last state means the whole pattern has just gone by.

If the letter doesn't continue the pattern, you don't start from zero. Say you are in state 5, having read ababa, and b comes next. The last 4 letters are now abab, so you go to state 4. The arrow from 5 to 4 says exactly that. Arrows that go back to state 0 are left out of the picture to keep it clean, but the table has them.

Read the maths
δ(q, a) = σ(P[:q] a)
P[:q] a
The first q letters of the pattern, then the letter a just read.
σ( )
The longest start of the pattern that ends there.

With numbers: δ(5, b) = σ(ababab) = 4. And δ(5, c) = σ(ababac) = 6, one step along the spine.

Why the table only needs the pattern: in state q, you know the last q text letters: they are P[:q]. So the longest start that ends after the next letter can be worked out from the pattern alone, ahead of time, before seeing any text.

Try it: press Next to feed in the book's text. Then change the pattern with the buttons, or type your own using a, b and c. Try aaab and watch state 3 loop on itself while more a's come in. The table sits under the states, so each column belongs to the state above it.

What the book says

The string-matching automaton for P[1 : m] has state set {0, 1, …, m}, start state 0, and state m as its only accepting state. Its transition function is δ(q, a) = σ(P[:q]a), equation (32.4). The state number q gives the length of the longest prefix of P that matches the most recently seen text characters, so reaching state m means the m most recently seen text characters match the entire pattern.

If a = P[q + 1], the character continues to match and the transition goes along the spine: δ(q, a) = q + 1. Otherwise the book finds the longest prefix of P that is also a suffix of T[:i]a, which has length at most q. In state 5 of Figure 32.6, reading c gives δ(5, c) = 6, and reading b gives δ(5, b) = 4.

The book's table has states as rows; here it is turned on its side so each column stands under its state. Figure 32.6 leaves out edges that lead to state 0, by convention. 32.3 · computing the transition function

Filling the table the slow way

To fill one cell, line up shorter and shorter starts of the pattern until one fits at the end.

Take one cell: state 5, letter b. The string in question is ababa then b, so ababab. Could the longest start of the pattern be 6 letters? That is ababac, and it doesn't end in the same way. Try 5 letters: ababa. No. Try 4: abab. Yes. So the cell holds 4.

Every cell gets this treatment. The pattern is being matched against itself, which is why the table can be built before seeing any text. It works, but it is slow, and a big alphabet means many more cells. That cost is the reason for the next section.

Read the maths
O(m³ |Σ|)
m |Σ|
The number of cells, roughly: one per state and letter. |Σ| is the size of the alphabet.
m
How many values of k each cell may try.
m
How many letters each try may compare.

With numbers: m = 7 and |Σ| = 3 gives 8 × 3 = 24 cells. The bound multiplies that by up to 7 × 7, though this pattern needs far fewer, as the counter shows.

Try it: press Next for the book's cell, state 5 and letter b. Then change the letter to c for a step along the spine, and to a for a long fall back to state 1. Drag q to fill other cells.

What the book says

COMPUTE-TRANSITION-FUNCTION computes δ directly from equation (32.4). The nested loops consider all states q and all characters a, and lines 3–6 set δ(q, a) to the largest k such that P[:k] ⊐ P[:q]a. It starts with the largest conceivable k, which is q + 1, unless q = m, in which case k cannot be larger than m. It then decreases k until P[:k] is a suffix of P[:q]a, which must eventually occur, since P[:0] = ε is a suffix of every string.

The running time is O(m³|Σ|): the outer loops contribute a factor of m|Σ|, the inner while loop can run at most m + 1 times, and the test on line 4 can compare up to m characters. Much faster procedures exist. Using information computed about the pattern (Exercise 32.4-8), the time improves to O(m|Σ|), and that gives O(m|Σ|) preprocessing with Θ(n) matching.

32.4 · the knuth-morris-pratt algorithm

After a mismatch, how much can you keep?

When a match breaks, the letters you matched are the pattern's own letters, so you can work out the next move without rereading the text.

You are searching for ababaca. Five letters have matched, ababa, and the sixth fails. The naive matcher now slides one column and rereads. But stop for a moment. You know what those five text letters are. They are the pattern's own first five letters.

So you can test shifts in your head, with the text covered up. Slide by 1, and the pattern's a would sit on a b. Impossible. Slide by 2, and aba sits on aba. That could work, and those 3 letters already match, so you never need to compare them again. Of two shifts that could work, take the smaller one, because the larger one could jump past a real match.

Read the maths
s′ = s + (q − k)
s
The shift where the mismatch happened.
q
How many letters had matched.
k
How many of those letters you can keep: the largest overlap, shorter than q.
s′
The next shift worth trying.

With numbers: s = 4, q = 5, k = 3, so s′ = 4 + (5 − 3) = 6. The 3 letters already known to match are not compared again.

Try it: in Work it out, watch the text get covered, so only the known letters show. The pattern tries each shift against just those. Then pick The naive way to see how many comparisons the same move costs when you reread.

What the book says

The Knuth-Morris-Pratt algorithm avoids computing the transition function altogether. It uses an auxiliary function π, precomputed from the pattern in Θ(m) time and stored in an array π[1 : m], which encapsulates knowledge about how the pattern matches against shifts of itself.

In Figure 32.9(a), q = 5 characters of P = ababaca have matched at shift s, and the 6th fails. Shift s + 1 is necessarily invalid. Shift s′ = s + 2, in part (b), is potentially valid, with P[:3] aligned with the text seen so far. Shift s + 4, in part (c), is also potentially valid, leaving only P[:1] aligned. If more than one shift amount works, you should choose the smallest shift amount so that you do not miss any potential matches.

The question is the least shift s′ > s such that, for some k < q, P[1 : k] = T[s′ + 1 : s′ + k], where s′ + k = s + q. Finding the smallest shift is the same as finding the longest prefix length k. Since those text characters are part of the matched portion, the question can be asked of the pattern alone: the greatest k < q such that P[:k] ⊐ P[:q]. The array stores k rather than the amount s′ − s to shift by. The book's T is partly drawn in the figure; the letters here are read from it. Thinking with the text covered
32.4 · the prefix function for a pattern

Slide the pattern along itself

Put a second copy of the pattern under the first and slide it right: the first place the letters agree gives the number you keep.

Write out the first five letters, ababa. Put a copy of the pattern underneath, and slide it right one column at a time. Look only where the two overlap, up to the line. After 1 column, the copy's a sits on b. No good. After 2 columns, the copy's aba sits on aba. They agree! The overlap is 3 letters long.

That 3 answers the question: after a mismatch, how much of what I matched can I keep? Do this for every length, and write the answers in a row. That row is the prefix function, π. For ababaca it is 0, 0, 1, 2, 3, 0, 1. These are not numbers to memorize. Each one is an overlap you can see.

Read the maths
π[q] = max { k : k < q and P[:k] ⊐ P[:q] }
π[q]
Pi of q: the overlap for the pattern's first q letters.
P[:k] ⊐ P[:q]
The first k letters are also the last k of those q letters. That is what "the copy agrees" means.
k < q
The copy must really move. Sitting exactly on top would agree on everything and tell you nothing.

With numbers: π[5] = 3, because the first 3 letters of ababa are aba, and so are its last 3. No longer overlap works, since k = 4 would need abab to equal baba.

Why the first agreement wins: a smaller slide leaves a longer overlap, so the first agreement is the longest one. Why does it matter? Any slide you skip might have been a real match, so you may never jump past one that agrees.

A common mix-up: π[q] is how many letters you keep, not how far you jump. The jump is q − π[q]. With q = 5 and π[5] = 3, you keep 3 and slide 2.

Try it: in Slide one copy, watch the copy move and drag q. Then Whole array builds all the numbers, one per picture. Fallback list shows every overlap at once, and how following the array from one number to the next visits them all.

What the book says

The prefix function for P[1 : m] is π : {1, 2, …, m} → {0, 1, …, m − 1}, with π[q] = max {k : k < q and P[:k] ⊐ P[:q]}. That is, π[q] is the length of the longest prefix of P that is a proper suffix of P[:q]. For ababaca, the book's values are 0, 0, 1, 2, 3, 0, 1. Figure 32.9(d) compares the pattern with itself to find π[5] = 3.

Iterating gives π*[q] = {π[q], π(2)[q], π(3)[q], …, π(t)[q]}, stopping when π(t)[q] = 0. Lemma 32.5, the prefix-function iteration lemma, says that π*[q] = {k : k < q and P[:k] ⊐ P[:q]}. So following the array lists every overlap, longest first. Figure 32.10 slides the template for q = 5 and finds matches at k = 3, 1, and 0, so π*[5] = {3, 1, 0}.

The book defines π by this formula; the listing writes the definition as a procedure. The fast way to compute π is the next scene. The other patterns on the buttons are this page's own examples.

32.4 · running-time analysis and correctness of the prefix-function computation

Build the numbers without sliding from scratch

Each new number starts from the last one, and a fall back can never exceed the climbing that came before.

Sliding a copy for every length repeats a lot of work. Here is the shortcut. Suppose the first 4 letters of the pattern overlap by k = 2. To get the answer for 5 letters, you only need to check one letter: does the next letter of the copy equal letter 5? If so, the overlap grows to 3.

If not, the copy has to slide. But you don't try every slide. The array you have already built says where the next overlap is: k becomes π[k]. So the pattern's own early answers speed up its later ones. This procedure is the matcher's search, run on the pattern against itself.

Read the maths
total falls of k ≤ total rises of k ≤ m − 1
k
The current overlap length. It starts at 0 and is never negative.
rise
k = k + 1 happens at most once for each of the m − 1 letters from 2 to m.
fall
k = π[k] always makes k smaller, because π[k] < k.

With numbers: for ababaca, m − 1 = 6. k rises 4 times and falls 2 times. There can't be more falls than rises, so the whole loop is at most about 2m steps.

Why some single steps are slow, yet the total is fast: one letter may cause several falls in a row. But each fall uses up a rise that already happened, like spending coins you saved one at a time. This way of counting the whole run, rather than one step, is an aggregate analysis.

Why falling to π[k] misses nothing: any overlap for q letters, minus its last letter, is an overlap for q − 1 letters. Those are exactly the numbers you get by following the array from the last answer. So the longest one whose next letter fits is the right answer.

Try it: press Next and watch the two bars. The falls bar can never pass the rises bar. Try aabaaab, then aaaabaaa, where one letter causes three falls in a row.

What the book says

The running time of COMPUTE-PREFIX-FUNCTION is Θ(m), shown with the aggregate method of amortized analysis. Line 3 starts k at 0, and the only way k increases is by line 8, at most once per iteration of the for loop, so the total increase is at most m − 1. Since π[q] < q for all q, each iteration of the while loop decreases k, and k never becomes negative. So the while loop iterates at most m − 1 times in all.

For correctness, Lemma 32.6 says that if π[q] > 0, then π[q] − 1 ∈ π*[q − 1]. With Eq−1 = {k ∈ π*[q − 1] : P[k + 1] = P[q]}, Corollary 32.7 says π[q] = 0 if Eq−1 is empty, and otherwise π[q] = 1 + max Eq−1. At the start of each iteration k = π[q − 1], and the while loop searches π*[q − 1] in decreasing order, so lines 7–9 set π[q] correctly.

The pattern searching itself
32.4 · the knuth-morris-pratt matcher and its correctness

The text pointer never goes back

On a mismatch the pattern jumps right using the table, and the text letter being read stays where it is.

Now use the numbers. Keep a count q of how many letters have matched. Read a text letter. If it equals the next pattern letter, add one to q and read on. If it doesn't, don't move in the text. Set q to π[q], which slides the pattern right, and try the same text letter again.

Each slide keeps a shorter overlap. Eventually the letter fits, or q reaches 0 and that text letter is given up on. After a full match, one more slide, to π[m], lets you find an occurrence that overlaps the one you just found.

Read the maths
q = π[q]
q
How many pattern letters currently match, ending just before the text letter being read.
π[q]
How many you can keep after a mismatch. The pattern slides right by q − π[q].

With numbers: with q = 5, text letter a and pattern ababaca, the fallback goes 5 → 3 → 1 → 0, testing c, b and b. Each fails. At q = 0 the first letter, a, matches, so q = 1. That is the book's δ(5, a) = 1.

Why it is the automaton in disguise: at every text letter, q is the same number the automaton's state would be. The automaton stores all the answers in a table. KMP stores only π, with m entries instead of about m|Σ|, and works out each answer when it needs one.

Try it: press Next and follow the arrow above the text. It only ever moves right. In Three falls it stays put while the pattern takes three jumps. In Overlapping, the two occurrences of aba share a letter, and KMP finds both.

What the book says

KMP-MATCHER calls COMPUTE-PREFIX-FUNCTION in line 1 and then scans the text from left to right. The book's example: in state q = 5 of Figure 32.6, reading c moves to δ(5, c) = 6. Reading b, line 5 runs once to reach q′ = π[5] = 3, and P[4] = b, so the new state is 4. Reading a, the test in line 4 comes up true three times, going through π[5] = 3, π[3] = 1, and π[1] = 0, and then line 7 moves to 1 = δ(5, a).

The while loop iterates through the states in π*[q] in decreasing order. So q is the same in the i th iteration of both KMP-MATCHER and FINITE-AUTOMATON-MATCHER, tested at line 8 and line 4 respectively, and KMP-MATCHER's correctness follows from the automaton's. Line 10 is necessary, because otherwise line 4 might try to reference P[m + 1] after finding an occurrence.

Compared with FINITE-AUTOMATON-MATCHER, using π rather than δ reduces the preprocessing time from O(m|Σ|) to Θ(m), while keeping the matching time bounded by Θ(n). 32.4 · running time of the matcher

The same text, searched twice

The plain way can compare text length times word length letters, while this one never compares more than twice the text length.

Put them side by side on the same text. Each step gives both of them one comparison. On a friendly text they run close. On a text of nearly all a's the naive matcher falls far behind. At each shift it rereads letters that KMP still has in its head.

The reason KMP is fast fits in two sentences. Every comparison that succeeds moves the arrow in the text one letter right, and that can happen at most n times. Every comparison that fails moves the pattern right, and that can happen at most n times too.

Read the maths
KMP comparisons ≤ 2n    naive ≤ (n − m + 1) m
n
The text's length. It limits how far the arrow, and the pattern, can travel.
m
The pattern's length. It appears in KMP's total only for building π, which costs Θ(m).

With numbers: take a text of 2,000 a's and a pattern of 31 a's and then a b. Every shift costs the naive matcher 32 comparisons: 1,969 shifts × 32 = 63,008. KMP uses fewer than 4,000.

Why a slow moment doesn't spoil the total: a single text letter can cause several comparisons in a row. But each extra one moved the pattern right, and the pattern never comes back. The total is what counts, and the total stays at most 2n.

32.5 · suffix arrays

Sort every ending of the text

Write down every ending of a text, sort them like a dictionary, and keep only the list of where each one starts.

Take the word ratatat. It has 7 endings: ratatat, atatat, tatat, atat, tat, at, t. Sort them into dictionary order, also called lexicographic order. A word comes before any longer word that starts the same way, so at comes before atat.

Storing all those copies would waste space, because each ending is just a position in the text. So keep only the start positions, in sorted order: 6, 4, 2, 1, 7, 5, 3. That list is the suffix array. Its partner, the rank array, answers the opposite question: given a start position, where does it sit in the sorted list?

Read the maths
SA[r] = j    rank[j] = r
T[j:]
The suffix of T that starts at position j and runs to the end.
r
A place in the sorted list, from 1 to n.
SA[r]
Where the r-th smallest suffix starts.
rank[j]
Which place the suffix starting at j has. It undoes SA.

With numbers: in ratatat, SA[2] = 4, because the 2nd smallest suffix is atat, which starts at 4. So rank[4] = 2. And rank[5] = 6, because tat is 6th.

Try it: press Next and watch the smallest remaining suffix glide up to its place. Then try hippityhoppity: suffixes that begin alike end up next to each other, and that is what the next scenes use.

What the book says

The algorithms so far can efficiently find all occurrences of a pattern in a text, and that is all they can do. A suffix array won't find all occurrences as quickly as Knuth-Morris-Pratt, but its additional flexibility makes it well worth studying. It is a compact way to represent the lexicographically sorted order of all n suffixes of a length-n text.

T[i:] denotes the suffix T[i : n]. The suffix array SA[1 : n] is defined so that if SA[i] = j, then T[j:] is the i th suffix of T in lexicographic order. Figure 32.11 shows SA, rank and LCP for the 7-character text ratatat, with rank[SA[i]] = i for i = 1, 2, …, n.

All the endings, in order
32.5 · suffix arrays: finding a pattern

One binary search finds them all

Every place a word occurs begins one of the sorted endings, and those endings sit next to each other.

Each place where at occurs is the beginning of a suffix. Since the suffixes are sorted, all the ones beginning with at are together, like all the words starting with "at" in a dictionary. So look in the middle of the list and compare. If the pattern comes earlier, drop the lower half. If it comes later, drop the upper half.

Once you hit one that starts with the pattern, look at its neighbours above and below. Keep going until a suffix doesn't start with the pattern. That whole run is the answer.

Read the maths
O(m lg n + km)
lg n
How many times the list can be halved. Halving 1,000,000 entries takes about 20 looks.
m
What each look may cost: comparing up to all m pattern letters.
k
The number of occurrences. Each neighbour you confirm costs up to m letters.

With numbers: for ratatat and the pattern at, n = 7, m = 2 and k = 3. lg 7 is under 3, so about 3 looks of up to 2 letters, then 3 confirmations of 2 letters each.

Why it is worth it: KMP reads the whole text for each new pattern. Here the sorting is done once, and each later search touches only a few suffixes. With many searches of one text, that pays for itself.

Try it: pick a pattern, or type your own. Press Next. The brackets close in as each look halves the list. Try tt, which doesn't occur, and see the brackets cross.

What the book says

Given the suffix array, you can search for a pattern via binary search. Each occurrence starts some suffix of the text, and because the suffix array is in lexicographically sorted order, all occurrences appear at the start of consecutive entries. In Figure 32.11, the three occurrences of at in ratatat appear in entries 1 through 3.

Finding the length-m pattern takes O(m lg n) time, because each comparison takes O(m) time. You can then find all occurrences by searching backward and forward from that spot until you find a suffix that does not start with the pattern, or you go beyond the bounds of the suffix array. If the pattern occurs k times, the time to find all k occurrences is O(m lg n + km).

32.5 · computing the suffix array

Sort by 2 letters, then 4, then 8

Replace each sorted piece by a small number, and then two such numbers sort a piece twice as long.

Comparing whole suffixes is slow. So be lazy. First sort only by the first 2 letters. Then give each 2-letter piece a number for its place in that order: its rank. at gets 1, ra gets 2, t gets 3, ta gets 4. Pieces that are the same share a number.

Now here is the trick. A 4-letter piece is two 2-letter pieces side by side, and you already have numbers for those. So sorting by pairs of numbers sorts the 4-letter pieces, and you don't compare letters at all. Do it again for 8. Each round doubles the length, so a text of length n needs only about lg n rounds.

Read the maths
the pair for i: ( rank[i], rank[i + l] )
l
The length sorted so far. It doubles every round: 2, 4, 8.
rank[i]
The rank of the piece of length l starting at i. The left part.
rank[i + l]
The rank of the piece right after it. The right part. It is 0 if that piece would start past the end, since an empty piece comes first.

With numbers: in ratatat with l = 2, rank is 2, 1, 4, 1, 4, 1, 3. For i = 3, the piece tata gets the pair (rank[3], rank[5]) = (4, 4). For i = 5, tat gets (4, rank[7]) = (4, 3). So tat sorts before tata.

Why the left part decides first: if the left piece of one string is smaller than the left piece of another, the whole string is smaller, whatever follows. The right part only matters when the left parts tie.

Try it: press Next. Rows glide when they are sorted, and glide back to text order when new pairs are made. Compare the tables with Figures 32.12 to 32.14 in the book: the numbers are the same. Ties in the middle of the book's tables may be in any order.

What the book says

The idea behind COMPUTE-SUFFIX-ARRAY is to lexicographically sort substrings of the text with increasing lengths, doubling each pass; by the ⌈lg n⌉th pass it is sorting all the suffixes. Substrings are represented by integer ranks: one substring is lexicographically smaller than another if and only if it has a smaller rank, and identical substrings have equal ranks. An empty substring always has rank 0.

Initial ranks come from a function ord that maps a character to its encoding, such as ASCII, so in Figure 32.12 a has 97. The procedure keeps an array substr-rank of objects with attributes left-rank, right-rank and index. MAKE-RANKS re-ranks a sorted substr-rank array, from 1 up to the number of unique substrings. The figures show why the loop stops after l = 4 for n = 7.

The while loop makes ⌈lg n⌉ − 1 iterations. With merge sort or heapsort on lines 8 and 18, the total is O(n lg2 n). Since the values sorted on line 18 are integers from 0 to n, radix sort does that line in Θ(n) time, by counting sort on right-rank and then on left-rank, for a total of Θ(n lg n). Problem 32-2 develops a linear-time algorithm instead. This page's Rust uses the library sort.

32.5 · computing the lcp array

Neighbours share a beginning

When one ending shares several letters with its sorted neighbour, the next ending inherits almost all of that work.

Look at the sorted list. atat and atatat, neighbours, share their first 4 letters. The LCP array records that number for each suffix and the one just before it. You could compare each pair from scratch, but that repeats a lot of work.

Here is the saving. Go through the suffixes in text order: the longest first, and then with one letter removed each time. Say atatat shares 4 letters with its neighbour. Remove its first letter to get tatat. Then tatat shares at least 3 letters with its own neighbour, so skip those 3 and start comparing at letter 4.

Read the maths

So upon considering T[i:], the longest common prefix with its predecessor T[j:] has length at least l. Lines 9–11 extend l, and line 14 peels off the first character. Shuffle a text so that it compresses, and undo it

The key ideas, in order.

A shift is one attempt

Shift s puts the pattern's first letter under text letter s + 1. A shift is valid when all m letters agree. There are n − m + 1 shifts to consider.

The naive matcher forgets

It tries every shift and throws away what it read at the last one. On a text of all a's it makes (n − m + 1)m comparisons.

Rabin-Karp rolls a number

Each window is a number, kept small with a remainder. Moving the window takes three sums. Different remainders rule a window out. Equal remainders still need a letter check, because a hit can be spurious.

An automaton keeps one number

Its state is the length of the longest prefix of the pattern that ends at the last letter read. Each text letter means one table lookup, so matching is Θ(n). The table costs O(m|Σ|) to build at best.

The prefix function is an overlap

π[q] is how far the first q letters overlap themselves when one copy slides along another. It answers: after a mismatch, how much of what I matched can I keep?

KMP never goes back

The text pointer only moves forward. Every comparison either moves that pointer or moves the pattern right, and each can happen at most n times. So at most 2n comparisons.

A suffix array sorts every ending

All occurrences of a pattern sit next to each other in the sorted list, so a binary search finds them in O(m lg n + km).

Doubling builds it quickly

Sort pieces of length 2, then 4, then 8. Each round turns the last round's order into ranks, and pairs of ranks sort the longer pieces. With radix sort this takes Θ(n lg n).

Neighbours share a beginning

The LCP array stores how many first letters each suffix shares with the one before it. Its largest value gives a longest repeated substring.

The book's words from this chapter, in plain language.

text
The long string you search in. The book calls it T, and its length is n.
pattern
The short string you search for. The book calls it P, and its length is m.
alphabet
The set of characters a string may use, written Σ. For example the digits 0 to 9, or a to z.
shift
How many columns the pattern has moved from the start of the text. Shift s puts its first letter under text letter s + 1.
valid shift
A shift where every letter of the pattern equals the text letter above it. In other words, a place where the pattern occurs.
prefix
A piece taken from the start of a string. Written w ⊏ x. The string ab is a prefix of abcca.
suffix
A piece taken from the end of a string. Written w ⊐ x. The string cca is a suffix of abcca.
proper prefix / proper suffix
A prefix or suffix that is shorter than the whole string.
empty string
The string with no letters, written ε. It is a prefix and a suffix of every string.
naive matcher
The procedure that tries every shift and checks the letters each time, using nothing it learned earlier.
remainder
What is left after taking out as many whole copies of a number as you can. 31 mod 13 is 5, because 31 = 13 + 13 + 5.
modulus
The number you divide by when you take a remainder. In Rabin-Karp it is the prime q.
window
The m text letters sitting above the pattern at the current shift. This page's word for the book's T[s + 1 : s + m].
hit
A window whose remainder equals the pattern's remainder. It might be a real match. Only a letter check can say.
spurious hit
A hit that turns out not to be a match: equal remainders, different letters.
radix
How many different digits there are. It is 10 for decimal digits, and d in general.
finite automaton
A small machine with a fixed set of states. It reads one character at a time, and a table says which state to go to next.
state
What the machine remembers, as one number from a fixed list. It is the machine's whole memory of what it has read.
accepting state
A state that means "yes". If the machine ends there, it accepts what it read.
transition function
The machine's table, written δ. Given a state and a letter, it says which state comes next.
final-state function
Written φ. The state the machine ends in after reading a whole string.
suffix function
Written σ. σ(x) is the length of the longest prefix of the pattern that ends at the end of x.
spine
The straight run of states 0, 1, 2, … in a string-matching automaton, one step per pattern letter matched.
prefix function
Written π. π[q] is the longest overlap of the pattern's first q letters with themselves, not counting the whole q letters.
aggregate analysis
Adding up the total work over a whole run, instead of multiplying the worst single step by the number of steps.
lexicographic order
Dictionary order. A string that runs out of letters comes before a longer string that starts the same way.
suffix array
Written SA. A list of where each suffix starts, in the sorted order of the suffixes. SA[1] is the start of the smallest one.
rank
The inverse of SA: rank[i] says where the suffix starting at i sits in the sorted list. Inside the sorting rounds, a number standing for a piece's place in sorted order.
LCP array
LCP[i] is how many first letters the i-th sorted suffix shares with the one before it. LCP stands for longest common prefix.
longest repeated substring
The longest piece of a text that occurs more than once. The two occurrences may overlap.
Burrows-Wheeler transform / BWT
Sort all rotations of a text and read off the last column. It tends to bring equal letters together, and it can be undone.
