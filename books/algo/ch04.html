Divide-and-Conquer

Split a problem into smaller copies of itself, solve those the same way, and combine the answers. This chapter multiplies matrices like that, then builds the tools for solving the recurrences that give such algorithms their running times.

4 · recurrences

A cost written in terms of itself

A teacher with 128 exam papers to sort hands half to each of two helpers, who split their piles again, and so on, until a pile is small enough to sort by hand. That is divide-and-conquer. When the problem is small enough, the base case, you solve it directly. Otherwise, the recursive case, you divide it into smaller instances of the same problem, conquer each one recursively, and combine their answers. Merge sort works this way.

Its running time comes out as a recurrence: an equation for T(n) that uses T on smaller arguments. T(n) = 2T(n/2) + n reads: two half-size subproblems, plus n work to divide and combine. A recurrence is algorithmic when, for every large enough threshold n₀, T(n) is a constant below n₀ and every path of recursion from a bigger n ends in one of those base cases. A correct divide-and-conquer algorithm always gives one.

So the book drops details. A recurrence with no stated base case is assumed to be algorithmic, and floors and ceilings are usually left out. The claim is that neither changes the Θ answer. The machine computes T(n) exactly, with a memo table so no value is computed twice, and divides it by the known answer, so you can test that claim.

Try it: press Step a few times to follow one call of T, then Play. Each n reuses smaller values from the memo, and the curve shows T(n) divided by the answer. Switch ⌊ ⌋ and ⌈ ⌉, and drag c₀ and n₀: the curve moves, yet it stays between two constants, which is what Θ means. Then choose ⌈ ⌉ and drag n₀ to 1: T(1) needs T(1), and the recursion never ends.

What the book says

Divide-and-conquer solves a problem instance recursively. If it is small enough (the base case) you solve it directly without recursing; otherwise (the recursive case) there are three characteristic steps: “Divide the problem into one or more subproblems that are smaller instances of the same problem.” “Conquer the subproblems by solving them recursively.” “Combine the subproblem solutions to form a solution to the original problem.”

A recurrence is an equation or inequality that describes a function over the integers or reals using the function itself, with recursive cases and base cases. It is well defined if at least one function satisfies it, and ill defined otherwise. A recurrence T(n) is algorithmic if, for every sufficiently large threshold constant n₀ > 0, (1) T(n) = Θ(1) for all n < n₀, and (2) for all n ≥ n₀, “every path of recursion terminates in a defined base case within a finite number of recursive invocations.” The recurrence for the worst-case running time of a correct divide-and-conquer algorithm is algorithmic.

The convention: “Whenever a recurrence is stated without an explicit base case, we assume that the recurrence is algorithmic.” The asymptotic solutions of most algorithmic recurrences don't depend on the threshold, as long as it is large enough, nor on dropping floors and ceilings; Section 4.7 gives a sufficient condition. An inequality such as T(n) ≤ 2T(n/2) + Θ(n) states only an upper bound, so its solution is given with O; the reverse inequality gives Ω.

The chapter's examples: T(n) = 8T(n/2) + Θ(1) = Θ(n³) for the simple recursive matrix multiply; Strassen's T(n) = 7T(n/2) + Θ(n²) = Θ(nlg 7) = O(n2.81); T(n) = T(n/3) + T(2n/3) + Θ(n) = Θ(n lg n); Chapter 9's T(n) = T(n/5) + T(7n/10) + Θ(n) = Θ(n); and recursive linear search, T(n) = T(n − 1) + Θ(1) = Θ(n).

Four methods solve recurrences. The substitution method (4.3) guesses the form of a bound and proves it by induction; it is “perhaps the most robust method” but needs a good guess. The recursion-tree method (4.4) adds up the costs level by level. The master method (4.5–4.6) “is the easiest method, when it applies,” for T(n) = aT(n/b) + f(n) with a > 0, b > 1 and a driving function f(n). The Akra-Bazzi method (4.7) is more general and uses calculus.

4.1 · multiplying square matrices

Row meets column, n³ times

To multiply two n × n matrices, every entry of the answer is a row of A walked against a column of B: multiply the pairs and add them up. Entry cij is the sum over k of aik · bkj. There are n² entries and each one is a sum of n products. The book assumes the matrices are dense, with most entries nonzero, rather than sparse ones that could be stored more compactly.

MATRIX-MULTIPLY is three nested loops: row i, column j, and the term k. It generalizes a little: it adds the product into C, computing C = C + A · B. If you only want A · B, set C to zero first, which costs Θ(n²) and is swamped by the rest. Each loop runs exactly n times, so line 4 runs n³ times: Θ(n³).

The Rust version stores each matrix the way real numeric code does, in one flat buffer, row after row: row-major order, with entry (i, j) at offset i · n + j. Walking along a row of A steps one slot at a time. Walking down a column of B jumps n slots each step.

Try it: press Step and watch row i of A and column j of B light up while cij collects one product per press, then Play. Compare the counter with n³ for 2 × 2, 3 × 3 and 4 × 4. Pick C = I first to see that the procedure adds into C rather than overwriting it. In Rust, the memory strip shows the row as one run of the buffer and the column as every n-th slot.

What the book says

For square n × n matrices A and B, the product C = A · B is also n × n, and for i, j = 1, 2, …, n its (i, j) entry is cij = Σk=1n aik · bkj (equation 4.1). The book generally assumes the matrices are dense, meaning that most of the n² entries are not 0, as opposed to sparse, where most are 0 and the nonzero entries can be stored more compactly than in an n × n array.

Computing C requires computing n² entries, each the sum of n pairwise products. MATRIX-MULTIPLY generalizes the problem slightly: it takes three n × n matrices A, B and C, and adds A · B to C, storing the result in C, so it computes C = C + A · B. If only A · B is needed, initialize all n² entries of C to 0 first, which takes an additional Θ(n²) time; the cost of matrix multiplication asymptotically dominates it.

The for loop of lines 1–4 computes the entries of each row i; within a row, the loop of lines 2–4 computes each entry cij for each column j; and each iteration of the loop of lines 3–4 adds in one more term of equation (4.1). Because each of the triply nested loops runs for exactly n iterations and line 4 takes constant time, MATRIX-MULTIPLY runs in Θ(n³) time, still Θ(n³) with the Θ(n²) initialization added in.

4.1 · a simple divide-and-conquer algorithm

Eight half-size products

Cut each n × n matrix into four n/2 × n/2 blocks, and the blocks multiply just like numbers do: C11 = A11 · B11 + A12 · B21, and the same pattern gives C12, C21 and C22. That is eight half-size multiplications and four additions. MATRIX-MULTIPLY-RECURSIVE makes each one a recursive call (with n an exact power of 2) until the blocks are single numbers, the base case: one multiply and one add.

How do you cut a matrix? You could copy every block into new storage, Θ(n²) work per call. Or you could use index calculation: a block is just named by the row r and column c where it starts, a couple of numbers, so cutting takes Θ(1), and writing into the block writes into the original matrix. The book uses index calculation, and the calls add straight into C, so there is nothing left to combine: T(n) = 8T(n/2) + Θ(1).

That solves to Θ(n³), no faster than the triple loop. Merge sort's 2T(n/2) + Θ(n) is only Θ(n lg n), even with the bigger extra term, because its tree has two children per node. This one has eight: a much bushier tree, with n³ leaves.

Try it: press Step: each press is one call. The outlined blocks show which quarter of A times which quarter of B is being added into which quarter of C, and the tree shows where that call sits. Play runs all 73 calls: 64 leaves, the same 64 multiplications and the same C as the triple loop. Then pick Copy blocks: the copied-elements counter climbs to 144 and the memory strip fills with new Vecs, yet the total stays Θ(n³).

What the book says

For n > 1, the divide step partitions the n × n matrices into four n/2 × n/2 submatrices, assuming n is an exact power of 2. Writing the product blockwise gives C11 = A11 · B11 + A12 · B21, C12 = A11 · B12 + A12 · B22, C21 = A21 · B11 + A22 · B21 and C22 = A21 · B12 + A22 · B22 (equations 4.5–4.8): eight n/2 × n/2 multiplications and four additions of submatrices.

There are two common ways to partition. One allocates temporary storage for A's and B's four submatrices, copies each element into it, and after the recursive conquer step copies the elements of C's four submatrices back into C; it takes Θ(n²) time, since 3n² elements are copied. The second “uses index calculations and is faster and more practical”: a submatrix is specified by where it lies within the matrix, so partitioning is arithmetic on location information of constant size, and changes to the submatrix update the original matrix, since they occupy the same storage. Exercise 4.1-3 asks you to show that copying makes no asymptotic difference for multiplication; for matrix addition it can (Exercise 4.1-4).

In the base case, n = 1, line 3 performs one scalar multiplication and one addition, so T(1) = Θ(1). In the recursive case, line 6 partitions in Θ(1) time by index calculation and lines 8–15 make eight recursive calls, the first four computing the first terms of equations (4.5)–(4.8) and the next four adding in the second terms. “There is no combine step, because the matrix C is updated in place.” So T(n) = 8T(n/2) + Θ(1) (recurrence 4.9), whose solution, by the master method of Section 4.5, is Θ(n³), the same as MATRIX-MULTIPLY.

Why so much larger than merge sort's Θ(n lg n)? The factor in front of T decides how many children each node of the recursion tree has. Here every internal node has eight children, not two, giving a “bushier” recursion tree with many more leaves, even though the internal nodes are each much smaller.

4.2 · strassen's algorithm for matrix multiplication

Seven products where eight seemed necessary

The definition of a matrix product spends n³ scalar multiplications, and for a long time people assumed nothing could do better. Then, in 1969, V. Strassen did. His idea has a small algebra cousin: x² − y² looks like two multiplications, yet (x + y)(x − y) gets it with one multiplication and two additions. When x and y are big matrices, a multiplication costs far more than an addition, so that trade pays.

Strassen splits A, B and C into four n/2 × n/2 blocks, like the simple recursive method, but he never forms the eight block products. He builds ten sums S1…S10, multiplies them in seven recursive calls P1…P7, and adds and subtracts the P's into C's blocks. The additions cost Θ(n²); the recursion branches seven ways instead of eight, a less bushy recursion tree: T(n) = 7T(n/2) + Θ(n²) = Θ(nlg 7) = O(n2.81).

The saving compounds. Each level of recursion keeps 7/8 of the multiplications, so ten levels keep (7/8)10, about a quarter. The extra additions are real work too: counted one scalar operation at a time, the full recursion overtakes the triple loop only at n = 1024.

Try it: press Step to fill the worksheet one line at a time, then Play. The flying numbers show which entries each line reads. It starts on the book's Exercise 4.2-1; New numbers deals other matrices, and C still matches the triple loop. Switch to Rust: the memory strip shows a and b copied into strassen's frame, with nothing on the heap. Then pick As n doubles, press Play, and flip the count to All operations.

What the book says

Many mathematicians presumed it was not possible to multiply matrices in o(n³) time until 1969, when V. Strassen published a remarkable recursive algorithm. It runs in Θ(nlg 7) time; since lg 7 = 2.8073549…, that is O(n2.81), asymptotically better than MATRIX-MULTIPLY and MATRIX-MULTIPLY-RECURSIVE. The key is to use the divide-and-conquer idea of MATRIX-MULTIPLY-RECURSIVE “but make the recursion tree less bushy”: seven recursive multiplications of n/2 × n/2 matrices instead of eight, paid for with a constant number of extra matrix additions. The book calls subtractions additions too, since they are structurally the same computation.

The algebra hint: x² − y² = (x + y)(x − y) needs one multiplication and two additions instead of two multiplications and one subtraction. For scalars both take three operations; for large matrices the cost of multiplying outweighs the cost of adding.

The four steps, for n an exact power of 2: (1) if n = 1, do one scalar multiplication and addition and return; otherwise partition A, B and C by index calculation in Θ(1). (2) Create S1, …, S10, each the sum or difference of two submatrices, and seven zeroed matrices P1, …, P7, in Θ(n²). (3) Recursively compute the seven products, 7T(n/2). (4) Update C11, C12, C21, C22 by adding or subtracting P's, in Θ(n²). Hence T(n) = 7T(n/2) + Θ(n²), recurrence (4.10).

The products are P1 = A11·S1, P2 = S2·B22, P3 = S3·B11, P4 = A22·S4, P5 = S5·S6, P6 = S7·S8, P7 = S9·S10; their expansions into A and B terms are never computed. C11 = C11 + P5 + P4 − P2 + P6, C12 = C12 + P1 + P2, C21 = C21 + P3 + P4, C22 = C22 + P5 + P1 − P3 − P7. Altogether the algorithm produces the correct product with 7 submatrix multiplications and 18 submatrix additions.

The chapter notes add that Winograd cut the additions from 18 to 15, still with seven multiplications; that Strassen's algorithm can be practical for large dense matrices; and that with limited-precision floating-point values it produces larger numerical errors than the Θ(n³) algorithms.

4.3 · the substitution method for solving recurrences

Prove the guess one rung at a time

The substitution method has two steps. First, guess the form of the answer with symbolic constants, such as T(n) ≤ c·n lg n. Second, prove it by mathematical induction, and find constants that make the proof work. The name comes from the second step: you substitute the guess for T on the smaller arguments.

The book's example is T(n) = 2T(⌊n/2⌋) + Θ(n), merge sort's recurrence with a floor. Picture a ladder whose rungs are n = 1, 2, 3, … Rung n stands on rung ⌊n/2⌋: if the guess holds there, then T(n) ≤ 2c⌊n/2⌋ lg⌊n/2⌋ + Θ(n) ≤ cn lg n − cn + Θ(n), which is at most cn lg n once cn swamps the Θ(n) term. That is the inductive step.

A ladder also needs a foot. Starting at n0 = 1 is hopeless: lg 1 = 0, so c·1·lg 1 = 0, smaller than any running time. The book starts at n0 = 2 and checks the base cases n = 2 and 3 directly, choosing c = max{T(2), T(3)}. To have real numbers to check, the machine takes the Θ(n) term to be exactly n, and T(1) = 1.

Try it: press Play. Base rungs (lilac ring) are checked against the real value of T(n); every other rung receives the hypothesis from rung ⌊n/2⌋ below it. Then drag c down to 1.5: rung 2 breaks, and so does every rung standing on it, even where the bound is true. Pick n₀ = 3 and c = 1.5 proves everything again. n₀ = 1 never works.

What the book says

The substitution method comprises two steps: “Guess the form of the solution using symbolic constants”; then use mathematical induction to show that the solution works, and find the constants. Applying the inductive hypothesis means substituting the guessed solution for the function on smaller values, hence the name. It can establish either an upper or a lower bound, and it is usually best not to try both at once: prove an O-bound, then an Ω-bound; together they give a Θ-bound (Theorem 3.1).

For T(n) = 2T(⌊n/2⌋) + Θ(n), recurrence (4.11), the inductive hypothesis is T(n) ≤ cn lg n for all n ≥ n0, with the constants c > 0 and n0 > 0 chosen later. Using T(n) = O(n lg n) itself as the hypothesis would be dangerous, “because the constants matter”. If the bound holds for ⌊n/2⌋, which it does when n ≥ 2n0, then T(n) ≤ 2(c⌊n/2⌋ lg(⌊n/2⌋)) + Θ(n) ≤ cn lg(n/2) + Θ(n) = cn lg n − cn + Θ(n) ≤ cn lg n, provided n0 and c are large enough that cn dominates the anonymous function hidden by the Θ(n) term.

The base cases are n0 ≤ n < 2n0. As long as n0 > 1, lg n > 0, so the book picks n0 = 2. The recurrence is algorithmic, so T(2) and T(3) are constants, and c = max{T(2), T(3)} gives T(2) ≤ c < (2 lg 2)c and T(3) ≤ c < (3 lg 3)c. Thus T(n) ≤ cn lg n for all n ≥ 2, and T(n) = O(n lg n).

Published proofs rarely treat base cases in this much detail, because for most algorithmic divide-and-conquer recurrences they are handled the same way: ground the induction on a range from a convenient positive constant n0 up to some n0′ > n0 (here 2n0) in which the recurrence always bottoms out, and choose the leading constant large enough for the hypothesis to hold across that range.

4.3 · making a good guess

Bracket the answer, then trim the guess

No recipe finds the tightest answer to every recurrence; guessing well takes experience. Two habits help. If a recurrence looks like one you have solved, guess a similar answer: T(n) = 2T(n/2 + 17) + Θ(n) looks like merge sort's, and for large n both n/2 and n/2 + 17 cut n nearly in half, so guess O(n lg n). Or bracket the answer: start from a loose lower bound and a loose upper bound, then raise one and lower the other until they meet.

Sometimes the guess is right and the induction still refuses to close. For T(n) = 2T(n/2) + Θ(1), the guess T(n) ≤ cn gives back cn + Θ(1): a little over, for every c. The fix sounds backwards: subtract a lower-order term. Guess cn − d. Each of the two recursive calls now brings a −d, so the step gives cn − 2d + Θ(1), which is at most cn − d once d covers the Θ(1) constant.

Adding a term instead, cn + d, makes things worse, because the extra d also arrives once per recursive call. A bigger guess such as cn² closes easily but proves less. The machine only gathers evidence and checks one step with real numbers; the proof is still the induction.

Try it: in Narrow the range, pick a guess and press Test: the ratio T(n)/g(n) climbs, sinks or settles, and the bracket of known bounds closes in. Try n√n, then n lg n. In Subtract a term, press Play with cn and drag c: the step always overshoots by exactly b = 3, the Θ(1) constant. Switch to cn − d and drag d up to 3, the value of b. Then try cn + d, and cn².

What the book says

“Unfortunately, there is no general way to correctly guess the tightest asymptotic solution to an arbitrary recurrence.” Making a good guess takes experience and, occasionally, creativity; heuristics, playing around with recurrences, and recursion trees (Section 4.4) all help.

If a recurrence is similar to one you've seen, guess a similar solution. T(n) = 2T(n/2 + 17) + Θ(n), defined on the reals, looks like the merge-sort recurrence (2.3); when n is large, n/2 and n/2 + 17 both cut n nearly in half, so guess O(n lg n) and verify it by substitution (Exercise 4.3-1). Another way is to prove loose bounds and reduce the uncertainty: for recurrence (4.11), start with Ω(n), because of its Θ(n) term, and an initial upper bound of O(n²), then work on both until they converge on Θ(n lg n).

A trick of the trade: when the math fails to work out, the inductive assumption is often not strong enough, and subtracting a lower-order term from the guess helps. For T(n) = 2T(n/2) + Θ(1), recurrence (4.12), guessing T(n) ≤ cn gives T(n) ≤ 2(c(n/2)) + Θ(1) = cn + Θ(1), which does not imply T(n) ≤ cn for any choice of c. The larger guess O(n²) works but is only a loose bound; O(n) is correct and tight, yet induction must prove the exact form of the hypothesis.

With T(n) ≤ cn − d, d ≥ 0: T(n) ≤ 2(c(n/2) − d) + Θ(1) = cn − 2d + Θ(1) ≤ cn − d − (d − Θ(1)) ≤ cn − d, as long as d is larger than the anonymous upper-bound constant hidden by the Θ-notation, with c large enough for the base cases. “Subtracting a lower-order term works!” It is not counterintuitive: with more than one recursive invocation, an added lower-order term is added once per invocation, and a subtracted one is subtracted once per invocation; here d is subtracted twice because the coefficient of T(n/2) is 2.

4.3 · avoiding pitfalls

The constant that wouldn't stay put

Here is a “proof” that T(n) = 2T(⌊n/2⌋) + Θ(n) is O(n). Assume T(n) = O(n) for smaller arguments. Then T(n) ≤ 2·O(⌊n/2⌋) + Θ(n) = 2·O(n) + Θ(n) = O(n). Every line looks harmless, and the conclusion is wrong: the true answer is Θ(n lg n).

The trick is that O(n) hides a constant, and the “proof” quietly lets it change. Name it: assume T(n/2) ≤ c·n/2. The step gives T(n) ≤ cn + Θ(n), which is O(n), but with a bigger constant than c. Induction needs the same c at every level; here it grows by one per level, so after lg n levels it is lg n + 1.

A second slip makes the same mistake from the other side: guess T(n) ≤ cn, reach T(n) ≤ cn + Θ(n), and declare it O(n) “since c is a positive constant”. The goal was the exact hypothesis, T(n) ≤ cn, and cn + Θ(n) is not that. The cure for both: no asymptotic notation inside an inductive hypothesis, and named constants throughout.

Try it: press Play in As O(n): every level's label says O(n) while the bars of T(n)/n climb. Switch to With c named to see the constant each level really needs. Then drag claimed c: whatever you pick, T(n) ≤ c·n breaks at n = 2c.

What the book says

Avoid using asymptotic notation in the inductive hypothesis for the substitution method, because it's error prone. For recurrence (4.11) you can falsely “prove” that T(n) = O(n) by adopting T(n) = O(n) as the hypothesis: T(n) ≤ 2·O(⌊n/2⌋) + Θ(n) = 2·O(n) + Θ(n) = O(n), which the book marks “wrong!”

The problem with this reasoning is that the constant hidden by the O-notation changes. Repeating the proof with an explicit constant, T(n) ≤ cn for all n ≥ n0, gives T(n) ≤ 2(c⌊n/2⌋) + Θ(n) ≤ cn + Θ(n). Indeed cn + Θ(n) = O(n), but the constant hidden by that O must be larger than c, because the function hidden by Θ(n) is asymptotically positive; the third step, cn + Θ(n) ≤ cn, cannot be taken. The constants hidden by any asymptotic notation must be the same constants throughout the proof, so it is best to name them explicitly.

Another fallacy: guess T(n) ≤ cn, argue T(n) ≤ 2(c⌊n/2⌋) + Θ(n) ≤ cn + Θ(n) = O(n), “since c is a positive constant.” The mistake is the difference between the goal, T(n) = O(n), and the inductive hypothesis, T(n) ≤ cn: in any inductive proof, “you must prove the exact statement of the inductive hypothesis.”

4.4 · the recursion-tree method: an illustrative example

Draw every call, then add up the rows

A recurrence is a tree in disguise. Take T(n) = 3T(n/4) + cn²: one call does cn² work of its own and hands three quarter-size jobs to helpers, who do the same. Draw each call as a node with its own cost inside and you have a recursion tree. Add across each row to get the per-level cost, then add the rows.

Depth i holds 3i nodes of size n/4i, so the row costs 3i·c(n/4i)² = (3/16)icn². Each row is 3/16 of the one above: a decreasing geometric series, so even infinitely many rows stay under (16/13)cn². The 3log4 n = nlog4 3 ≈ n0.79 leaves barely register. The guess is T(n) = O(n²), and the root alone costs cn², so it is tight.

A tree drawn for a guess may cut corners (here: n a power of 4, T(1) = Θ(1)). The substitution method checks it properly: if T(n/4) ≤ d(n/4)², then T(n) ≤ (3/16)dn² + cn², which is at most dn² exactly when d ≥ (16/13)c. The constant c is given by the Θ; d is yours to choose.

Try it: in Build the tree, press Step to expand one level at a time, like parts (a)–(d) of Figure 4.1, and watch the total bar creep toward the 16/13 mark without reaching it. Move n to 256 and play again. Then switch to Check the guess and drag d just below 16/13 ≈ 1.231, say 1.23: the check now fails, but only at a large n.

What the book says

In a recursion tree, “each node represents the cost of a single subproblem somewhere in the set of recursive function invocations.” You sum the costs within each level to get per-level costs, then sum those. “A recursion tree is best used to generate intuition for a good guess, which you can then verify by the substitution method.” Used only for a guess, it can tolerate a little sloppiness; drawn and summed meticulously, it can serve as a direct proof.

Figure 4.1 builds the tree for T(n) = 3T(n/4) + cn², where c > 0 is the upper-bound constant in the Θ(n²) term of recurrence (4.13). For intuition, assume n is an exact power of 4 and T(1) = Θ(1). A node at depth i has size n/4i, so internal nodes sit at depths 0, 1, …, log4 n − 1 and leaves at depth log4 n. Depth i has 3i nodes, each costing c(n/4i)², for (3/16)icn² in all; the 3log4 n = nlog4 3 leaves cost Θ(nlog4 3).

Summing, T(n) = Σi=0log4 n (3/16)icn² + Θ(nlog4 3) < Σi=0∞ (3/16)icn² + Θ(nlog4 3) = (16/13)cn² + Θ(nlog4 3) = O(n²). The coefficients form a decreasing geometric series, and since the root contributes cn², “the cost of the root dominates the total cost of the tree.” The bound is tight: the first call alone costs Θ(n²), so Ω(n²) is a lower bound.

The substitution method confirms it: T(n) ≤ 3T(n/4) + cn² ≤ 3d(n/4)² + cn² = (3/16)dn² + cn² ≤ dn², where the last step holds if d ≥ (16/13)c; choosing d large enough also covers the base cases below the threshold n0. The constant c is given by the Θ-notation (any c′ ≥ c also works), while d is ours to pick, and letting it depend on c is fine.

4.4 · an irregular example

A lopsided tree that still costs n lg n

Not every split is even. T(n) = T(n/3) + T(2n/3) + cn cuts each job into a third and two thirds. Draw every node as wide as its subproblem and a row of the tree is never wider than the root: the pieces of a full level add back up to n, so that level costs exactly cn.

The tree is lopsided. The left edge, always taking thirds, reaches the base case after about log3 n levels; the right edge, taking two thirds, goes deeper, to height h = ⌊log3/2(n/n0)⌋ + 1 = Θ(lg n). Rows below the left edge have gaps and cost less. At most cn per level times Θ(lg n) levels: the internal nodes cost O(n lg n).

The leaves need care. A complete binary tree that tall would have 2h ≈ n1.71 leaves, more than n lg n. The real tree is far sparser: its leaf count obeys L(n) = L(n/3) + L(2n/3), which is only O(n). So the internal nodes dominate, and T(n) = O(n lg n).

4.5 · the master theorem

Who pays most: the root, the leaves, or every level?

Most divide-and-conquer algorithms split a job of size n into a pieces of size n/b and spend f(n) on dividing and combining. That is a master recurrence, T(n) = aT(n/b) + f(n), with constants a > 0 and b > 1. The root of its recursion tree costs the driving function f(n). At the bottom sit alogb n = nlogb a leaves: that count is the watershed function.

The master theorem compares the two. Case 1: the watershed grows polynomially faster, f(n) = O(nlogb a − ε) for some ε > 0. Level costs grow toward the leaves, and T(n) = Θ(nlogb a). Case 2: they match up to a log factor, f(n) = Θ(nlogb a lgk n) with k ≥ 0. Every level costs about the same, so multiply by the number of levels: Θ(nlogb a lgk+1 n). Case 3: f grows polynomially faster and passes the regularity condition af(n/b) ≤ cf(n) for some c < 1. Level costs shrink from the root, and T(n) = Θ(f(n)).

You don't have to worry about rounding: the theorem reads aT(n/b) as some mix of T(⌊n/b⌋) and T(⌈n/b⌉) calls, and the answer is the same however the sizes round.

Then drag the sliders: the blue dot is f(n) = np lgk n, the lilac line the watershed, and the bars are the tree's level costs ajf(n/bj). Set a = 4, b = 2, p = 1.99: still case 1, though the bars barely grow. Press p = logb a to land on the watershed, then raise k.

What the book says

The master method provides a “cookbook” method for solving algorithmic recurrences of the form T(n) = aT(n/b) + f(n), where a > 0 and b > 1 are constants. The function f(n) is the driving function and the recurrence is a master recurrence. It describes an algorithm that divides a problem of size n into a subproblems of size n/b < n, solves each recursively in T(n/b) time, and spends f(n) to divide and combine. Strassen's recurrence is a master recurrence with a = 7, b = 2 and f(n) = Θ(n²).

Theorem 4.1 (Master theorem). Let a > 0 and b > 1 be constants, let f(n) be defined and nonnegative on all sufficiently large reals, and let T(n) = aT(n/b) + f(n) on the natural numbers, where aT(n/b) actually means a′T(⌊n/b⌋) + a″T(⌈n/b⌉) for constants a′, a″ ≥ 0 with a = a′ + a″. (1) If f(n) = O(nlogb a − ε) for some constant ε > 0, then T(n) = Θ(nlogb a). (2) If f(n) = Θ(nlogb a lgk n) for some constant k ≥ 0, then T(n) = Θ(nlogb a lgk+1 n). (3) If f(n) = Ω(nlogb a + ε) for some constant ε > 0, and af(n/b) ≤ cf(n) for some constant c < 1 and all sufficiently large n, then T(n) = Θ(f(n)).

The function nlogb a is called the watershed function. In case 1 it must be larger than f(n) by at least a factor of Θ(nε); in the recursion tree, “the cost per level grows at least geometrically from root to leaves, and the total cost of leaves dominates the total cost of the internal nodes.” In case 2 each level costs about Θ(nlogb a lgk n) and there are Θ(lg n) levels; k = 0 is the most common situation. In case 3 “the cost per level drops at least geometrically from the root to the leaves, and the root cost dominates the cost of all other nodes.” Most polynomially bounded functions satisfy the regularity condition; it can fail for a function that grows slowly in local areas yet relatively quickly overall (Exercise 4.5-5).

“The separation doesn’t need to be much, but it must be there, and it must grow polynomially.” For T(n) = 4T(n/2) + n1.99 the watershed is n², the driving function is smaller by a factor of n0.01, and case 1 applies with ε = 0.01. The master method also lets you state a recurrence without floors and ceilings: the bounds stay the same however the arguments are rounded, and even for the recurrence defined on the reals.

4.5 · using the master method

Nine recurrences, one question: which case?

Using the master method takes three moves. Read off a and b. Work out the watershed nlogb a. Compare the driving function f(n) with it, pick the case, and write down the answer. The book runs the method on a handful of recurrences, among them the ones from merge sort, the simple recursive matrix multiplication and Strassen's algorithm.

Sometimes no case fits. The cases leave gaps: f(n) can be smaller than the watershed without being polynomially smaller, or larger without being polynomially larger. The book's example is T(n) = 2T(n/2) + n/lg n: n/lg n is below n, but only by a lg n factor, and case 2 would need k = −1. Case 3 can also fail its regularity condition, and some driving functions can't be compared with the watershed at all. Then you fall back on substitution or the Akra-Bazzi method.

Recurrence (4.14) from the previous scene is out of reach for a different reason: with subproblems of sizes n/3 and 2n/3, it isn't a master recurrence at all.

For T(n) = 2T(n/2) + n lg n, case 2 with k = 1 gives Θ(n lg² n).

When the master method doesn't apply: the watershed and driving functions may not be asymptotically comparable. Even when they are, there is a gap between cases 1 and 2 when f(n) is asymptotically smaller than the watershed but not polynomially smaller, and a gap between cases 2 and 3 when f(n) grows more than polylogarithmically faster but not polynomially faster. If the driving function falls into a gap, or the regularity condition fails, you need another method.

4.6 · proof of the continuous master theorem

Add up the tree, one depth at a time

Picture the recursion as an office. The boss gets a job of size n and spends f(n) splitting it up and gluing the answers back together. Each of a helpers gets a job of size n/b and does the same, so at depth j there are aj workers, each spending f(n/bj). A job smaller than 1 is a leaf, done in constant time. Lemma 4.2 adds up the bill depth by depth: T(n) is the leaves' cost Θ(nlogb a), the watershed function again, plus the sum g(n) of the depth costs aj f(n/bj) for j = 0 to ⌊logb n⌋.

Lemma 4.3 bounds g(n) by comparing each depth with the one above it. If the cost grows by a constant factor per depth, g(n) is a geometric series whose last terms dominate, and the leaves decide the answer (case 1). If every depth costs the same, g(n) is one depth's cost times ⌊logb n⌋ + 1 depths, an extra lg n factor (case 2). If each depth costs at most c < 1 times the one above, the regularity condition, the whole series is at most f(n)/(1 − c) and the root decides (case 3).

The continuous master theorem (Theorem 4.4) gives the same three answers for recurrences over the real numbers whose base case covers everything below some threshold constant n0. The proof renames the problem: T′(n) = T(n0n) has its base case below 1, so Lemma 4.2 applies to it. A bigger n0 only removes the bottom logb n0 depths, which changes T(n) by a constant factor and Θ not at all.

Try it: press Play and watch each depth's bar appear while the code panel keeps the running sum g. Drag a: at a = 4 every bar has the same length (case 2), below 4 the bars shrink from the root (case 3), above 4 they grow toward the leaves (case 1). Drag n up: T(n) grows fast, but the last counter, T(n) divided by the Θ answer, settles toward a constant. Raise n₀ to cut whole depths off the bottom, then try f(n) = n² lg n.

What the book says

Proving the master theorem in full generality, especially dealing with floors and ceilings, is beyond the scope of the book. Section 4.6 instead proves the continuous master theorem, in which the master recurrence is defined over sufficiently large positive real numbers. “The proof of this version, uncomplicated by floors and ceilings, contains the main ideas needed to understand how master recurrences behave.” The name does not mean that T(n) or f(n) need be continuous, only that the domain of T(n) is the real numbers.

Lemma 4.2: for constants a > 0 and b > 1 and f(n) defined over real numbers n ≥ 1, the recurrence T(n) = Θ(1) if 0 ≤ n < 1 and T(n) = aT(n/b) + f(n) if n ≥ 1 has solution T(n) = Θ(nlogb a) + Σj=0⌊logb n⌋ aj f(n/bj), equation (4.18). The recursion tree (Figure 4.3) has aj nodes at depth j, each of cost f(n/bj), height ⌊logb n⌋ + 1, and a⌊logb n⌋+1 = Θ(nlogb a) leaves of cost Θ(1).

The three cases depend on how the total cost is distributed across levels: in case 1 the costs increase geometrically from the root to the leaves; in case 2 they depend on k, and with k = 0 they are equal for each level; in case 3 they decrease geometrically from the root to the leaves. Lemma 4.3 bounds g(n) = Σ aj f(n/bj): if f(n) = O(nlogb a − ϵ) for a constant ϵ > 0, then g(n) = O(nlogb a); if f(n) = Θ(nlogb a lgk n) for a constant k ≥ 0, then g(n) = Θ(nlogb a lgk+1 n); and if 0 < af(n/b) ≤ cf(n) for a constant c in 0 < c < 1 and all n ≥ 1, then g(n) = Θ(f(n)), because j iterations give aj f(n/bj) ≤ cj f(n) and the geometric series is at most f(n)/(1 − c).

Theorem 4.4 (continuous master theorem) gives T(n) = Θ(nlogb a), Θ(nlogb a lgk+1 n) or Θ(f(n)) under the same three conditions, case 3 also asking for f(n) = Ω(nlogb a + ϵ) and the regularity condition for all sufficiently large n. Its proof handles an arbitrary threshold constant n0 > 0 by defining T′(n) = T(n0n) and f′(n) = f(n0n): T′ satisfies the conditions of Lemma 4.2, and T(n) = T′(n/n0).

4.7 · akra-bazzi recurrences

Uneven pieces: find the one exponent that fits

Not every divide-and-conquer algorithm cuts its problem into equal pieces. The book's example, T(n) = T(n/5) + T(7n/10) + n, is close to the recurrence of a selection algorithm in Chapter 9: one recursive call works on a fifth of the input, the other on seven tenths of it. The master theorem wants a single a and a single b, so it has nothing to say here. An Akra-Bazzi recurrence allows any number of terms ai T(n/bi), each with its own shrink factor.

The Akra-Bazzi method replaces the watershed exponent logb a with the one number p that makes the pieces weigh exactly one: S(p) = Σ ai/bip = 1. S falls steadily as p grows, so bisection finds p: keep a bracket [lo, hi] with S(lo) ≥ 1 ≥ S(hi) and halve it until it is tiny. Then T(n) = Θ(np(1 + ∫1n f(x)/xp+1 dx)). The integral does the job of the master theorem's three cases: it decides whether the driving function, every level alike, or the leaves win.

Like the master theorem, the method drops floors and ceilings. That is safe when f satisfies the polynomial-growth condition: stretching n by any factor between 1 and φ changes f(n) by at most a constant factor d. Polynomials and logarithms pass. 2n fails, because 22n/2n = 2n outgrows every constant.

Try it: press Play and watch the yellow bracket close in on p while the code panel shows lo, hi and S(mid). Then drag s, the size of the second subproblem: below 0.8 the answer is Θ(n), as the book finds for 7/10; at 0.8 the two pieces add up to the whole input and it becomes Θ(n lg n); above 0.8 it is Θ(np) with p > 1. What the book says

The recurrences originally studied by M. Akra and L. Bazzi take the form T(n) = f(n) + Σi=1k ai T(n/bi) (4.22), where k is a positive integer, all the constants a1, …, ak are strictly positive, all the constants b1, …, bk are strictly greater than 1, and the driving function f(n) is defined on sufficiently large nonnegative reals and is itself nonnegative. They generalize master recurrences and can describe algorithms that break a problem into different-sized subproblems.

It is not okay in general to ignore floors and ceilings, because some driving functions “can be really, really weird.” f(n) satisfies the polynomial-growth condition if there exists a constant n̂ > 0 such that for every constant φ ≥ 1 there exists a constant d > 1 (depending on φ) with f(n)/d ≤ f(ψn) ≤ d f(n) for all 1 ≤ ψ ≤ φ and n ≥ n̂. To a first order it says f(Θ(n)) = Θ(f(n)). Functions of the form Θ(nα lgβ n lg lgγ n) satisfy it; exponentials and superexponentials do not. Theorem 4.5, presented without proof: if f satisfies the condition, replacing each T(n/bi) with T(⌈n/bi⌉) or T(⌊n/bi⌋) changes the solution only to within Θ, and even perturbations of size O(n/lg1+ϵ n) leave it unaffected.

The method first determines the unique real number p such that Σ ai/bip = 1. Such a p always exists: as p → −∞ the sum goes to ∞, it decreases as p increases, and as p → ∞ it goes to 0. The solution is then T(n) = Θ(np(1 + ∫1n f(x)/xp+1 dx)) (4.23).

Example: T(n) = T(n/5) + T(7n/10) + n (4.24), similar to the recurrence for selecting the ith smallest of n numbers in Chapter 9. Solving (1/5)p + (7/10)p = 1 exactly is messy (p = 0.83978…), but (1/5)0 + (7/10)0 = 2 and (1/5)1 + (7/10)1 = 9/10 put p in the range 0 < p < 1, and that is enough: the integral of x−p gives Θ(np · Θ(n1−p)) = Θ(n). The method is more general than the master theorem but requires calculus. “When it applies, the master method is much simpler to use, but only when subproblem sizes are more or less equal.”

problem 4-2 · parameter-passing costs

Hand over the address, or photocopy the book?

Handing an array to a function can mean two very different things. You can give the callee the array's address, one number whatever the array's size, or you can photocopy the whole array first. The book always assumes the first: passing an array costs Θ(1), because a pointer to it is passed. Problem 4-2 asks what happens to running times when that assumption is wrong.

There are three strategies: pass by pointer, Θ(1); copy the whole array, Θ(N) for an N-element array even if the callee looks at only a few items; or copy only the subrange the callee might touch, Θ(n) for n elements. Each changes the recurrence. Binary search's T(n) = T(n/2) + Θ(1) becomes T(n/2) + Θ(N), which is Θ(N lg N) in all, or T(n/2) + Θ(n), which is Θ(N). Merge sort can absorb an extra Θ(n) per call, since merging already costs that much, but an extra Θ(N) per call turns Θ(N lg N) into Θ(N²).

Rust puts the choice into the types. A slice &[i32] is a borrowed (address, length) pair: 16 bytes, whatever the length. v.clone() deep-copies the whole Vec to a new heap buffer, and a[p..q].to_vec() copies just the subrange. Moving a Vec copies only its pointer, length and capacity, so the expensive copies happen exactly where the code asks for them.

Tap a lane to follow it in the memory strip and the Rust code: in copy all N every live call holds its own 16-item buffer, while by pointer every frame points into the one buffer v owns. Then switch to Merge sort and compare the copying with the 24 writes the sort itself makes.

Find one honest chip, and it can judge the rest

Professor Diogenes has n chips that should be identical, and a jig that tests two at a time: each chip reports whether the other is good or bad. A good chip always tells the truth. A bad chip can say anything, and the bad chips may even work together. If both chips call each other good, they are both good or both bad; any other answer means at least one of them is bad.

If at least half of the chips are bad, no strategy works. Let every bad chip call bad chips good and good chips bad: the test results are then exactly those of the mirror world where the two groups swap roles, so the professor cannot tell which world is real. With more than half good, pair the chips up: ⌊n/2⌋ tests, keep one chip from every pair that calls each other good, and drop the rest. Agreeing pairs are pure, both good or both bad, and among them the good pairs still outnumber the bad, so at most ⌈n/2⌉ candidates remain and more than half of them are good.

Repeat until one chip is left: it must be good. The tests add up to T(n) = T(⌈n/2⌉) + ⌊n/2⌋, which is Θ(n), at most n − 1 in fact. The survivor then tests every other chip, n − 1 more tests, and its answers are the truth. Every chip is identified in Θ(n) tests, a divide-and-conquer that throws half the problem away each round.

Add up the cost of each level, then the levels. 3T(n/4) + cn² shrinks geometrically to O(n²); the uneven T(n/3) + T(2n/3) + cn costs cn per full level, Θ(n lg n). → 4.4

The master theorem

Compare the driving function f(n) with the watershed nlogb a. Leaves win, a tie adds a lg n factor, or the root wins if regularity holds. Some recurrences fall in the gaps. → 4.5, 4.6

Akra-Bazzi for uneven splits

Find the p with Σ ai/bip = 1, then T(n) = Θ(np(1 + ∫ f(x)/xp+1 dx)). Floors and ceilings are safe when f(n) meets the polynomial-growth condition. → 4.7

Costs hide in the details

Copying arrays at every call changes the recurrences for binary search and merge sort. In chip testing, with more than half the chips good, ⌊n/2⌋ pairwise tests leave at most ⌈n/2⌉ candidates, and recursing on them finds a good chip. → 4-2, 4-6

Words to know

The book's words from this chapter, in plain language.

divide-and-conquer
Split a problem into smaller instances of itself, solve those recursively, and combine their answers.
base case / recursive case
The small inputs solved directly, and the bigger ones that recurse.
recurrence
An equation or inequality that defines a function using its own values on other, usually smaller, arguments.
algorithmic recurrence
One that is constant below some threshold n₀ and where every path of recursion ends in a base case.
threshold n₀
The size below which T(n) is a constant. Any large enough choice gives the same Θ answer.
dense / sparse matrix
Most entries nonzero, or most entries zero and stored compactly.
index calculation
Naming a submatrix by where it starts instead of copying it: Θ(1), and writes reach the original.
Strassen's algorithm
Matrix multiplication with seven half-size products instead of eight: Θ(nlg 7).
substitution method
Guess the form of the solution, then prove it by induction and find the constants.
lower-order term
A smaller term, like the d in cn − d, subtracted to make an induction go through.
recursion tree
A drawing of every call as a node labelled with its own cost, summed level by level.
master recurrence
T(n) = aT(n/b) + f(n): a subproblems of size n/b plus f(n) to divide and combine.
driving function
The f(n) in a master recurrence: the work outside the recursive calls.
watershed function
nlogb a, the leaves' total. The master theorem compares f(n) with it.
regularity condition
a·f(n/b) ≤ c·f(n) for some c < 1: case 3 needs it, so costs shrink below the root.
polynomially larger
Bigger by at least a factor nε for some ε > 0, which cases 1 and 3 require.
Akra-Bazzi recurrence
T(n) = f(n) + Σ aiT(n/bi): subproblems of different sizes.
polynomial-growth condition
f grows tamely enough that f(Θ(n)) = Θ(f(n)), roughly; then floors and ceilings don't matter.
parameter passing
Handing an array to a call: by pointer in Θ(1), or by copying it, which costs time per call.

Rust words from the code panels

For readers coming from another language. Each one shows up in a listing above.

HashMap + &mut
A memo table on the heap. Passing &mut memo lends it to every recursive call in turn, so they all fill the same table.
Option + ?
Some(value) or None. Inside a function that returns an Option, x? hands a None straight back to the caller.
row-major Vec
A matrix in one flat buffer, row after row: entry (i, j) at index i * n + j. A row is a slice; a column is every n-th item.
Copy types
Small values like i64, [[i64; 2]; 2] or a #[derive(Clone, Copy)] struct are copied when passed, so the caller can keep using them.
fixed-size array
[T; N] has its length in the type, lives inline (often on the stack) and needs no heap.
assert_eq!
Stops the program with both values printed if they differ: a test built into the run.
i64 vs u64
Signed and unsigned 64-bit integers. Subtracting below zero in a u64 panics in a debug build; checked_sub returns None instead.
enum + match
A type that is one of several variants, some carrying data, like Case::Two(k). match must handle every variant.
closures
Unnamed functions such as |x: f64| x * x. Ones that capture nothing coerce to a plain fn pointer; impl Fn or &dyn Fn accept any.
slice vs clone vs to_vec
&a[p..q] borrows part of a buffer in Θ(1); clone() and to_vec() copy items into a new heap buffer.
Drop
When an owner goes out of scope, its heap buffer is freed on the spot. No garbage collector.
